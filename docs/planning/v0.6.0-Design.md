## Goal

Ship v0.6.0 as **Einstein field equation closure + curvature classification + Shapiro investigation** (reframed per F-4: "GR theoretical closure" overclaims — geodesic deviation, Einstein-Hilbert action, junction conditions, and Lie derivative remain v0.7.0 work). Three interlocking themes:

1. **Close the Einstein field equation as a structurally-validated AST equation.** v0.5.0 shipped the LHS (`EinsteinTensorNode`, `MetricTensorNode`). The RHS (`T_μν`), the cosmological term (`Λ`), and the full equality predicate (`G_μν + Λg_μν = (8πG/c⁴) T_μν`) are still absent. BE-13, BE-17, BE-20 explicitly document this gap. After v0.6.0, that statement is false and those bridges become structurally encodable.
2. **Add the conserved-charge machinery (Killing vectors)** required for a principled diagnostic of the BE-37 Shapiro residual floor (PC-1.5 from v0.5.1 carry-forward). In Schwarzschild, `∂_t` and `∂_φ` are Killing vectors → `E = -p_t` and `L = p_φ` are exact conserved quantities. A symplectic integrator should preserve them to machine precision; deviation pinpoints integrator vs null-IC reconstruction.
3. **Complete the classical-GR curvature surface**: Weyl tensor (trace-free Riemann; vacuum classification object), Kretschmann scalar (full curvature invariant; horizon-piercing diagnostic), and the PD-6-triggered `CurvatureCompositeNode<K,S>` factory extraction (Weyl is the 5th curvature primitive; PD-6 fires).

Plus two breaking-change carry-forwards bundled because the user authorized "don't worry about breaking API":

- **BR-2**: `christoffelFn` returns `Float64Array(64)` (was nested `number[4][4][4]`). No backwards-compat shim. Gate at ≥30% GL4+RK4 speedup.
- **FD default flip**: `pderivNumericalFn` default `order: 2 → 4` (was opt-in via PD-7 in v0.5.1).

**Non-goals** (deferred to v0.7.0+):
- Higher-dimensional spacetime support (Weyl formula is `n=4`-hardcoded).
- Lie derivative `ℒ_X` AST primitive (Killing equation uses `∇_(μ ξ_ν)` form; pure `ℒ` is broader). **F-4 add**: the natural definition of Killing is `ℒ_ξ g = 0`; deferring Lie means Killing uses the symmetrized-covariant-derivative form.
- **F-4 add**: Geodesic deviation `D²V^μ/dτ² = R^μ_{νρσ} U^ν V^ρ U^σ` (physical Riemann-as-tidal-force). Natural sequel to PC-1.5 diagnostic.
- **F-4 add**: Einstein-Hilbert action `S = ∫(R + L_M) √−g d⁴x` (variational foundation; `ActionNode` v0.7.0).
- **F-4 add**: Junction conditions (Israel-Lanczos; stellar-interior–exterior matching).
- **E-6 add**: Generic `TensorEquationNode<LHS, RHS>` (v0.7.0 — `EinsteinFieldEquationNode` is bespoke for v0.6.0; BE-13 trace and BE-37 eikonal will benefit from a shared shape).
- Spinor structure / Dirac equation (quantum-side primitive).
- Stress-energy raised to upper-upper variance `T^μν` (locked to lower-lower in v0.6.0).
- Torsion `T^ρ_{μν}` as a first-class AST kind (BE-17 still uses tensor-product scalar reduction).
- Path-integral / functional measure (quantum-gravity side).

## Architectural Decisions (locked)

### Decision #1 — `KillingVectorNode` validates symbolically; verification is numerical

The Killing equation `∇_(μ ξ_ν) = 0` is operator-valued (a tensor identity that must hold pointwise on the manifold). The validator returns `freeIndices` and dimension; the *numerical* check `verifyKillingEquation(killingFn, metricFn, x)` lives in `src/numerical/killing.ts`.

**F-3 update**: Default tolerance is `1e-10` (not `1e-12` — the c²·g_tt ~ 6e16 scale on Schwarzschild causes FD-cancellation noise that v0.5.1 lessons documented as a footgun; `1e-12` is over-tight). The implementation uses a **hybrid approach**: exact symbolic Christoffels `Γ^λ_{μν}` from `schwarzschildChristoffelFn` for the `Γ^λ_{μν} ξ_λ` inner term (eliminating metric-derivative cancellation), and 4th-order FD only for the outer `∂_μ ξ_ν` partials. `1e-12` remains available as an explicit override for analytically-given Killing fields where the Christoffel path is exact. Pattern mirrors `bianchiResidual()` from v0.5.0 but with the symbolic-Γ tightening.

### Decision #2 — `StressEnergyTensorNode` locks to lower-lower variance

Canonical form is `T_μν` (lower-lower). Upper-upper `T^μν` requires metric-raising machinery that introduces no theoretical content. v0.7.0 may add the raised variant if a bridge needs it directly. Symmetry `T_μν = T_νμ` is enforced via a new `symmetry: 'symmetric' | undefined` field on the AST node (minimal symmetry-tag system; BE-17 antisymmetry stays deferred).

### Decision #3 — `EinsteinFieldEquationNode` is a first-class predicate, not an `op '='`

Rather than encoding `G + Λg = κT` as nested `op '+'` and an outer equality, we introduce `EinsteinFieldEquationNode` as a discriminated-union variant whose validator checks (a) free-index agreement (b) per-component dim equality (c) symmetry agreement on both sides. This is the natural shape for *every* rank-2 tensor equation in the catalog; v0.6.0 introduces it for Einstein and the pattern generalizes in v0.7.0.

### Decision #4 — `WeylTensorNode` hardcodes `n=4`

Spacetime dimension is `n=4` throughout UPT. The Weyl formula has explicit `1/(n-2)` and `1/((n-1)(n-2))` factors. Hardcode `n=4` with an explicit comment block; future-dimension parameterization is out of scope for v0.6.0 and would touch every curvature kind, not just Weyl.

### Decision #5 — `CurvatureCompositeNode<K,S>` factory extraction happens NOW

v0.5.1's PD-6 doc note pinned the extraction trigger as "first 5th curvature primitive." Weyl is that primitive. The migration applies to all six kinds: Riemann, Ricci, Einstein, BianchiResidual, Weyl, Kretschmann. Net LOC estimate **−180** (current parallel-validator duplication ~30 LOC × 4 + new factory ~60). Existing six-kind tests pass unchanged (refactor-only invariant).

### Decision #6 — BR-2 ships without backwards-compat shim

User directive: "don't worry about breaking API." No `christoffelFnFlatToNested(fn)` adapter. Migrate `tests/fixtures/schwarzschild.ts`, `computeChristoffelTensor`, and the RK4 + GL4 integrators in one coordinated commit. Bench gate ≥30% on `bench/gl4-mercury-1000step.bench.ts` is mandatory — failure reverts the BR-2 commits and ships v0.6.0 without it (negative-result documented).

> **Post-cycle note (2026-05-19):** Execution found that GL4 (`integrateGeodesicGL4`) and
> `computeChristoffelTensor` do NOT consume `christoffelFn` via the path the migration
> list assumed — BR-2 touched only the RK4 path. The GL4 and `computeChristoffelTensor`
> sites were not impacted. See commits `5c786cc` and `9576839` for the actual migration
> scope.

### Decision #7 — FD default flip 2→4 is unconditional

`pderivNumericalFn` default `order` flips from 2 to 4. v0.5.1's PD-7 introduced the opt-in path; the curvature-lowering helpers already migrated. Any v0.5.1 test that *needs* `{order: 2}` (numerical noise sensitivity) gets explicit annotation. No deprecation warning; the user-directive scope explicitly accepts breaking changes.

### Decision #8 — PC-1.5 is measure-and-document, not measure-and-fix

User-confirmed gate. Phase 1 delivers a written finding (`docs/architecture/pc-1.5-shapiro-residual-floor.md`) backed by three benches (step-count sweep, null-IC reconstruction variance, conserved-charge drift). No numeric residual commitment; the diagnostic surfaces the root cause and v0.7.0 may implement a fix.

### Decision #9 — Bridge-status promotions remain deliberate

After Phase 2/3 enable structural encoding of BE-13/17/19/20/39/50, the temptation is to promote `speculative → established` automatically. Decline. Status promotion is a per-bridge **physics-validation** decision separate from AST closure; document the gap in CHANGELOG ("bridge X is now structurally encodable; status pin unchanged pending physics validation") and let v0.7.0 audit revisit.

### Decision #10 (F-7 Q1) — `verifyKillingEquation` accepts optional `engine` parameter

`verifyKillingEquation(killingFn, metricFn, x, opts?: { engine?: TensorEngine; order?: 2|4; tolerance?: number })`. Optional `engine` mirrors `bianchiResidual()` pattern; defaults to `Float64ReferenceEngine`. Enables MathTSEngine wiring without breaking the default surface.

### Decision #11 (F-7 Q2) — `EinsteinFieldEquationNode.cosmological: CosmologicalConstantNode | null`

`null` semantically means "Λ-omitted" (explicit absence). A zero-valued `CosmologicalConstantNode` is reserved for explicit `Λ = 0` claims in the literature (rare). Validator branches on `null` vs node, not on numeric value.

### Decision #12 (F-7 Q3) — `StressEnergyTensorNode.symmetry: 'symmetric'` explicit field

Locked symmetry as an explicit AST field (not implicit at the node-kind level). This enables future Belinfante-Rosenfeld asymmetric T_μν⁺ without breaking the ABI; v0.6.0 only emits `'symmetric'`, but the field is checked by the validator and the equation predicate (Decision #3).

### Decision #13 (F-7 Q4) — `WeylTensorNode` does NOT carry a `dimension: 4` AST field

Hardcoded `n=4` in the numerical implementation (Decision #4) without an AST field. Adding `dimension: 4` would be cargo-culted (no consumer for non-4 in v0.6.0). Revisit if higher-dim spacetime arrives in v0.8.0+.

## Phase 1 — PC-1.5 + Killing-vector machinery

### Theoretical motivation

In a spacetime admitting a Killing vector `ξ^μ` satisfying the Killing equation
`∇_μ ξ_ν + ∇_ν ξ_μ = 0`, the contraction `Q = ξ^μ p_μ` is exactly conserved
along any geodesic (Carroll §3.8, eq. 3.174–3.175). Schwarzschild has two
manifest Killing vectors — `∂_t` (time-translation) → conserved energy `E = -p_t`,
and `∂_φ` (axial rotation) → conserved angular momentum `L = p_φ`. A symplectic
integrator (GL4) on a Hamiltonian with these symmetries preserves the conserved
charges to machine precision modulo the integrator's truncation floor. **Drift
in `E` therefore localizes the BE-37 Shapiro residual floor**:

- If `max|ΔE/E|` over the Earth-Mars geodesic ≥ 2.5e-4: integrator-driven (step
  count too coarse).
- If `max|ΔE/E|` < 1e-10 while the BE-37 relErr stays at 2.51e-4: null-IC
  reconstruction noise (the sqrt + sign-choice on `p^μ p_μ = 0` produces an
  initial condition off by ~1e-15 absolute that compounds across the affine
  parameter range, not the integrator).

This is a *theoretically-grounded* diagnostic — the v0.5.1 audit's PC-1
hypothesis (constants drift) had no such grounding, which is part of why it
was refuted.

### Sign convention (E-2 reconciliation)

In (−,+,+,+) signature with timelike Killing vector `ξ^μ_t = (1, 0, 0, 0)`,
the raw conserved charge `Q = ξ^μ p_μ = p_t` is **negative** for
forward-time motion of massive particles (Carroll Eq. 8.29–8.30). The
physical energy is `E ≡ −p_t = −Q`. UPT's convention:

- `evaluateConservedCharge(killing, momentum, x)` returns the raw `Q = ξ^μ p_μ`
  (signature-agnostic, no minus sign applied).
- For timelike Killing vectors in (−,+,+,+), JSDoc explicitly notes
  `physicalEnergy = -Q`.
- PC-1.5 diagnostic computes `|ΔQ / Q|` (magnitude-only), avoiding the
  sign-convention question entirely.

### Components

- **`src/dimensional/killing-validators.ts`** — `KillingVectorNode` (rank-1
  upper tensor + metric reference), `ConservedChargeNode` (inner contraction
  with rank-1 lower momentum), validators returning freeIndices + dim.
- **`src/numerical/killing.ts`** — `evaluateConservedCharge(killing, momentum, x)`,
  `verifyKillingEquation(killingFn, metricFn, x, { order = 4, tolerance = 1e-12 })`
  using 4th-order FD covariant derivatives.
- **`tests/fixtures/schwarzschild.ts`** — add `schwarzschildKillingT()` returning
  the rank-1 upper `[1, 0, 0, 0]` field; `schwarzschildKillingPhi()` returning
  `[0, 0, 0, 1]`. Pin both against `verifyKillingEquation` residual < 1e-12.
- **`bench/be37-step-count-sweep.bench.ts`** — BE-37 Earth-Mars at step counts
  `{256, 1024, 2048, 4096, 8192}`. Record relErr, max|ΔE/E|, max|ΔL/L|.
- **`bench/null-ic-reconstruction.bench.ts`** — reconstruct null IC 1000× with
  perturbed seed metric components; record variance in `p^μ` components.
- **`bench/geodesic-conservation.bench.ts`** — Mercury 100-orbit and BE-37
  Earth-Mars; record per-orbit max|ΔE/E| and max|ΔL/L|.
- **`docs/architecture/pc-1.5-shapiro-residual-floor.md`** — written finding
  with the three benches' outputs, a verdict (integrator vs null-IC), and a
  recommendation for v0.7.0+. Honest about uncertainty.

### Tests

- `tests/dimensional/killing-validators.test.ts` — node validation, dim, freeIndices.
- `tests/numerical/killing-schwarzschild.test.ts` — `verifyKillingEquation`

## Phase 2 — Einstein-equation closure + BR-2 + FD-flip

### Theoretical motivation

The Einstein field equation

```
G_μν + Λ g_μν = (8πG / c⁴) T_μν
```

is the defining equation of GR. v0.5.0 shipped the LHS structurally
(`EinsteinTensorNode`, `MetricTensorNode`). The RHS (`T_μν`), the
cosmological term (`Λ g_μν`), and the equation itself as a structural
predicate are absent. BE-17 (Einstein-Cartan) `src/bridges/equations/be-17-einstein-cartan.ts:13-20`
explicitly documents this gap. Phase 2 closes it.

### Components

- **`src/dimensional/einstein-equation.ts`** —

- **`src/numerical/einstein-equation.ts`** — numerical closure evaluator for
  `G_μν[g] + Λ g_μν - (8πG/c⁴) T_μν` at a point, returning residual tensor.

  `perfectFluidStressEnergy(massDensity, pressure, fourVelocity, metric)`

## Phase 3 — Weyl + Kretschmann + CurvatureCompositeNode<K,S>

### Theoretical motivation

**Weyl tensor `C^ρ_{σμν}`** is the trace-free part of Riemann:

```
C^ρ_{σμν} = R^ρ_{σμν}
          − (1/(n-2)) (δ^ρ_μ R_{σν} − δ^ρ_ν R_{σμ} − g_{σμ} R^ρ_ν + g_{σν} R^ρ_μ)
          + (1/((n-1)(n-2))) R (δ^ρ_μ g_{σν} − δ^ρ_ν g_{σμ})
```

(n=4 hardcoded per Decision #4.) Weyl encodes purely gravitational
degrees of freedom — the part of curvature that survives in vacuum.
Schwarzschild and Kerr have `R_μν = 0` but `C^ρ_{σμν} ≠ 0`; this is
why tidal forces exist outside a black hole. Without `WeylTensorNode`,
UPT cannot distinguish Ricci-curvature (matter-coupled) from
Weyl-curvature (vacuum/gravitational-wave) — a core GR classification
that no unification claim can omit.

**Kretschmann scalar `K = R_{ρσμν} R^{ρσμν}`** is the full quadratic
curvature invariant. For Schwarzschild,
`K(r) = 48 G² M² / (c⁴ r⁶)` — diverges at `r = 0` (true singularity),
finite at `r = r_s` (coordinate singularity). Canonical horizon-piercing
diagnostic.

**`CurvatureCompositeNode<K, S>` factory**: v0.5.0 shipped four parallel
curvature-composite AST kinds. v0.5.1's PD-6 pinned the extraction
trigger as "first 5th curvature primitive." Weyl is that primitive.

### Components

- **`src/dimensional/weyl-validators.ts`** — `WeylTensorNode` (one upper +
  three lower indices, componentDim `[L⁻²]`).
- **`src/numerical/weyl-lowering.ts`** — Weyl from Riemann + Ricci +
  Ricci-scalar using the n=4 formula. **F-5 lock — mixed-variance plan**:
  the formula uses `R^ρ_ν` (one-upper-one-lower Ricci) which UPT does NOT
  ship as a primitive. The lowering steps are:
  1. Compute Ricci once via existing `RicciTensorNode` lowering → `R_{σν}`.
  2. Compute Ricci scalar `R = g^{μν} R_{μν}` via existing
     `metric-inverse.ts`.
  3. Raise the first Ricci index where needed: `R^ρ_ν = g^{ρα} R_{αν}`
     (single inverse-metric contraction; reuse `metric-inverse.ts`).
  4. Assemble Weyl per the n=4 formula above.

  Add a non-diagonal-metric regression test (Kerr-Schild ingoing
  coordinates) to catch index-raising bugs that pass on diagonal
  Schwarzschild.
- **`src/dimensional/curvature-invariants.ts`** — `KretschmannScalarNode`
  (componentDim `[L⁻⁴]`).
- **`src/numerical/kretschmann.ts`** — `R_{ρσμν} R^{ρσμν}` numerical
  contraction.

## Breaking Changes (CHANGELOG-bound)

- **BR-2**: `christoffelFn` and `schwarzschildChristoffelFn` now return
  `Float64Array(64)` (was nested `number[4][4][4]`). Index encoding
  `(λ,μ,ν) → 16λ + 4μ + ν`. No shim. Migration: replace
  `christoffel[λ][μ][ν]` with `christoffel[16*λ + 4*μ + ν]` or use the
  new `getChristoffel(arr, lambda, mu, nu)` helper.
- **FD default**: `pderivNumericalFn` default `order` is now 4 (was 2).
  Sites that need 2nd-order get explicit `{order: 2}` annotation.
- **Internal**: 6 curvature kinds share `CurvatureCompositeNode<K, S>`.
  Transparent if accessed via existing names (Riemann/Ricci/Einstein/
  Bianchi/Weyl/Kretschmann); breaking if accessed by structural pattern
  matching on the AST discriminator (none in catalog).
