# G-9 Units-Normalization Layer — Design Note (v0.10 candidate)

> 2026-06-11. Closes the *design* obligation of improvement-plan G-9;
> the implementation is deliberately NOT attempted in the v0.9.0 cycle
> — see "Why not now". Run this note through the Adam+Eve pair before
> converting to an implementation plan.

## The bug class

SI-unit internals put c² ≈ 8.99×10¹⁶ on `g_tt`, so finite-difference
derivative chains suffer catastrophic cancellation. Documented strikes:
v0.5.1 Minkowski curvature tests (forced a unitless c=1 fixture),
the v0.5.1 Schwarzschild-fixture cycloid blowup (relErr 3.4e-6 →
3-file consumer escalation), and the v0.5.0 FD-order finding that
forced the 4th-order `pderiv` default (a ~2.4× per-sample cost paid
forever). Every mitigation so far is per-site.

## Proposal

A geometrized-units boundary layer:

1. **Internal convention:** G = c = 1 inside the GR numerical pipeline
   (`christoffelAt` → `dGammaAt` → `buildRiemann` → GL4), with mass as
   length (M → GM/c²) — the standard numerical-relativity choice.
2. **Boundary adapters:** `toGeometrized(quantity, dim)` /
   `fromGeometrized(...)` driven by the EXISTING `Dimension` exponent
   vectors — the conversion factor is mechanically `c^a·G^b` computed
   from (L, M, T) exponents; no per-quantity hand-tables. This is the
   dimension functor earning its keep again.
3. **Fixtures:** geometrized Schwarzschild/PG variants beside the SI
   ones (SI stays for the public API; geometrized is the internal fast
   path), sharing closed forms via the `makeSchwarzschildContext`
   pattern.
4. **Acceptance:** (a) Mercury Δφ and Shapiro Δt reproduce current
   relErr (1.8e-7 / ~2e-8) through the geometrized path; (b) the
   2nd-order `pderiv` default becomes viable again on geometrized
   metrics (truncation-vs-roundoff sweep documented) — if confirmed,
   that claws back the v0.6.0 4th-order cost; (c) R-1/R-1b/R-1c-style
   pins on the adapters' round-trips (property-based: `from∘to = id`
   to 1 ulp across the Dimension lattice).

## Why not now (honest scope statement)

The v0.9.0 sprint just migrated the metric-fn layout under the entire
GR pipeline (suite-verified, bench-gated 1.56×). Re-deriving the unit
convention of the same pipeline in the same cycle stacks two
foundation changes with overlapping blast radii — the v0.5.0/v0.5.1
lessons say exactly one at a time. The migration also changes which
G-9 design is right: flat Float64Array fixtures make the boundary
adapters cheaper than the pre-v0.9.0 estimate. Queue for v0.10 with
the fresh bench anchors as the baseline.
