# G-9 Units-Normalization Layer — Design Note (v0.10 candidate)

> 2026-06-11. Closes the *design* obligation of improvement-plan G-9;
> the implementation is deliberately NOT attempted in the v0.9.0 cycle
> — see "Why not now". Run this note through the Adam+Eve pair before
> converting to an implementation plan.

## The bug class

SI-unit internals put c² ≈ 8.99×10¹⁶ on `g_tt`, so finite-difference
derivative chains suffer catastrophic cancellation. Documented strikes:
v0.5.1 Minkowski curvature tests (forced a unitless c=1 fixture),
the v0.5.1 Schwarzschild-fixture cycloid blowup (relErr 3.4e-6 →
3-file consumer escalation), and the v0.5.0 FD-order finding that
forced the 4th-order `pderiv` default (a ~2.4× per-sample cost paid
forever). Every mitigation so far is per-site.

## Proposal

A geometrized-units boundary layer:

1. **Internal convention:** G = c = 1 inside the GR numerical pipeline
   (`christoffelAt` → `dGammaAt` → `buildRiemann` → GL4), with mass as
   length (M → GM/c²) — the standard numerical-relativity choice.
2. **Boundary adapters:** `toGeometrized(quantity, dim)` /
   `fromGeometrized(...)` driven by the EXISTING `Dimension` exponent
   vectors — the conversion factor is mechanically `c^a·G^b` computed
   from (L, M, T) exponents; no per-quantity hand-tables. This is the
   dimension functor earning its keep again.
3. **Fixtures:** geometrized Schwarzschild/PG variants beside the SI
   ones (SI stays for the public API; geometrized is the internal fast
   path), sharing closed forms via the `makeSchwarzschildContext`
   pattern.
4. **Acceptance:** (a) Mercury Δφ and Shapiro Δt reproduce current
   relErr (1.8e-7 / ~2e-8) through the geometrized path; (b) the
   2nd-order `pderiv` default becomes viable again on geometrized
   metrics (truncation-vs-roundoff sweep documented) — if confirmed,
   that claws back the v0.6.0 4th-order cost; (c) R-1/R-1b/R-1c-style
   pins on the adapters' round-trips (property-based: `from∘to = id`
   to 1 ulp across the Dimension lattice).

## Why not now (honest scope statement)

The v0.9.0 sprint just migrated the metric-fn layout under the entire
GR pipeline (suite-verified, bench-gated 1.56×). Re-deriving the unit
convention of the same pipeline in the same cycle stacks two
foundation changes with overlapping blast radii — the v0.5.0/v0.5.1
lessons say exactly one at a time. The migration also changes which
G-9 design is right: flat Float64Array fixtures make the boundary
adapters cheaper than the pre-v0.9.0 estimate. Queue for v0.10 with
the fresh bench anchors as the baseline.

## r2 revisions (post-Adam vet, 2026-06-11 — authoritative over the body above)

Adam verdict: **YELLOW** (full findings in the vet transcript, condensed
here). The direction stands; six revisions before a v0.12 plan consumes
this note:

1. **[HIGH] Tensor-component bookkeeping + coordinate convention.** The
   scalar `toGeometrized(quantity, dim)` does not cover g_μν or (x, p)
   state: components carry HETEROGENEOUS dimensions in SI coordinates
   (g_tt ~ L²T⁻², g_rr dimensionless, g_θθ ~ L²). The plan must derive
   per-component dimensions mechanically from (coordinate-dim vector ×
   tensor valence) and pin the coordinate convention (decision: x⁰ = ct,
   making all g components dimensionless and the conversion uniform —
   the standard NR choice).
2. **Corrected conversion formula (Adam's derivation):** for SI
   dimension L^l M^m T^t, **Q_geom = Q_SI · G^m · c^(t−2m)** (residual
   pure-length dimension l+m+t); inverse with negated exponents. Only
   the M and T exponents enter. **Domain guard:** reject nonzero
   I/Θ/N/J exponents with a typed error (k_B/ε₀ extensions out of
   scope).
3. **Acceptance (b) REFRAMED as a measured gate, not a criterion:**
   per-component relative FD error is UNIT-INVARIANT (ε|f|/(h|f′|) —
   c² cancels); the real wins are absolute zero-gates and mixed-scale
   sums. Run the truncation-vs-roundoff sweep near-field (r ~ few·r_s),
   document the outcome, keep the order-4 default as the standing
   fallback. Precedent: the PC-1 constants hypothesis was numerically
   refuted once already (todo lesson: RED-test-verify every numeric
   prediction).
4. **Strike reclassification:** strike 2 (cycloid) was inline-constant
   DRIFT (units-consistency class), not c²-cancellation; strike 3's
   order-4 default flip was v0.6.0, not v0.5.0.
5. **Rollout order:** O-4 layout unification first or bundled (DONE
   2026-06-11 — kretschmann/weyl widened, sibling fixtures unified, so
   the 2-units × 2-layouts matrix risk is retired); SUBSUME the
   existing ad-hoc `unitless*` (c=1) fixture family into the
   geometrized convention — the codebase must not end with three unit
   conventions; full consumer conversion list (kretschmann/weyl,
   killing, bianchi, BE-37 eikonal, BE-51/52, perihelion finder) with
   the boundary at geometrized-native fixtures + public-API adapters.
6. **Test/bench gates:** round-trips alone are insufficient
   (consistently-wrong factors cancel) — add absolute factor pins
   (M_sun → GM/c² ≈ 1476.6 m; 1 s → 2.998×10⁸ m) and one SI-vs-
   geometrized pipeline equivalence test; bench gate = no regression vs
   the v0.9.0 anchors (PO-1 3,248 hz) with the conditional order-2
   claw-back quantified only if the sweep confirms. Share ONE computed
   factor between to/from for the 1-ulp property. Implementation target
   is v0.12 (this note's "v0.10" framing predates the rollups).
