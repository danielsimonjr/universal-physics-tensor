## Requirements

R1. Same-physical-quantity sharing must stay expressible (ST-2's
    deliberate aliasing is a feature).
R2. Different-physical-quantity collisions must be impossible by
    default (the be-42>>be-12 failure mode).
R3. Junction matching (name or `QUANTITY_IDENTIFICATIONS`) must keep
    working unchanged for the 15 existing edges + 4 registered CT-*
    compositions + ST-1/ST-2 pins (zero behavioral regression).
R4. The reviewable-judgment property is non-negotiable: whatever
    resolves a collision must be recordable data, not code-only.

## Options

**A — per-edge qualified names** (`be-42/mass`, `be-12/mass`): every
source quantity is namespaced by its edge id; composition rewrites
junction names. Kills R2 completely but ALSO kills R1's free sharing —
every shared input then needs an explicit identification, exploding
`QUANTITY_IDENTIFICATIONS` for the trivial cases (mass-is-mass in
ST-2-style chains) and breaking R3 (every existing composition's input
keys change).

**B — global role registry**: a curated registry of canonical roles
(`gravitating-mass`, `particle-mass`, `temperature`, …) and every edge
declares against it. Solves R2 with maximal review value (the registry
IS the physics ontology) but the registry is a new global coordination
artifact, and 44 edges × per-edge role audits is exactly the human
bottleneck the migration already has — it doubles the judgment surface.

**C (r1) — collision-explicit with same-object carve-out**: REJECTED by
the Adam vet (A-1): be-42>>be-12 and ST-2 are object-identical, so the
carve-out either misses the motivating failure or breaks ST-2.

**D (r2, RECOMMENDED) — pure name-collision rule + dispositions**:
quantity names stay canonical (R1, R3 mostly intact); `composeEdges`
throws a typed `CompositionAliasError` whenever the composed sources
would contain a DUPLICATE NAME across operands — no object-identity
clause — unless a disposition is supplied:
`{ aliases: [{ name, treatAs: 'shared' | { renameSecond: string }, rationale, citation? }] }`,
with a registered `SOURCE_ALIAS_DISPOSITIONS` table (keyed by composed
id, mirroring `QUANTITY_IDENTIFICATIONS`) so judgments live in
reviewable registry data, not only call sites. `'shared'` = one input
feeds both slots (ST-2); `renameSecond` = split the collision
(be-42>>be-12). The enumerator marks colliding pairs
`requiresDisposition` instead of silently composing.

**Implementation requirements pinned by the vet (A-4):**
- `renameSecond` MUST remap the evaluator input: the composed evaluate
  and domain predicate shadow the colliding key
  (`{ ...inputs, [name]: inputs[renamed], [junction.name]: intermediate }`)
  — without the remap the rename is a no-op and the first operand's
  value still reaches the second evaluator.
- Reject a `renameSecond` target colliding with any existing source
  name of either operand.
- `'shared'` does NOT dedupe the sources array (ST-2 pins
  `['mass','mass']`); intra-operand duplicates inherited from a
  recorded `'shared'` disposition are exempt from re-checking in
  deeper chains (they denote one input key).

**Prerequisite hygiene (A-2/A-6.3):** centralize Quantity node objects
in one module (one object per canonical name, pinned by a uniqueness
test) BEFORE the 29-edge migration — the tranche already drifted
(catalog-tranche's be48 defines its own 'mass' node while its
docstring falsely claims reuse of calibration's; fix that docstring in
the same change). Centralization removes the false-positive class but
does NOT replace dispositions: node-level facts cannot decide
composition-level questions (A-1).

## Recommendation

**Option D** (r2). Small delta (name-collision check + `aliases` option
+ one error class + disposition registry + enumerator flag), converts
the aliasing hazard into the framework's reviewable-judgment currency,
and its recorded dispositions are the seed data for Option B's role
registry if ever wanted. Known churn is EXPLICIT, not zero (per Adam
A-3): exactly two call sites change — ST-2 gains a recorded
`treatAs: 'shared'` disposition, and the Phase-D aliasing pin test
(`tests/composition/enumerate-uncertainty.test.ts:61-79`, which
self-describes as v0.11-replaceable) is rewritten to assert
`requiresDisposition`. CT-1/CT-1b/CT-3, all synthetic compose tests,
and the associativity property chain are verified unaffected
(disjoint names); CT-2/CT-4 are consistency quotients, out of scope.

## Acceptance criteria for the v0.11 plan (r2, per Adam)

1. `composeEdges(be42Edge, be12Edge)` THROWS `CompositionAliasError`
   (today it silently aliases) — the Phase-D finding becomes a guard.
2. CT-1/CT-1b/CT-3 pass UNCHANGED; **ST-2 changes by exactly one
   recorded `treatAs: 'shared'` disposition** (keeping its
   `['mass','mass']` sources pin); the Phase-D aliasing pin test is
   rewritten to assert `requiresDisposition`.
3. A `renameSecond: 'particle-mass'` disposition makes be-42>>be-12
   evaluable with separate inputs, pinned against the Adam-computed
   values: **T_H(M_sun) = 6.1684×10⁻⁸ K; λ_T(m_e, T_H) =
   3.0012×10⁻⁴ m** (relErr ≤ 1e-12; contrast the current aliased
   2.031×10⁻³⁴ m). Prerequisite: add `M_E_SI = 9.1093837015e-31` to
   `src/core/constants.ts` (no electron-mass constant exists).
4. Enumerator partitions gain `requiresDisposition`; the novel-
   candidates report renders the ⚠ rows from it.
5. Property test: composing any two synthetic edges with disjoint
   source names never throws `CompositionAliasError` (exact under the
   name-based rule).
6. Quantity-node centralization landed first, with a name-uniqueness
   pin and the be48 false-reuse docstring corrected.
