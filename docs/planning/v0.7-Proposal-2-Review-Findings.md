### Adam-V2 — Rule 3 uses non-existent `BridgeCell` fields `from`/`to`
**Claim:** Causality rule reads `cell.from.scale` / `cell.to.scale` (design lines 428–435).
**Verdict:** ❌ UNSUPPORTED. `BridgeCell` at `src/core/cell.ts:107–114` exposes `source: TensorIndices` and `target: TensorIndices`, not `from`/`to`. `TensorIndices.scale` is `PhysicalScale | undefined`, so the `=== undefined` early-return fires on every entry whose source/target lacks an explicit scale.
**Action:** Plan must rename throughout and re-derive warning criteria when `source.scale === undefined`.

### Adam-V3 — Rule 1 reads non-existent `cell.dimensional_signature`

## Net assessment

The design carries **two compile-blocking defects** the Implementation Plan must resolve before TDD: Rule 3 uses `cell.from`/`cell.to` where `BridgeCell` exposes `source`/`target` (Adam-V2), and Rule 1 reads `cell.dimensional_signature`, a field no `Cell` variant defines (Adam-V3). Both stem from the design not re-verifying against `src/core/cell.ts` after P3 shipped — the proposals-doc sketch used names P3 didn't adopt.

Beyond those, the architecture is sound: `BRIDGE_EQUATIONS` is read-only (V4), `FluxReport` is TDD-pinnable (V6), `TupleKey` is correct (V7). Catalog state slightly off — 26 not 30 unknown-bridge entries (V5); qualitative claim survives. Phase 0 is near-vacuous post-P3 (V8). Public-surface delta is ~12 symbols, not 7 (V9); timeline is tight (V10).

Recommendation: **fix V2 and V3 in the design** before opening the plan. Eve should focus on the `encodingDebt` sentinel (Risk §3) and multi-scale `LawEntry` semantics (Risk §2).
