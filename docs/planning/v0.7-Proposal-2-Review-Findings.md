## Net assessment

The design carries **two compile-blocking defects** the Implementation Plan must resolve before TDD: Rule 3 uses `cell.from`/`cell.to` where `BridgeCell` exposes `source`/`target` (Adam-V2), and Rule 1 reads `cell.dimensional_signature`, a field no `Cell` variant defines (Adam-V3). Both stem from the design not re-verifying against `src/core/cell.ts` after P3 shipped — the proposals-doc sketch used names P3 didn't adopt.

Beyond those, the architecture is sound: `BRIDGE_EQUATIONS` is read-only (V4), `FluxReport` is TDD-pinnable (V6), `TupleKey` is correct (V7). Catalog state slightly off — 26 not 30 unknown-bridge entries (V5); qualitative claim survives. Phase 0 is near-vacuous post-P3 (V8). Public-surface delta is ~12 symbols, not 7 (V9); timeline is tight (V10).

Recommendation: **fix V2 and V3 in the design** before opening the plan. Eve should focus on the `encodingDebt` sentinel (Risk §3) and multi-scale `LawEntry` semantics (Risk §2).

## Eve findings

Adam flagged two compile-blocking field-name defects (V2, V3) and the
unknown-bridge miscount (V5). Eve covers risks Adam missed:
storage-layer drift, encoding-debt contamination, key versioning,
extract-mapping semantics, registry exhaustiveness. Grep-verified
against HEAD; unverifiable items tagged "speculative".

### Eve-R1 — "1 null `dimensional_signature`" is empirically WRONG

Decision #3 cites BE-15 as the null entry.
`grep -nE "^\s+dimensional_signature: null" src/bridges/index.ts` →
**0** matches. BE-15 has `dimensional_signature: \`[area]\``
(`src/bridges/index.ts:331`). The only "null" hits are inside BE-36's
`notes` prose. **Adam-V5 ratified "1-null ✅" without disambiguating
field-vs-string** — the v0.5.1 trap fired in verification itself.

**Severity:** HIGH. **Fix:** Re-tally. If zero nulls, Rule 1's
warning-tier rationale collapses; rule could be error-tier in v0.7.

### Eve-R2 — TWO `Map`s of truth after Phase 2

Phase 2 sketch (line 471) writes `this.cells.set(canonicalize(tuple),
cell)` — a NEW Map. `tensorData` (`tensor.ts:130`) is not removed;
shims still write via `serializeIndices`. Decision #7 calls
`canonicalize` a "rename-and-extract", but it uses ALPHABETICAL order
(`dim|force|info|scale|sym|topo`) while `serializeIndices` uses
INSERTION order (`scale|force|sym|info|dim|topo`, `tensor.ts:488-499`).
Identical coordinates → different keys. `getCellContents` / `getStats`
see the old map; `populatedCells` the new. Adam-V7 noted in passing;
deserves SHOWSTOPPER weight.

**Severity:** SHOWSTOPPER. **Fix:** Pick one Map. Either delegate shims
through `add()`, or have `add()` write `tensorData` via existing
`serializeIndices` (drop the sort).

### Eve-R3 — `encodingDebt` flag contaminates `BridgeCell` public surface

Task 4.1 (lines 567-574) proposes optional `encodingDebt: true` on
`BridgeCell` to suppress rule violations on 26 sentinel entries. P3
Eve-R1 warned against catalog vocabulary leaking into `Cell`; v0.6.1
dropped 24 exports for surface discipline. A public bypass for
transitional catalog state is the same contamination P3 was disciplined
against.

**Severity:** HIGH. **Fix:** Private `isSentinelCoordinate(tuple)`
predicate inside the FluxRule layer. `BridgeCell` stays clean.

### Eve-R4 — `extractTuple` collapses off-diagonal storage to diagonal

Risk §1 admits `extractTuple` unspecified; "use `from`" (actually
`source` per Adam-V2). `bridgeCellKey(source, target)` at
`tensor.ts:289-291` addresses bridges by PAIR `key1 -> key2`. The new
`Map<TupleKey, Cell>` keys by a single tuple — a quantum→classical
bridge keyed at *quantum* collides with quantum laws.

**Severity:** HIGH. **Fix:** Keep pair-key shape, or populate BOTH
tuples (and de-dupe `populatedCount`). Spec with a round-trip test.

### Eve-R5 — `TupleKey` brand offers no schema-version protection

`TupleKey = string & { __brand: 'TupleKey' }` is TypeScript-only. No
version prefix. When v0.8 adds a 7th axis (e.g. `time`), `canonicalize`
produces strings that collide with v0.7 keys.

**Severity:** MEDIUM. **Fix:** Prefix keys with `v1|...`. Add a test
for the "axis added" scenario.

### Eve-R6 — `IndexTuple` overlaps `TensorIndices`; dual coordinate drift

`IndexTuple` is required over 6 axes; `TensorIndices`
(`src/core/types.ts:76-83`) is partial over the same 6. No adapter.
`canonicalize` reads `tuple.dimension` unconditionally — a
`TensorIndices` with `dimension: undefined` produces a literal
`dim:undefined` key fragment.

**Severity:** MEDIUM. **Fix:** Add `tensorIndicesToTuple()` with
defaults; document the v0.8 unification path.

### Eve-R7 — `unpopulatedNeighborhoods()` integer-axis spec self-contradicts

Decision #4 says `dimension`/`topology` are wildcards; Task 3.3 says
"± 1 within config-declared range". `TensorConfig` has no such range
field (`src/core/types.ts:53-71`).

**Severity:** MEDIUM. **Fix:** Pick one rule. If ± 1, add the field.

### Eve-R8 — `pendingDiagnostics` resurrected after Risk §5 deleted it

Risk §5 deletes the accumulator. Phase 2 sketch line 470 still pushes
to it. v0.5.0 lesson — never assume a plan inherits its design's fixes.

**Severity:** MEDIUM. **Fix:** Delete from the Phase 2 sketch.

### Eve-R9 — Flux-rule dispatch lacks exhaustiveness guard

Severity compared with `===`; a misspelled `'warn'` silently skips the
throw. v0.5.0 ricci-slot lesson: registry patterns hide miscomputes.

**Severity:** MEDIUM. **Fix:** Literal-union severity with
`_exhaustive: never` switch (mirror `tensor.ts:377-383`).

### Eve-R10 — Phase 0 does not guard a P3 revert

Task 0.1 only checks `Cell` importable. P3 revert between Phase 0 and
Phase 4 caught only via suite-count delta.

**Severity:** LOW (speculative). **Fix:** Pin P3 commit SHA; assert
HEAD descends.

### Eve-R11 — Public-surface growth reverses ~80% of v0.6.1 minimize

Adam-V9 enumerated ~12 new symbols. P3 added 7. v0.7 net ~+19 vs.
v0.6.1's -24. No `@internal` vs. `@public` discipline in the design.

**Severity:** MEDIUM. **Fix:** Default `FluxRule`, `FluxRuleResult`,
`FluxDiagnostic`, `FluxReport`, `FluxViolationError`, `extractTuple` to
`@internal`.

### Eve-R12 — Rule 3 suggests a nonexistent field

Message: "add `timeReversalAnnotation: true` to the BridgeEntry."
`BridgeCell` has no such field (`cell.ts:107-114`).

**Severity:** LOW. **Fix:** Add field or rewrite message.

### Eve-R13 — Multi-scale `LawEntry` collision unresolved (Risk §2)

LBE rule conflicts with multi-scale laws (`LawCell.scales` plural,
`cell.ts:90`). Decision punted to Phase 2 TDD.

**Severity:** MEDIUM. **Fix:** Decide now (fan-out vs. loose
diagonality).

### Eve-R14 — `catalog-adapter` partial-failure leaves tensor mid-state

Adapter calls `add()` 42×. Throw on entry 7 → 1-6 persisted, partial
catalog never flagged. Real failure mode for startup bootstrap.

**Severity:** LOW. **Fix:** Two-pass collect-then-commit, or
