## Goal

Reduce the surface area of the codebase along five orthogonal axes while
preserving every public-API contract and every behavioral guarantee. The
sprint succeeds if:

1. The set of "unused exports" reported by `npm run docs:deps` drops
   meaningfully from the Phase-0-captured baseline (was 79 in
   2026-05-21 snapshot; will be re-measured at sprint start). Each
   remaining item is either explicitly `@public`-tagged (downstream
   API surface), `@internal`-tagged (test-only importer — kept
   `export`ed by TS-ESM necessity but not part of the public contract),
   or accompanied by a one-line skip rationale in `unused-analysis.md`.
2. The set of "unused files" drops from 44 to ≤3 by (a) adding
   `--include-tests` to the `docs:deps` npm script (eliminates the 40
   bridge-equation false-positives, which are imported only by
   per-bridge encoding tests), and (b) parsing `package.json` `exports`
   in the dep-graph generator (eliminates the `mathts-engine` subpath
   false-positive). Remaining ≤3 deliberately-retained reference
   modules get a one-line skip rationale.
3. `src/numerical/lowering.ts` and `src/dimensional/validator.ts` each
   drop below 900 LOC via factor-outs that pass Adam+Eve adversarial
   review.
4. Three bench harnesses (`bench/gl4-picard-alloc.bench.ts`,
   `bench/ricci-lowering.bench.ts`, `bench/pderiv-grid.bench.ts`) land
   with baseline numbers in `docs/architecture/benchmarks.md`.
5. `CLAUDE.md` no longer claims `.ruff_cache` exists; every "Current
   Version: v0.X.Y" or "as of v0.X.Y" reference is honest.
6. Suite stays ≥ the Phase-0 baseline (re-measured at sprint start —
   v0.6.0 shipped at 1693, but the post-v0.6.0 BE-33 fix and doc-refresh
   commits may have shifted the number). Any net-new tests are net-add,
   not net-replace.

## Architectural Decisions (locked)

### Decision #1 — Balanced export-policy (per the maintainer's scoping choice; reworked post-Adam+Eve)

**Reworked from the initial design after Adam+Eve adversarial review
caught S1**: the original recon's bucket (a) included symbols used
only by tests, but TypeScript ESM does not honor test-imports as
internal — dropping `export` on a test-imported symbol breaks the
build. Reclassified into FOUR buckets:

- **(a) FULLY UNUSED** — no importers in `src/`, `tests/`, `bench/`,
  `examples/`, or `tools/`. Action: **delete the `export` keyword AND
  the symbol itself** if there are zero references.
- **(a') TEST-ONLY EXPORT** — imported only by `tests/` (and optionally
  `bench/`), zero `src/` consumers, not re-exported by `src/index.ts`.
  Action: **keep `export` (TS-ESM requires it), add `@internal` JSDoc
  tag** with a one-line rationale ("kept exported for test consumption
  only — not part of the public API contract").
- **(b) PUBLIC-API SURFACE** — re-exported by `src/index.ts`, OR
  returned as a public function's result type, OR a parameter-options
  shape for a `@public` function. Action: **keep, add `@public` JSDoc
  tag**.
- **(c) UNCERTAIN** — needs maintainer judgment. Action: **flag in the
  per-symbol classification table, default to (b) treatment**
  (conservative).

**Per-symbol classification deferred to Phase 0**: the original recon
mis-classified at least 5 symbols (`EXPECTED_DIMENSION_BY_BRIDGE`,
`GL4_C`, `GL4_A`, `GL4_B`, `riemannLowerAt`,
`covariantDerivRiemannLowerAt`) because the bucket-(a) criterion was
wrong. Phase 0 produces the corrected table with a verifier-gated
`grep -rn` per row: any symbol with a test importer auto-routes to
(a') unless it's also `src/index.ts`-re-exported (then (b)).

**Expected counts** (recalibrated, to be confirmed in Phase 0):
- (a) Fully unused: ~5-10 symbols (the curvature-lowering-helpers
  internal types `FlatMatrix`/`DGammaTensor`/`GammaTensor`, `ODESystem`,
  `EinsumFreeAxis`, `WeylInputs`, `buildEinsumSpec`, likely a handful
  of `*ValidationResult` interfaces with no test importer).
- (a') Test-only export: ~10-15 symbols (the test-imported items above
  plus the test-consumed `kronecker`/`raise`/`lower`/`scale`/`tsum`
  helpers if they have no `src/` consumer, etc.).
- (b) Public-API surface: ~43+ symbols (re-exported by `src/index.ts`).
- (c) Uncertain: ~2-5 symbols.

### Decision #2 — Large-file factor-outs are LOC-neutral on the public surface

Extractions are PURE refactors: they move LOC across files but do NOT
add or remove public exports. Every extracted function is `export`-less
(internal-only) unless an existing public consumer requires it. This
keeps Track-B fully orthogonal to Track-A.

Two specific factor-outs proceed (Track-B recon Proposal 1 + 2):

- **Proposal 1** — Extract the 10-arm curvature/GR-object dispatch out
  of `validator.ts`'s `infer()` switch into a registry pattern, mirroring
  the existing `CURVATURE_KIND_REGISTRY` in `curvature-composite.ts`.
  New module: `src/dimensional/validator-registry.ts` (~60–80 LOC).
- **Proposal 2** — Extract the `weyl-tensor` and `bianchi-residual` FD
  pipelines out of `lowering.ts`'s `lowerCurvature` dispatcher into the
  existing `src/numerical/curvature-lowering-helpers.ts` module.

**Proposal 3 (extracting covariant + tensor-partial-derivative arms) is
DEFERRED** — Track-B recon flagged it as medium-risk due to the
recursive `lowerNode` call inside `covariant-derivative`. Not blocked,
just not a v0.6.1 ROI. Carry to v0.7.0 if needed.

### Decision #3 — Dep-graph generator: configuration fix + parser knowledge (reworked post-Adam+Eve)

**Reworked from the initial design after Adam+Eve caught S3**: the
original premise ("the generator is missing the `BRIDGE_EQUATIONS`
array imports") is wrong. The 40 `be-NN-*.ts` modules are NOT imported
by `src/bridges/index.ts` at all (only 2 of the 40 module paths appear
anywhere in the file, and only as prose inside `notes:` string-literal
fields). The 40 modules ARE imported by their per-bridge encoding tests
(e.g. `tests/bridges/be-25-iit-encoding.test.ts:37`), and the generator
HAS an `--include-tests` mode (line 128) — but `package.json`
`scripts.docs:deps` invokes it without the flag.

Three changes, in order of impact:

- **Update `docs:deps` npm script to pass `--include-tests`** —
  one-line change in `package.json`. Eliminates ALL 40 BE-equation
  false-positives in a single keystroke. This is the v0.6.1 fix.
- **Parse `package.json` `exports`** in
  `tools/create-dependency-graph/create-dependency-graph.ts` — for
  every key in the `exports` field, resolve to a file path and mark
  it as implicitly reachable. Eliminates the `mathts-engine.ts`
  false-positive (and any future subpath additions). ~20-40 LOC change.
- **NO `.depgraphignore` file** — explicitly rejected. A regex whitelist
  is a hack; the goal is for the generator to be *correct*, not for it
  to ignore inconvenient findings. (This is the same principle that
  killed the C-9 "skip the bug" approach in the v0.6.0 doc-integrity
  review.)
- **`await import()` dynamic-imports are explicitly OUT OF SCOPE** —
  `src/numerical/mathts-engine.ts:145,186` uses `await import(...)`
  with literal string arguments. v0.6.1 does NOT teach the generator
  to follow these. If any file becomes a new false-positive due to a
  dynamic-import edge, document by name with rationale; no generator
  change.

If after both fixes any false-positives remain, document them by name
in the `unused-analysis.md` header with a one-line rationale.

### Decision #4 — `@public` JSDoc tag is the canonical surface marker

Per the v0.5.1 audit and the v0.6.0 doc-integrity review, the
public-API contract is currently implicit (re-exported from
`src/index.ts` ↔ public). Decision: every symbol re-exported by
`src/index.ts` gets a `@public` JSDoc tag at its declaration site.
This makes the contract explicit at the source of truth and lets the
dep-graph generator (or any future tool) classify exports without
parsing the manifest.

NOT in scope: a typescript-level `internal`/`public` separation via
distinct entry points. That's a v0.7.0+ concern.

### Decision #5 — Bench harnesses use the v0.5.0+ vitest-bench template

The three new bench files follow the existing convention (per
`bench/README.md` + `docs/architecture/benchmarks.md`): tinybench-backed,
inputs pre-built outside the bench callback (F4 pattern), sync benches
preferred, baseline numbers recorded in markdown after the run.

NO threshold gates. v0.6.0 set the precedent that bench gates are
informational only; v0.6.1 maintains this. A regression of >5%
wall-time on any of the three benches is a discussion item, not a
build failure.

### Decision #6 — CLAUDE.md staleness gets a single-pass refresh

## Phase 2 — Large-file factor-outs

### Motivation

`lowering.ts` (1015 LOC) and `validator.ts` (816 LOC) are the two
largest src files outside the `bridges/index.ts` catalog (1774 LOC,
which is expected and not in scope). Track-B recon identified two
high-confidence extractions.

### Proposal 1 — `validator-registry.ts` (reworked post-Adam+Eve)

**Reworked from the initial design after Adam+Eve caught S2 (Eve-R2 +
Adam-V6)**: the original claim "10 arms all follow the identical
pattern" is wrong. **11 arms across 3 patterns**, verified at
`src/dimensional/validator.ts:592-740`:

- **Pattern A — no callback, propagate freeIndices (5 arms):**
  `riemann-tensor`, `killing-vector`, `stress-energy`,
  `einstein-equation`, `weyl-tensor`. Each calls `validateX(node)`
  with no additional argument; the result's freeIndices map is
  merged into `ctx.freeIndices`.

- **Pattern B — riemann-closure callback, propagate freeIndices (3 arms):**
  `ricci-tensor`, `einstein-tensor`, `bianchi-residual`. Each calls
  `validateX(node, (riemannChild) => { const rr =
  validateRiemannTensor(riemannChild); return { dim: rr.dim,
  freeIndices: rr.freeIndices }; })`. The closure threads the inner
  Riemann's signature-check + freeIndices outward. This pattern
  exactly mirrors the v0.5.0 ricci-slot trap: a registry that ignores
  the per-arm callback shape will silently miscompute.

- **Pattern C — no callback, skip freeIndices (3 arms):**
  `conserved-charge`, `cosmological-constant`, `kretschmann-scalar`.
  Each calls `validateX(node)`; the result has empty freeIndices by
  construction (the kind is scalar), so no merge loop is needed.

**Extraction:** create `src/dimensional/validator-registry.ts` with a
discriminated-union entry type that encodes pattern A/B/C explicitly,
NOT a `propagateFreeIndices: boolean` flag:

```ts
type ValidatorEntry<K extends NodeKind> =
  | { pattern: 'A'; validator: (node: NodeOfKind<K>) => ValidatorResult }
  | { pattern: 'B'; validator: (node: NodeOfKind<K>, riemannCb: RiemannChildCallback) => ValidatorResult }
  | { pattern: 'C'; validator: (node: NodeOfKind<K>) => ValidatorResult };

const VALIDATOR_REGISTRY: { [K in CurvatureOrGRKind]: ValidatorEntry<K> } = {
  'riemann-tensor':         { pattern: 'A', validator: validateRiemannTensor },
  'killing-vector':         { pattern: 'A', validator: validateKillingVector },
  'stress-energy':          { pattern: 'A', validator: validateStressEnergyTensor },
  'einstein-equation':      { pattern: 'A', validator: validateEinsteinFieldEquation },
  'weyl-tensor':            { pattern: 'A', validator: validateWeylTensor },
  'ricci-tensor':           { pattern: 'B', validator: validateRicciTensor },
  'einstein-tensor':        { pattern: 'B', validator: validateEinsteinTensor },
  'bianchi-residual':       { pattern: 'B', validator: validateBianchiResidual },
  'conserved-charge':       { pattern: 'C', validator: validateConservedCharge },
  'cosmological-constant':  { pattern: 'C', validator: validateCosmologicalConstant },
  'kretschmann-scalar':     { pattern: 'C', validator: validateKretschmannScalar },
};
```

Then the `infer()` switch becomes 11 fall-through arms dispatching to
a `lookupAndApply(node, ctx)` helper that branches on the registry
entry's `pattern` tag.

**Why this matters:** the discriminated union makes the three patterns
exhaustively typecheck. Adding a new GR-object node kind that
deviates from A/B/C requires either (a) extending the union, or (b)
explicit type errors at the registry definition site. The flag-based
approach would let a new arm slip in with the wrong `propagateFreeIndices`
value and only fail at TDD-RED, which is the v0.5.0 ricci-slot bug
re-played.

### Adversarial-review note for the plan

Per the v0.5.0 lesson ("never assume the plan inherits the design's
fixes"), the upcoming Implementation Plan MUST spec the registry's
discriminated-union type EXPLICITLY in the Task description — not
inherit it implicitly from this design doc. The plan's Adam+Eve vet
should grep-confirm the per-arm pattern assignment against
`validator.ts` HEAD before TDD starts.

### Proposal 2 — `weyl` + `bianchi` FD pipelines into curvature-lowering-helpers

`lowerCurvature()` in `lowering.ts` has six arms; two of them (weyl
~85 LOC, bianchi ~42 LOC) are self-contained FD pipelines that already
have a natural home in `curvature-lowering-helpers.ts` (the v0.6.0 PD-6
extraction module).

**Extraction:** move the two arm bodies into the helpers module as
`lowerWeylTensor` + `lowerBianchiResidual`. The `lowerCurvature`
dispatcher becomes:

```ts
case 'weyl-tensor': return lowerWeylTensor(node, inputs, engine);
case 'bianchi-residual': return lowerBianchiResidual(node, inputs, engine);
```

### Tests (snapshot scaffolding dropped per E-R6)

The original design proposed pre-extraction snapshot tests. Per Eve's
E-R6 review finding, this is overkill: snapshot tests are brittle on
floating-point output + AST serialization, and existing test coverage
already pins both behaviors. **The existing test suite IS the guard.**

What runs in CI / TDD cycle:

- `tests/dimensional/*` — existing validator tests on all 11 kinds.
- `tests/numerical/weyl-*` + `tests/dimensional/bianchi-*` — existing
  numerical extraction tests.
- `tests/api/public-surface.test.ts` — pins the (unchanged) `src/index.ts`
  re-export set. Phase 2 must not affect this.

Extraction-cycle protocol per task:

1. RED — write a typed test that the extracted symbol does NOT yet
   exist (compile-time fail). Confirm RED.
2. GREEN-1 — extract the symbol; confirm typed test passes.
3. GREEN-2 — re-run the full vitest suite. Confirm ALL pre-existing
   tests still pass with bit-identical numerical output on Schwarzschild
   fixtures.
4. COMMIT.

### Deliverable

- 1 commit for `validator-registry.ts` extraction (Proposal 1).
- 1 commit for the weyl + bianchi helper moves (Proposal 2).
- LOC budget (revised per Adam-V10): `validator.ts` ~816 → ~735
  (drop ~80 LOC); `lowering.ts` ~1015 → ~890 (drop ~125 LOC).

## Risks

1. **Track A risk**: dropping `export` on a symbol that an unannounced
   downstream consumer depends on. Mitigation: every drop is on a
   non-`@public` symbol that does NOT appear in `tests/api/public-surface.test.ts`.
   The "balanced" policy (Decision #1) errs toward keeping any
   ambiguous symbol.
2. **Track B risk**: the validator-registry extraction introduces a
   subtle behavior change (e.g., the `propagateFreeIndices` flag is set
   wrong on one of the 10 kinds). Mitigation: the pre-extraction
   snapshot test (locked-in BEFORE the extraction) catches this.
3. **Track C risk**: the dep-graph generator fix over-broadens
   reachability and now hides real dead code. Mitigation: add a unit
   test fixture for the generator (a mini-source-tree) that pins both
   directions — known-reachable should be reachable; known-unused
   should still be flagged.
4. **Track D risk**: CLAUDE.md is the cross-session SoT; an edit that
   drifts from reality is high-impact. Mitigation: every edit is
   evidence-anchored (file existence check for `.ruff_cache`; grep
   count for bridge-status distribution).
5. **Track E risk**: the three benches reveal a real regression and
   force an unrelated investigation that blows the sprint timeline.
   Mitigation: Decision #5 commits to informational-only treatment.
   Any flagged regression becomes a follow-up `todo.md` item, not a
   v0.6.1 blocker.
