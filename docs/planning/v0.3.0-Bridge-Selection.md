# v0.3.0 Worked-Example Bridge Selection

**Date:** 2026-05-13
**Status:** Locked decision — input to v0.3.0-Implementation-Plan.md Task 13.

## Context

v0.3.0 adds three AST node kinds (`metric-tensor`, `kronecker-delta`,
`tensor-partial-derivative`) plus `raise()` / `lower()` / `pderiv()`
helpers. The release is justified by encoding at least one GR-flavored
bridge using these primitives. This decision record locks the bridge
BEFORE the spec is written (per v0.3.0-Design.md §13 Q4 + Implementation
Plan Task 1) so subsequent AST shapes, helper signatures, and error
messages can be validated against a real encoding from day one.

The 40-bridge catalog was surveyed via grep for GR-keywords
(`lensing|deflection|geodesic|schwarzschild|post-newtonian|friedmann|raychaudhuri|christoffel|covariant|metric`)
plus inspection of all bridges whose category-tag or title hinted at
gravity / spacetime physics. **No bridge in the catalog uses
gravitational lensing or post-Newtonian Schwarzschild as its primary
encoding** — both v0.3.0-Design.md §7 and the reasoners' suggestions
were hypothetical, not catalog references. The selection below works
within the actual catalog.

## Choice

**BE-37 (Shapiro gravitational time-delay)** is chosen because:

1. **Cleanest "before" baseline → "after" payoff.** BE-37's current
   v0.2.1 encoding is a pure scalar stub (zero tensor structure: the
   log-factor is a fresh dimensionless symbol `ln_R_ratio`, the LHS is
   a single time-dimensioned symbol). The structural rewrite via the
   null-geodesic eikonal `g^μν (∂_μ S)(∂_ν S) = 0` is the maximal
   v0.1.0/v0.2.x → v0.3.0 delta of any candidate, matching the BE-17
   precedent (typed-stub `T_torsion_squared` in v0.1.0 → structural
   rank-3 contraction in v0.2.0).

2. **Exercises all five surface items in one tight expression.** The
   eikonal seed `g^μν (∂_μ S)(∂_ν S) = 0` hits `metric-tensor`
   (inverse metric `g^μν`), `tensor-partial-derivative` (∂_μ S and
   ∂_ν S), `raise()` (raising one of the gradient indices via the
   inverse metric), and Einstein contraction through
   `computeContraction` (both μ and ν label pairs contract to a
   scalar). `kronecker-delta` is exercised indirectly through the
   optional `InverseMetricInconsistencyWarning` (Design §5) if we
   also declare `g_μν` alongside `g^μν` — fully covering the v0.3.0
   surface.

3. **Recognizable GR physics with literature provenance.** The
   eikonal / null-geodesic Hamilton-Jacobi equation in curved
   spacetime is a textbook GR derivation (MTW §22.5, Carroll §3.7);
   the Shapiro delay falls out as the first-order perturbative
   solution in the weak-field Schwarzschild metric. Future TensorJS
   readers grasp it immediately. This satisfies the "recognizable GR
   equation" bonus criterion in Task 1.

### Why not BE-17

BE-17 has a strong claim — it is *already* partially structural and
its own docstring nominates v0.3.0 as the next step — but its current
scalar invariant `T_λμν T^λμν` does NOT involve a partial derivative.
To exercise `pderiv` via BE-17 we would have to introduce a *different*
equation (the torsion conservation / Bianchi identity, ∂_μ T^μνρ),
which is not what's currently encoded and would amount to ADDING a
bridge rather than rewriting one. BE-37's eikonal form covers all five
items in a single canonical equation.

A complementary upgrade pass on BE-17 (replacing its
all-lower / all-upper idiom with explicit `lower(T^λμν, g, …)` × 3) is
worth doing as a SECONDARY worked example, but is not the v0.3.0
forcing function — leave it for the Task-13 polish or a v0.3.1 follow-up.

### Why not the lensing / Schwarzschild PPN candidates suggested by reasoners

Neither bridge exists in the 40-bridge catalog. v0.3.0-Design.md §7
sketches a deflection-angle expression as a HYPOTHETICAL preview;
implementing it would mean ADDING a new bridge (BE-51?), which is out
of scope for v0.3.0 (no new bridges, only restructuring existing ones).
BE-37 is the closest in-catalog match — same physics family (light
propagation in Schwarzschild), same surface coverage requirements.

## Sketch of the structural encoding

The rewrite uses the **null-geodesic eikonal in curved spacetime**
form as the foundational tensor equation. The original Shapiro delay
scalar `Δt = (2GM/c³) · ln(R_far/R_near)` is preserved as the LHS /
closed-form solution and as the numerical evaluator's output; the
v0.3.0 contribution is exposing the tensor-structural ORIGIN of that
scalar.

```typescript
import { tsym, contract } from '../../dimensional/tensor.js';
import {
  metric,
  raise,
  pderiv,
  kronecker,  // optional; for inverse-consistency check only
} from '../../dimensional/metric.js';
import {
  Dimension,
  DIMENSIONLESS,
  LENGTH,
  TIME,
} from '../../dimensional/types.js';

// --- Dimensions ---

/** Eikonal phase S has dim [length] in geometrized units
 *  (S/ℏ is the action; ∂_μ S = k_μ, the wave-4-covector). */
const EIKONAL_PHASE_DIM: Dimension = LENGTH;

/** Schwarzschild metric components are dimensionless in the (−,+,+,+)
 *  signature with coordinates carrying [length] (t = x⁰/c folded into
 *  the coordinate basis). */
const METRIC_COMPONENT_DIM: Dimension = DIMENSIONLESS;

// --- Coordinate basis (used as `wrt` for pderiv) ---

const x_coord = tsym(
  'x',
  [{ label: 'α', variance: 'upper' }],
  LENGTH,
  'coordinate',  // role flag — pderiv inherits dim-only from wrt
);

// --- Inverse metric g^μν (rank-2, both upper) ---

const g_inverse = metric(
  'g_inverse',
  [
    { label: 'μ', variance: 'upper' },
    { label: 'ν', variance: 'upper' },
  ],
  METRIC_COMPONENT_DIM,
  '-,+,+,+',  // Schwarzschild signature (Lorentzian, mostly-plus)
);

// --- (Optional) covariant metric g_μν, for inverse-consistency warning ---

const g_lower = metric(
  'g',
  [
    { label: 'α', variance: 'lower' },
    { label: 'β', variance: 'lower' },
  ],
  METRIC_COMPONENT_DIM,
  '-,+,+,+',
);

// --- Eikonal phase scalar field S(x) ---

const S = tsym(
  'S',
  [],                  // rank-0
  EIKONAL_PHASE_DIM,
);

// --- ∂_μ S  and  ∂_ν S  (rank-1 wave-covectors) ---

const dmu_S = pderiv(S, x_coord, { label: 'μ', variance: 'lower' });
// free indices: {μ:lower}, dim = LENGTH / LENGTH = DIMENSIONLESS
// (the gradient of an eikonal phase is the wave-covector k_μ)

const dnu_S = pderiv(S, x_coord, { label: 'ν', variance: 'lower' });
// free indices: {ν:lower}, dim = DIMENSIONLESS

// --- Raise ∂_μ S via g^μν → k^μ with free index ν' (alpha-converted) ---

const raised_grad = raise(dmu_S, g_inverse, 'μ');
// internal alpha-conversion (Design §6 / Decision 8a): the inverse
// metric's labels are renamed so one matches 'μ' (contracts with the
// gradient) and the other is a fresh non-colliding label. Result is a
// tensor-product whose free index is the fresh label, variance upper.

// --- Contract raised_grad with ∂_ν S → scalar  g^μν (∂_μ S)(∂_ν S) ---
//
// In the eikonal limit of null geodesics this scalar = 0; in the
// weak-field perturbative expansion around Minkowski it yields the
// Shapiro delay integrand.

const eikonal_lhs = contract(raised_grad, dnu_S);
// All labels paired → scalar. Validator confirms freeIndices empty,
// dim = DIMENSIONLESS · DIMENSIONLESS · DIMENSIONLESS = DIMENSIONLESS.

// --- The null-geodesic / eikonal equation (LHS = 0) ---
//
// g^μν (∂_μ S)(∂_ν S) = 0
//
// The Shapiro delay arises from solving this perturbatively in the
// Schwarzschild g^μν; the closed-form scalar Δt = (2GM/c³)·ln(...)
// is the integrated first-order solution along a null ray.

export const BE37_EIKONAL_LHS = eikonal_lhs;
export const BE37_EIKONAL_RHS_ZERO = sym('zero', DIMENSIONLESS);
//                                ^ dimensionless null marker; same
//                                  convention as existing zero-RHS
//                                  bridges (e.g., BE-36 ratio bound)

// The existing BE37_SHAPIRO_DELAY_LHS / _RHS scalar pair is RETAINED
// as the closed-form solution and the numerical evaluator's surface.
// The eikonal AST is the v0.3.0 STRUCTURAL ORIGIN of that scalar.
```

### Optional inverse-consistency check

```typescript
// Demonstrates the kronecker-delta primitive — only fires the
// InverseMetricInconsistencyWarning if g · g_inverse ≠ δ. For
// Schwarzschild declared correctly this is satisfied.

  g_inverse,           // g^μν   (free: μ:up, ν:up)
```

## What the sketch tells us about the spec

1. **`pderiv(of, wrt, wrtIndex)` of a rank-0 scalar must yield a
   rank-1 tensor with the wrtIndex as its only free index.** This is
   the most-exercised composition in the sketch (`pderiv(S, x_coord,
   {label: 'μ', variance: 'lower'})`) and the validator rule
   `freeIndices = freeIndices_of ∪ {wrtIndex.label: lower}` (Design
   §5) must handle the empty-`freeIndices_of` case correctly. The
   spec's pderiv validation rules section should call this case out
   explicitly with a worked example.

2. **`raise()`'s internal alpha-conversion must handle the `operand
   has only one free index` case.** `raise(dmu_S, g_inverse, 'μ')`
   alpha-converts `g_inverse`'s labels so one matches 'μ' (contracts
   with the gradient's lone free index) and the OTHER becomes a fresh
   non-colliding label that survives as the output's free index. The
   fresh-label generator must NOT collide with 'μ', 'ν' (which appear
   in `dnu_S`, not in `dmu_S`), or `x_coord`'s 'α'. The deterministic
   naming scheme (Design §6 — "e.g., `<original-label>_<counter>`")
   must produce a label that doesn't trip later contractions when
   `raised_grad` is plugged into `contract(raised_grad, dnu_S)`. This
   is a load-bearing test case for `raise-lower.test.ts`.

3. **`metric-tensor.dim = DIMENSIONLESS` is the canonical case for GR
   work.** The (−,+,+,+) Schwarzschild metric has dimensionless
   components when coordinates carry their natural dimension. The
   spec's "user specifies dim per encoding" (Decision 4) is correct,
   but the Part-VIII §VIII.2 "metric-tensor invariants" section
   should document `DIMENSIONLESS` as the GR-canonical case and
   `[L²]` (Faraday-style geometrized) as a future-work case
   (cross-references §VIII.10 v0.5.0+ refactor scope).

4. **The contraction algebra is genuinely unchanged.** Both
   `raise(dmu_S, g_inverse, 'μ')` and `contract(raised_grad, dnu_S)`
   pass through `computeContraction` without algorithmic
   modification. This confirms Design §3's load-bearing claim that
   "`computeContraction` barely changes in v0.3.0" — the sketch
   demonstrates `tensor-product` composition is sufficient to make
   the new primitives work end-to-end. The spec should explicitly
   state this invariant: `metric-tensor` and `pderiv`-derived nodes
   are first-class `tensor-product` arguments, no special-casing
   needed in the contraction engine.

5. **`tensor-partial-derivative.wrtIndex.variance === 'lower'` is
   non-negotiable.** The spec's `PartialDerivativeIndexVarianceError`
   (Design §5) MUST fire if a user writes `pderiv(S, x_coord, {label:
   'μ', variance: 'upper'})`. Physically, ∂/∂x^μ has a covariant
   operator index regardless of the coordinate's variance — Design
   §5's "wrt-argument semantics spec comment" pins this. The sketch
   demonstrates the rule is needed in the simplest possible context
   (scalar field S, single-index gradient). Test the negative case
   in `tests/dimensional/tensor-partial-derivative.test.ts`.

6. **The inverse-consistency check is optional but the
   `kronecker(μ, λ)` constructor is real either way.** Even if
   `InverseMetricInconsistencyWarning` is deferred to v0.3.5 (per
   Implementation-Plan adjudication §13 Q2), the
   `kronecker-delta` AST node and its constructor must exist in
   v0.3.0 — at minimum to validate the `g · g_inverse ≟ δ` machinery
   when it lands. The sketch shows the constructor signature
   `kronecker('μ', 'λ')` (upper-first per Decision 7a / §13 Q3) is
   the right shape; the optional `dim` default of DIMENSIONLESS is
   correct for the canonical δ^μ_ν.

## Forward-compat anchor

This bridge encoding is the canonical seed for:

- **v0.3.5 mathjs lowering**: `g_inverse` and `dmu_S` will be lowered
  to numerical `math.Matrix` instances; the Shapiro delay's numerical
  evaluator (already shipped) is the reference for end-to-end
  numerical agreement.
- **v0.4.0 covariant derivative**: the eikonal equation in the
  *covariant* form `g^μν (∇_μ S)(∇_ν S) = 0` is the natural v0.4.0
  successor; v0.3.0 ships the ∂_μ version, v0.4.0 swaps ∂_μ → ∇_μ
  with Christoffel symbols. The sketch's structure is preserved
  verbatim; only the helper changes.
- **v0.5.0+ Faraday-cascade refactor**: BE-37's encoding uses
  uniform-dim metric (`DIMENSIONLESS` components), so it is NOT a
  forcing case for the Faraday mixed-dim refactor — it remains
  v0.3.0-encoding-stable through that refactor. This is a feature,
  not a bug: the worked example should not couple to the v0.5.0
  breaking change.
