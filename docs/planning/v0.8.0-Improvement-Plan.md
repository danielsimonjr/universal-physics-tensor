# v0.8.0 Improvement Plan — Post-Spec-Review Assessment

> **Provenance:** Written 2026-06-10, at the close of the full
> specification review session (branch
> `claude/bridge-equations-specs-review-4mfy38`) that completed the
> 44-bridge catalog in the spec, added Part-X + the spec index, relocated
> the wave-note history to `docs/specification/CHANGELOG.md`, and
> condensed the root README. This document records the resulting
> whole-project assessment and the prioritized improvement plan for the
> v0.8.0 cycle. It is an opinionated planning input, not a vetted design —
> run it through the Adam+Eve adversarial pair before converting any item
> into an implementation plan.

## Overall assessment

UPT is an unusually epistemically disciplined project, and that
discipline makes its central weakness visible: **the engineering is far
ahead of the science.**

What is genuinely strong:

- **Epistemic honesty.** The Part-I framing commitment ("Π is a catalog,
  not a tensor; 'tensor' is brand"), the status taxonomy with no
  unearned promotions (8 established · 33 speculative · 3
  highly-speculative), honest negative results (PC-1 refuted and
  documented), and the explicit "NOT claiming to have unified physics"
  posture. This is rare and is the project's best asset.
- **Engineering discipline.** 2126 tests, bidirectional spec↔code drift
  guards, regression pins on past bugs (ricci slot, prefactor
  reconciliations), and an adversarial-review loop that has caught real
  defects.
- **Real numerics.** The GL4 symplectic integrator validated against
  Mercury's perihelion (relErr 1.8×10⁻⁷) and Shapiro delay (~2×10⁻⁸) is
  legitimate numerical relativity. The dimensional AST validator with
  machine-checked round-trips across 42 encoded bridges is the project's
  most defensible scientific artifact.

The unanswered question is the one the README's own Vision section
poses: what does representing all of physics in a single indexed object
*buy*?

## Major gaps (ranked)

### G-1. The central object doesn't do anything yet

Π has six axes, but no computation uses the six-axis structure. All
computational value lives in individual bridge evaluators and the GR
pipeline — a flat list of 44 bridges would deliver identical results
today. The v0.7 flux rules and Cell machinery are bookkeeping over the
structure, not physics from it. The unification promise is currently an
indexing scheme.

**Resolution path:** Part-IX composition Phase B. If composing two
bridges derives a third relation the literature confirms, that is the
first moment the catalog structure earns its keep. This should outrank
any further catalog extension or hygiene sprint.

### G-2. The bridge ontology is unprincipled

The catalog is a curated reading list more than a defined class of
objects. The physics audit flagged ~9 entries as NOT-A-BRIDGE and
renamed 17; the BE-42 and BE-29 reversals are still parked awaiting a
physics-judgment session. Many entries are famous single-domain
equations relabeled as bridges (Hawking temperature, Landauer). Missing:
a crisp membership criterion — *what property must an equation have to
be a bridge?* — applied uniformly. Without it, "44 bridges" counts
editorial decisions, not physical connections, and a physicist reviewer
will notice within ten minutes.

**Resolution path:** write the bridge membership criterion; re-adjudicate
the full catalog against it, folding in the deferred BE-42/BE-29
decisions. A 30-bridge catalog with a principled definition beats a
44-bridge catalog without one.

### G-3. Validation is asymmetric: reproduction, not confrontation

Everything validated so far reproduces known closed-form results — which
validates the *machinery*, not the *bridges*. Part-IV's experimental
roadmap is honest but aspirational (2035–2050+). Bridges that could meet
real data now: BE-36's GW170817 graviton-speed bound, BE-21/BE-23
condensed-matter scalings, the BE-21-adjacent KSS bound. One pipeline
that ingests one actual dataset and scores one bridge against it is
worth more scientifically than ten more catalog entries.

**Resolution path:** real-data validation pipeline, first target
GW170817 → BE-36 (the bound is already encoded as a dimensionless
ratio).

### G-4. The core spec dilutes credibility

Parts I–VI still carry large speculative essays — Part-V's medical
device specifications and existential-risk analysis, Part-VI's
cosmic-engineering content — caveated but present. Meanwhile the spec
inverted: the real algorithms (GL4, lowering, the validator) are spec'd
only in supplements VII/VIII/X, while the core parts describe pseudocode
none of which is implemented. For the stated goal of recruiting
physicists, the core spec is the front door, and it currently makes the
strongest material hardest to find.

**Resolution path:** relocate the application/risk essays into a
separate `docs/essays/` companion; let Parts I–VI shrink toward
foundation + catalog + what is actually built.

### G-5. No on-ramp for the collaborators the README asks for

No `CONTRIBUTING.md`, no per-bridge "what would falsify this" statement,
no arXiv/Zenodo presence or DOI to cite. A physicist arriving today has
no bounded task to pick up.

**Resolution path:** CONTRIBUTING.md listing 5–10 concrete review tasks
(e.g., "check BE-23's Planckian-dissipation encoding against Hartnoll
2015"; "adjudicate the BE-42 NOT-A-BRIDGE dispute — both arguments are
in BRIDGE-PHYSICS-AUDIT-v2"). Consider a Zenodo DOI for citability.

### G-6. No CI

Verified 2026-06-10: no `.github/workflows/`. All 2126 tests run only
when someone runs them. Given how much credibility rests on the test
discipline, a GitHub Actions gate (test + tsc + drift guards) is cheap,
makes the green badge public, and mechanically protects against the
spec↔code drift this review spent a session cleaning up. It also
complements the LLM-only Adam+Eve loop, whose ceiling is documented
(Eve fabrication history; two plan bugs that slipped to TDD).

### G-7. Smaller debts (mostly already in existing ledgers)

- Orphaned `src/bridges/equations/be-25-orch-or.ts` beside the IIT
  replacement (archive-or-delete deferred from v0.7.3 queue).
- `KleinGordonEquationNode` has no numerical evaluator (wave-operator
  lowering deferred).
- Kretschmann O(4⁸) contraction cost (P-6, deferred; correctness gates
  pass at current cost).
- MathTS optional-peer chain fragility across environments
  (typed-function EOVERRIDE class of failure).
- `describe.skipIf` debt: one remaining gate in
  `tests/diff/bridge-gradient.test.ts`.

## Top three for v0.8.0

1. **Execute Part-IX Phase B (composition).** One literature-confirmed
   composed relation changes the project's category from "organized
   catalog" to "framework that derives things." (G-1)
2. **Wire one real dataset to one bridge.** GW170817 → BE-36. (G-3)
3. **Write the bridge membership criterion and re-adjudicate the
   catalog**, resolving the deferred BE-42/BE-29 NOT-A-BRIDGE
   decisions. (G-2)

Supporting (cheap, high leverage, can land any time): CI workflow (G-6),
CONTRIBUTING.md (G-5).

Deferrable to v0.9+: core-spec essay relegation (G-4), G-7 items.

## Closing note

The project's signature virtue is that it never claims more than it
has. The next phase should be about *having more*: one derivation, one
dataset, one definition.
