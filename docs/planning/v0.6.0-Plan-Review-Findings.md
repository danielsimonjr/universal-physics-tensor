## CRITICAL

### P-1 (Adam) — `CurvatureCompositeNode<K, S>` type is decorative; S is unused

**Quote (Task 3.9)**:
```typescript
export interface CurvatureCompositeNode<K extends CurvatureKind, S> {
  readonly kind: K;
  // S contains kind-specific slots (e.g., for Ricci: { riemann: RiemannTensorNode })
}
```

**Issue**: The `S` generic parameter is declared but not referenced in the interface body. A consumer writing `CurvatureCompositeNode<'ricci-tensor', { riemann: RiemannTensorNode }>` gets a type with ONLY `{ kind: 'ricci-tensor' }` — the `riemann` field is invisible to the type system. Future TDD tasks (3.10a–e migrating six kinds) would silently drop slot type safety.

**Action**: Use an intersection type:
```typescript
export type CurvatureCompositeNode<K extends CurvatureKind, S> = {
  readonly kind: K;
} & S;
```
Update Task 3.9 plan body. Update Task 3.10 sub-tasks to use the corrected form when migrating each kind.

### E-4 (Eve) — Schwarzschild vacuum residual `< 1e-9` may be over-tight

**Quote (Task 2.4)**: "G_μν residual <1e-9 at 10 sample points"

**Issue**: With Schwarzschild's `c²·g_tt ~ 6e16` SI scale and 4th-order FD, truncation error is `O(h⁴ · ∂⁶g)`. Eve's order-of-magnitude estimate: `h ~ 10⁻³` (in meters) and `|g_tt'| ~ c²/r ~ 10¹⁰`, giving truncation floor `~10⁻⁴` to `~10⁻⁶`. The actual floor depends on the metric — but `1e-9` is suspiciously below 4th-order's reach at this scale.

**Action**: Don't lock `1e-9` in the test pin. Update Task 2.4 plan:
1. First run a measurement: implement the residual evaluator, compute on 10 points, record the actual residual distribution.
2. Lock the tolerance at `2× max_observed_residual` as a safety margin.
3. If the observed floor is much higher than `1e-9` (e.g., `1e-5`), document the limitation and consider Richardson-extrapolated 6th-order FD as a v0.7.0 follow-up. **Don't ship a failing pin.**

### P-4 (Adam) — TDD RED-step rigor on numerical tests

**Quote (Task 2.4)**: "Schwarzschild vacuum pin (10 points, residual <1e-9)"

**Issue**: For numerical pins, the RED step is non-obvious. A test that asserts `residual < 1e-9` will *pass vacuously* if the evaluator returns 0 (e.g., a stubbed implementation). The RED-step rigor: assert against a known-bad value first to verify the test discriminates.

**Action**: For all numerical-pin tasks (2.4, 2.5, 2.7, 3.3, 3.7, 3.8), add an explicit Step 1.5: "Verify the test's RED state by first stubbing the evaluator to return a non-zero residual (e.g., 1.0) and confirming the test fails. Then implement the real evaluator and confirm GREEN." Three-step TDD instead of two-step.
