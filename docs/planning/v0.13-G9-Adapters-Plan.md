# G-9 Increment 1 — Geometrized Boundary Adapters (Implementation Plan)

Converts the Adam-vetted design note (`v0.10.0-Units-Normalization-Design-Note.md`,
r2) into an executable plan for the FIRST, self-contained increment: the
dimension-functor-driven SI↔geometrized conversion adapters. The risky parts of
the full design (geometrized fixtures, the whole GR-pipeline migration, the
FD-order order-2 claw-back) are explicitly INCREMENT 2 — deferred, with their own
plan + vet (one foundation change at a time; the v0.5.0/v0.5.1 lesson).

## Scope (increment 1 — additive, zero blast radius)

A new pure module that converts a scalar between SI and geometrized (G = c = 1)
units, driven mechanically by the existing `Dimension` exponent vector. It
touches NOTHING in the existing pipeline — it is the foundation the pipeline
migration (increment 2) will later sit on.

### The conversion (Adam r2 §2, re-derived)

For an SI quantity of dimension `L^l M^m T^t`:
`Q_geom = Q_SI · G^m · c^(t − 2m)` — only the M and T exponents enter (each kg →
`G/c²` metres, each second → `c` metres). The residual geometrized quantity is a
pure length `L^(l+m+t)`. Inverse: divide by the same factor.

Self-consistency check (in the plan, pinned by a test): `to(mc²) === to(m)` —
mass-energy and mass map to the same geometrized length.

### API (`src/numerical/geometrized.ts`, INTERNAL)

```ts
/** The single c/G factor for `dim`: G^M · c^(T − 2M). Shared by to/from so the
 *  round-trip is exact to 1 ulp. Throws on a non-mechanizable dimension. */
export function geometrizedFactor(dim: Dimension): number;
export function toGeometrized(valueSI: number, dim: Dimension): number;   // · factor
export function fromGeometrized(valueGeom: number, dim: Dimension): number; // / factor
export class NonGeometrizableDimensionError extends Error {} // I/Θ/N/J ≠ 0
```

Placement: `src/numerical/` (geometrization is a numerical-pipeline concern;
`numerical/` already imports `core/constants` for `C_SI`/`G_SI`). Internal — no
public-surface change; the public-API geometrized adapters are an increment-2
concern.

### Domain guard (Adam r2 §2)

`geometrizedFactor` throws `NonGeometrizableDimensionError` when any of
`I, Θ, N, J` is nonzero — only c and G are in scope; k_B/ε₀ extensions are
increment-2+ (and tie into the Eve M-1 per-quantity unit-convention tag, OUT of
scope here). `L, M, T` may be any real (fractional exponents from `^` are fine —
`Math.pow` handles them).

## Why the tests are the gate (Adam r2 §6: round-trips alone are insufficient)

A consistently-WRONG factor cancels in a round-trip, so round-trip ≠ correct.
The test suite therefore pins, in order of strength:

1. **Absolute factor pins** (the load-bearing check — they fix the factor, not
   just its self-inverse):
   - `toGeometrized(M_SUN_SI, MASS)` ≈ `GM_sun/c²` ≈ **1476.6 m** (the
     Schwarzschild radius is `2×` this; standard NR value).
   - `toGeometrized(1, TIME)` === **`C_SI`** (1 s → c metres, exact).
   - `toGeometrized(x, LENGTH)` === `x` (length is the geometrized base; factor 1).
   - `toGeometrized(c, VELOCITY)` === 1 (the speed of light is geometrized-1).
2. **Self-consistency**: `toGeometrized(E_rest, ENERGY)` ≈ `toGeometrized(m, MASS)`
   for `E_rest = m·c²` (mass-energy equivalence through the functor).
3. **Round-trip property** (across a lattice of dims — length, mass, time,
   velocity, energy, acceleration, and a couple negative/fractional exponents):
   `fromGeometrized(toGeometrized(x, dim), dim)` === `x` to ≤1 ulp (relative).
   Shared-factor implementation makes this exact.
4. **Domain guard**: `CHARGE` (I≠0), `TEMPERATURE` (Θ≠0) throw
   `NonGeometrizableDimensionError`.

## Out of scope (increment 2+, named so the boundary is explicit)

- Geometrized Schwarzschild/PG fixtures + SUBSUMING the ad-hoc `unitless` (c=1)

- Routing the GR pipeline (`christoffelAt`→`dGammaAt`→`buildRiemann`→GL4,
  kretschmann/weyl, killing, bianchi, BE-37 eikonal, BE-51/52, perihelion) onto
  the geometrized fast path, with public-API adapters at the boundary.
- The FD order-2 claw-back truncation-vs-roundoff sweep (Adam r2 §3 — a measured

- The x⁰=ct coordinate convention + per-component tensor bookkeeping (Adam r2 §1).
- The Eve M-1 per-quantity unit-convention tag (GeV/J, bits/nats) — a separate
  axis from c/G geometrization.

## Eve vet — revisions applied (binding)

Eve verdict: YELLOW, all numerics independently computed. Direction, domain
guard, placement, and 3/4 pins bit-verified correct. Binding fixes:

- **(F-1, HIGH) The M_sun pin literal was wrong for the repo's constants.**
  `G_SI·M_SUN_SI/C_SI² = 1477.063 m` (grep-verified), NOT the design note's
  1476.6 m (that is the IAU-nominal `GM_sun`, inconsistent with
  `M_SUN_SI = 1.989e30`). Pin against the EXPRESSION
  `(G_SI*M_SUN_SI)/(C_SI*C_SI)` (self-tracking) with a coarse sanity band
  (1476 < x < 1478), not a hardcoded literal.
- **(F-4, MEDIUM) `NonGeometrizableDimensionError extends UPTError`** (the
  repo error hierarchy, `errors.ts:12`), sets `this.name`, and calls
  `Object.setPrototypeOf(this, …prototype)` — matching every sibling
  (`TensorInScalarOpError`, etc.). NOT bare `extends Error {}`.
- **(F-2/F-3) Assertion style.** Round-trip and the `to(mc²)≈to(m)`
  self-consistency are RELATIVE-tolerance (≤ a few ulp, e.g. 1e-15) — NOT
  `===` (op-order/`Math.pow` differences; measured max round-trip rel error
  1.78e-16). Reserve `===` for the three Eve bit-verified pins: LENGTH-identity
  (factor 1), `to(1, TIME) === C_SI`, `to(C_SI, VELOCITY) === 1`. Drop the word
  "exact" for the general round-trip.
- **(F-5) Guard order.** `geometrizedFactor` checks `I/Θ/N/J ≠ 0` and throws
  BEFORE computing any `Math.pow` factor (a pure exponent predicate).
