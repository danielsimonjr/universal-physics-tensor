## CRITICAL findings (must fix before plan)

### F-1 (Adam) — Wrong closed-form `K(r_s)` in Kretschmann horizon test

**Quote (design Phase 3 Tests)**: "kretschmann-horizon: `K(r_s) = 3/(4G²M²)` is finite (coordinate-singularity diagnostic)."

**Math check** (independently verified):
`K(r) = 48G²M²/(c⁴·r⁶)` with `r_s = 2GM/c²` ⇒ `r_s⁶ = 64G⁶M⁶/c¹²`, so:

```
K(r_s) = 48G²M²·c¹² / (c⁴ · 64G⁶M⁶) = (48/64) · c⁸/(G⁴M⁴) = 3c⁸/(4G⁴M⁴)
```

The design's `3/(4G²M²)` is dimensionally wrong by a factor `c⁸/(G²M²)` and would fail at TDD-RED on the first run. Standard reference: Schwarzschild Kretschmann at horizon — `K = 12/r_s⁴` in geometrized units (`c = G = 1`), which becomes `3c⁸/(4G⁴M⁴)` after restoring SI units via `r_s = 2GM/c²`.

**Action**: Update design Phase 3 test spec to `K(r_s) = 3c⁸/(4G⁴M⁴)`. Same fix needed in test fixture for `tests/numerical/kretschmann-horizon.test.ts` when Phase 3 lands.

## HIGH findings

### F-2 (Adam) — `ρ` ambiguity in perfect-fluid stress-energy

**Quote (design Phase 2)**: "perfectFluidStressEnergy(rho, p, fourVelocity, metric) returning T_μν array for `T_μν = (ρ + p/c²) u_μ u_ν + p g_μν`."

**Issue**: The formula `(ρ + p/c²) u_μ u_ν` is dimensionally consistent **only** if `ρ` is mass density `[M·L⁻³]` (then `p/c²` is `[M·L⁻¹·T⁻²]/[L²·T⁻²] = [M·L⁻³]` matches). If `ρ` were energy density `[M·L⁻¹·T⁻²]`, the addition is dimensionally inconsistent. The Friedmann test `H² = 8πGρ/3` is conventionally written with mass density.

**Action**: Lock `ρ` as **mass density** `[M·L⁻³]` (kg/m³) in JSDoc; rename parameter `massDensity` (deprecating `rho` as a parameter name). Add a dim-check assertion in the numerical evaluator. Update `einstein-flrw.test.ts` fixture comment to make the convention explicit.

### F-3 (Adam) — `verifyKillingEquation` FD tolerance optimism

**Quote (design Decision #1)**: "verifyKillingEquation with 4th-order FD covariant derivatives, default tolerance 1e-12".

**Issue**: `∇_μ ξ_ν + ∇_ν ξ_μ = ∂_μ ξ_ν + ∂_ν ξ_μ − 2 Γ^λ_{μν} ξ_λ`. The Christoffels carry first derivatives of `g`, so `verifyKillingEquation` evaluates `∂ξ − (∂g)ξ`-grade quantities numerically. On Schwarzschild's `c²·g_tt ~ 6e16` scale, the v0.5.1 c²-cancellation noise footgun (memory `feedback_v0_5_0_plan_template_riemann_bug.md` / v0.5.1 lesson) bites. Tolerance `1e-12` may be unachievable even for the symmetric Schwarzschild fixture.

**Action**: Two-pronged mitigation:
1. **Tighten the precondition**: use exact symbolic Christoffels (`schwarzschildChristoffelFn`) for the inner `Γ^λ_{μν} ξ_λ` term, FD only the outer `∂_μ ξ_ν` partials. This eliminates the metric-derivative cancellation.
2. **Document a realistic floor**: tolerance default `1e-10` (not `1e-12`), with `1e-12` as an explicit override for analytically-given Killing fields.

### E-2 (Eve) — Energy sign convention on `ConservedChargeNode`

**Quote (design Phase 1)**: "ConservedChargeNode (Q = ξ^μ p_μ). … Schwarzschild fixtures: ξ^t = [1,0,0,0]."

**Issue**: In (−,+,+,+) signature with timelike Killing vector `ξ^μ_t = (1,0,0,0)`, `Q = ξ^μ p_μ = p_t`. But `p_t < 0` for forward-time motion of massive particles (Carroll Eq. 8.29–8.30), so physical energy `E ≡ −p_t = −Q`. The design's diagnostic `max|ΔE/E|` will report **negative** Q values, which is fine in magnitude but trips intuition.

**Action**: Add an explicit "**Sign convention**" section to the design:
> Conserved charges are returned **raw** as `Q = ξ^μ p_μ`. For timelike Killing vectors in (−,+,+,+) signature, physical energy `E ≡ −Q`. Test fixtures and the PC-1.5 diagnostic use `|ΔQ/Q|` (sign-agnostic) to avoid the convention question.

Document the −1 sign in `evaluateConservedCharge` JSDoc.

## MEDIUM findings

### F-4 (Adam) — "GR theoretical closure" overclaim in goal framing

**Quote (design Goal)**: "Ship v0.6.0 as a GR theoretical closure minor bump."

**Issue**: Missing primitives for full classical-GR closure:
- **Geodesic deviation equation** `D²V^μ/dτ² = R^μ_{νρσ} U^ν V^ρ U^σ` (the *physical* meaning of Riemann tidal forces)
- **Einstein-Hilbert action** `S = ∫(R + L_M)√−g d⁴x` (variational foundation)
- **Junction conditions** (Israel-Lanczos; needed for stellar-interior–exterior matching)
- **Lie derivative `ℒ_X`** (currently deferred — but it's the natural definition of Killing: `ℒ_ξ g = 0`)

**Action**: Reframe goal as "**Einstein field equation closure + curvature-classification + Shapiro investigation**" — narrower and accurate. Add the four missing primitives explicitly to v0.7.0 non-goals/roadmap.

### F-5 (Adam) — Weyl mixed-variance index gymnastics unspecified

**Quote (design Phase 3)**: "C^ρ_{σμν} = R^ρ_{σμν} − (1/(n−2)) (δ^ρ_μ R_{σν} − δ^ρ_ν R_{σμ} − g_{σμ} R^ρ_ν + g_{σν} R^ρ_μ) + ..."

**Issue**: The formula mixes `R_{σν}` (Ricci lower-lower, already shipped) with `R^ρ_ν` (mixed-variance Ricci, requires `g^{ρα} R_{αν}` contraction). UPT does not yet have a dedicated mixed-variance Ricci primitive. `weyl-lowering.ts` must perform the metric inversion + raising step explicitly.

**Action**: In `src/numerical/weyl-lowering.ts`:
1. Compute Ricci once via existing `RicciTensorNode` lowering
2. Raise the first index via `R^ρ_ν = g^{ρα} R_{αν}` using the existing `metric-inverse.ts`
3. Document the contraction pattern in module JSDoc
4. Add a non-diagonal-metric regression test (Kerr-Schild coordinates or a 2-D rotated frame) to catch index-raising bugs that pass on diagonal Schwarzschild

### E-3 (Eve) — Friedmann `c²` factor accounting in FLRW test

**Quote (design Phase 2)**: "FLRW Friedmann `H² = 8πGρ/3` to relErr <1e-7"

**Issue**: With `T_00 = ρc²` (mass-density convention per F-2) and SI Einstein equation `G_00 = (8πG/c⁴) T_00`, the RHS is `8πGρ/c²`. The corresponding `G_00` in FLRW with metric `−c²dt² + a²δ_ij dx^i dx^j` is `3H²/c²` (the c² appears via `g_00 = −c²`). Both sides carry `1/c²` → cancels cleanly to `H² = 8πGρ/3`. **Math works**, but the test fixture must use a consistent metric convention or it goes red by a factor `c²`.

**Action**: In `tests/numerical/einstein-flrw.test.ts`:
1. Pin the metric as `g_μν = diag(-c², a(t)², a(t)², a(t)²)` (full-SI with `c²` retained)
2. Pin `T_00 = ρ c²` with explicit `c² *` in the fixture
3. Add a regression test using `c = 3e8 m/s` (not `c = 1`) to catch unit-mistake regressions

### E-5 (Eve) — BR-2 cache layout: λ-major encoding may defeat prefetch

**Quote (design Phase 2)**: "index encoding `(λ,μ,ν) → 16λ + 4μ + ν`"

**Issue**: GL4 inner-loop access pattern is typically `Γ^λ_{μν} U^μ U^ν` — for fixed (λ), the integrator iterates `(μ, ν)` over all 16 components. λ-major encoding makes `(μ, ν)` access have stride 1 within a 16-element block, which is fine. **But** if the inner pattern is `Γ^λ_{μν} U^ν` for fixed (λ, μ) iterating ν, that's still stride 1. So Eve's specific cache concern is probably mooted by Mercury's loop shape. **Worth verifying empirically**, not in design.

**Action**: Phase 2 Task 0 (above) prototypes both `λ-major (16λ+4μ+ν)` and `ν-major (16ν+4μ+λ)` layouts on a microbench; lock the winning layout into the breaking ABI.

## REJECTED finding (Eve hallucination)

### E-1 (Eve) — Weyl prefactor "off by factor 2" — **NOT A REAL BUG**

**Eve's claim**: Design uses `1/(n-2)` and `1/((n-1)(n-2))`; "Wald Eq. 3.2.5 and Carroll Eq. 3.103" use `2/(n-2)` and `2/((n-1)(n-2))`. For n=4, design says 1/2 and 1/6; correct should be 1 and 1/3.

**Verification by hand**:

Wald's form uses antisymmetrization brackets: `g_{a[c} R_{d]b} ≡ (1/2)(g_{ac} R_{db} − g_{ad} R_{cb})`. With brackets, prefactors are `2/(n-2)` and `2/((n-1)(n-2))`. Expanding brackets explicitly (which the design does):

```
g_{a[c} R_{d]b} − g_{b[c} R_{d]a}
  = (1/2)(g_{ac}R_{db} − g_{ad}R_{cb} − g_{bc}R_{da} + g_{bd}R_{ca})
```

Multiplying both sides by `2/(n-2)` and the (1/2) from bracket-expansion gives `1/(n-2)` per term — exactly the design's form. The two forms are mathematically identical; Eve did not recognize the antisymmetrization-to-expanded notation transformation.

**Hallucination signature**: cited specific equation numbers ("Wald Eq. 3.2.5", "Carroll Eq. 3.103") with high confidence; these eq numbers may or may not exist but the substance of the claim is wrong. Consistent with the 55% rate from v0.5.1 audit-vet (memory `feedback_eve_o3_hallucinations.md`).

**Action**: No code change. Document in this findings doc as an Eve-style hallucination caught at vet time. Update memory entry if useful.
