# v0.14 — G-9 Increment 3 (Default-Pipeline Migration) — Design / Disposition

The original G-9 design (`v0.10.0-Units-Normalization-Design-Note.md`) queued, as
the final increment, "route the DEFAULT GR pipeline onto the geometrized fast
path + subsume the `unitless*` fixture family." This note RE-EXAMINES that
increment against what increments 1–2 actually established, and reaches an
evidence-based split: **the default-pipeline migration is NOT justified and is
declined; the fixture-name consolidation IS justified and is done.**

## The migration's premise has collapsed (the honest finding)

The original "bug class" (design note §"The bug class") rested on three
documented strikes. Every one is now resolved or misattributed:

1. **"SI c² ≈ 9×10¹⁶ on g_tt causes catastrophic FD cancellation → geometrized
   units improve precision."** REFUTED. Adam (increment 1, r2 §3) + Eve
   (increment 2, Y3) independently established that per-component central-
   difference RELATIVE error `ε|f|/(h|f′|)` is SCALE-INVARIANT (multiply `f` by
   c² and numerator + truncation term scale identically). Geometrization cannot
   improve per-component relative FD accuracy. This is not just theory — it is
   MEASURED: the increment-2 geometrized Schwarzschild Kretschmann had relErr
   **4.06e-7** at r=50·r_s versus the SI fixture's **2.95e-8** at the same point
   (`tests/numerical/geometrized-schwarzschild-equivalence.test.ts` vs
   `kretschmann-schwarzschild.test.ts`) — geometrization was ~14× WORSE at far
   field, comparable near field. There is no measured precision win to bank.
2. **The v0.5.1 Schwarzschild "cycloid blowup."** Adam (increment-1 vet, r2 §4)
   reclassified this as inline-constant DRIFT (units-consistency class), NOT
   c²-cancellation — so geometrization was never its fix.
3. **The 4th-order `pderiv` default cost ("2nd-order claw-back").** CUT in
   increment 2 (Eve Y3) as provable unit-invariant ceremony, already covered by
   `pderiv-order*.test.ts`. The order-4 default stands; there is nothing to claw
   back.

The mixed-scale ABSOLUTE cancellation that geometrization could in principle help
(`g_tt=−f·c²` ≈ −9e16 beside `g_θθ=r²`) is, per Eve (increment 2, Y3), "partly
already engineered away in SI" via the inner FD step + the analytic
`schwarzschildDgFn` bypass — and the increment-2 measurement shows the net effect
is no improvement.

## Decision: DECLINE the default-pipeline migration

Routing `christoffelAt → dGammaAt → buildRiemann → GL4`, kretschmann/weyl,
killing, bianchi, BE-37 eikonal, BE-51/52, and the perihelion finder onto a
geometrized default would re-derive the unit convention of the entire GR pipeline
— a high-blast-radius foundation change — to buy a precision improvement that is
MEASURED to be absent (and at far field, negative). The acceptance criterion (a)
in the original design was "reproduce CURRENT relErr (1.8e-7 / ~2e-8)" — i.e. the
best case was break-even, and the measured evidence is worse-or-equal. Per the
repo's own discipline (RED-test every numeric prediction; measure-then-lock; one
foundation change per cycle), a risky rewrite with no measured benefit is exactly
what NOT to ship. **The geometrized layer remains the OPTIONAL public boundary
API delivered in increment 2; the SI pipeline stays the default.**

## Done: fixture-name consolidation (the one justified piece)

The genuine remaining concern — "the codebase must not end with three unit
conventions" — is real but small. Across the test suite the `unitless*` (c=1)
closures are:
- `unitlessMinkowskiGFn` / `unitlessMinkowskiGInverseFn` in the shared fixture
  layer (`tests/fixtures/minkowski.ts`), imported by
  `tests/dimensional/minkowski-curvature.test.ts` (aliased on import).
- `unitlessDeSitterGFn` / `unitlessDeSitterGInverseFn` /
  `unitlessSchwarzschildGFn` / `unitlessSchwarzschildGInverseFn` — test-LOCAL
  closures in `tests/dimensional/bianchi-residual.test.ts` (Adam YELLOW: these
  carry the same `unitless` name and must be scoped in, or the consolidation is
  half-done).

All of these are flat/geometrized (G=c=1, no c²) — "unitless" is just an older
NAME for the geometrized convention. So consolidate the NAME everywhere it
appears so the test suite presents exactly two conventions — **SI** and
**geometrized** — with consistent naming:
- HARD rename `unitless*` → `geometrized*` (these are test-only, not shipped, and
  have few consumers — a hard rename is cleaner than carrying `@deprecated`
  aliases, which would leave dead surface to sweep later; Adam's lean).
- Update the one shared-fixture importer + the bianchi-residual call sites +
  docstrings.

Test-fixture-only; no `src/` change, no public-surface change, no behavior change
(the closures are byte-identical — only their names change).

## Adam verdict: GREEN on the DECLINE (strengthened); YELLOW on scope → folded

Adam adversarially challenged the decline on all five axes and it held — more
robustly than this note first argued. He reproduced the Kretschmann comparison
apples-to-apples (same N, engine, r-grid, FD step) and EXTENDED it: the
geometrized far-field error DIVERGES with r (k=100: 3.96e-6; k=500: 2.38e-2;
k=1000: 0.40 — 40% error — vs SI staying ~1e-7) — a measured precision
CATASTROPHE intrinsic to the geometrized chart's signal-to-baseline ratio, not a
fixable FD-step artifact (the step is coordinate-keyed, identical in both
charts). He confirmed the dynamical consumers (GL4, perihelion, eikonal) use
ANALYTIC closures, not FD, so the precision argument is inapplicable there; and
that `E = −p_t ≈ 9e16` is conserved BIT-EXACT over 2 Mercury orbits (cyclic-
coordinate momentum the symplectic update never touches), so there is no
long-integration benefit to geometrizing it. And the pipeline is convention-
agnostic (one internal pipeline + boundary adapters), so there is no dual-path
maintenance cost to eliminate. The decline is correct. Folded his YELLOW: the
consolidation now scopes in the bianchi-residual `unitless*` locals.
