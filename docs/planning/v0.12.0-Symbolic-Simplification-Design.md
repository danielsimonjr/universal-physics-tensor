# v0.12.0 — Symbolic Simplification via MathTS (Design Note)

Optional supplement to symbolic composition: fold the UNSIMPLIFIED composed
`ExprNode` (CT-1's `k_B·(ℏc³/8πG·mass·k_B)·ln2`) into its canonical reduced
form (`ℏc³·ln2/(8πG·mass)`), using `@danielsimonjr/mathts-functions`'
`simplify` — the same optional peer the Path-A formula parser already loads.
This removes the "no algebraic simplification" caveat the symbolic-composition
feature shipped with.

## Grounded facts (2026-06-15)

- `mathts-functions` (assembled mathjs-style instance) exposes `parse`,
  `simplify`, `derivative`, `evaluate` (runtime-verified). Smoke test:
  `simplify(parse('k_B*(h*c^3/(p*k_B))*l'))` → `h * c^3 * l / p` — it cancels
  `k_B`, exactly the CT-1 reduction.
- It is an OPTIONAL peer (the formula registry already loads it dynamically
  and falls back to Path B when absent). So simplification MUST degrade
  gracefully: no MathTS ⇒ return the input unchanged.
- `mathts-core` also ships a units engine (`Dimensions`, `BASE_UNITS`,
  `DERIVED_UNITS`, `DimensionMismatchError`) and exact arithmetic
  (`BigNumber`, `Fraction`, `Complex`). OUT OF SCOPE here (UPT's ℤ⁷
  `Dimension` is bespoke and load-bearing) but noted for the record.

## The round-trip (and why it's not a string round-trip)

`simplify` takes a MathTS AST. The naive path — render `ExprNode` → string →
`parse` → `simplify` → walk back — BREAKS because UPT leaf names are not all
valid mathjs identifiers: `'8pi'` parses as `8*pi`, `'schwarzschild-radius'`
as subtraction, `'2'`/`'3'` as numbers. So we GENSYM every non-exponent leaf
to a safe identifier (`g0`, `g1`, …) and track `gensym → { name, dim }`:

```
ExprNode --(gensym render)--> mathjs string --parse--> Node
        --simplify--> Node --(walk, un-gensym, re-attach dim)--> ExprNode
```

Gensym rules (the crux):
- **Exponent position** (arg[1] of `^`): render as the LITERAL number
  (`c^3` → `g2 ^ 3`). ExprNode's `^` requires a numeric-literal exponent, and
  symbolic exponents confuse `simplify`.
- **All other leaves** — physical constants (`k_B`, `hbar`, `c`, `G`),
  named constants (`8pi`, `4pi`, `ln2`), AND source quantities (`mass`,
  `temperature`, `schwarzschild-radius`): gensym to a SYMBOL. Keeping
  constants symbolic means `simplify` does pure ALGEBRAIC cancellation
  (`k_B/k_B → 1`) and never numerically evaluates `8π`/`ln2` — the output
  stays the readable `ℏc³ln2/(8πGM)`, not `…/(25.13·…)`.
- **Bare numeric-literal leaves** that are NOT exponents (the `2` in
  `2·G·mass`): render as the literal number; `simplify` may fold pure-numeric
  subexpressions (fine).

Walk-back handles `ConstantNode` → numeric-literal `sym`, gensym `SymbolNode`
→ original `sym(name, dim)`, `OperatorNode(+ - * / ^)`, and unary minus;
`^`'s exponent `ConstantNode` becomes a numeric-literal exponent symbol. Any
other node kind (`FunctionNode`, etc.) ⇒ the simplifier gives up and returns
the input unchanged (graceful — simplification is best-effort).

## The safety guards (load-bearing — simplify is a black box)

A CAS rewrite that is algebraically wrong, or a walk-back bug, would silently
corrupt the expression. Two guards, REUSING the symbolic-composition machinery,
make adoption safe:

1. **Dimensional**: `validate(simplified).inferredDimension` must `equals` the
   original's inferred dimension. (A rewrite that changes dimension is rejected.)
2. **Numeric drift**: `evalExpr(simplified, probe)` must match
   `evalExpr(original, probe)` at relative tol 1e-9 over several probes (the
   SAME guard the symbolic forms already use; reuse the helper).

If MathTS is PRESENT but the simplified form fails either guard ⇒ throw
`SimplificationError` (a real bug, surface it). If MathTS is ABSENT ⇒ return the
input unchanged with `simplified: false` (expected fallback). This is the
Path-A/Path-B contract: absent peer degrades; present-but-wrong errors.

## API

`src/composition/expr-simplify.ts` (internal helpers; the Observable wrapper is
public-surface-neutral — it returns the existing `Observable` type):

- `simplifyExpr(expr: ExprNode): Promise<{ expr: ExprNode; simplified: boolean }>`
  — dynamic-imports `mathts-functions` (cached, like `formula-registry`),
  runs the round-trip + guards, returns `{simplified:false, expr}` unchanged
  when the peer is absent or the result is a no-op. Async because the peer load
  is async (mirrors `getFormulaParser`).
- `simplifyObservable(obs: Observable): Promise<Observable>` — returns a new
  `Observable` with the simplified `expr` and recomputed `leaves` (constants
  excluded), same `name`/`symbol`/`dim`/strict-`evaluate` contract.

`composeSymbolic` stays SYNC and unchanged (returns the unsimplified
Observable); simplification is a separate opt-in async step. No public-surface
additions beyond possibly re-exporting `simplifyObservable` (decided post-vet;
lean = keep internal, surface via CLI `upt symbolic --simplify`).

## Tests

- CT-1 round-trip: `simplifyObservable(composeSymbolic(be42Edge, be16Edge))`
  drops `k_B` (leaf/structure check) AND numeric value unchanged AND dim still
  `[energy]`.
- CT-1b likewise (the `r_s` substitution form reduces).
- Fallback: with the peer un-loadable (inject a stub), `simplifyExpr` returns
  `{simplified:false}` and the input expr verbatim.
- Guard: a deliberately-corrupted "simplified" result (injected) is rejected.
- Idempotence: simplifying an already-simple form (be-16) is a safe no-op.
- Gensym safety: a leaf named `'schwarzschild-radius'`/`'8pi'` round-trips
  without mathjs mis-parsing.

## Adam vet — r2 revisions applied

Adam verdict: YELLOW. Binding fixes:

- **(CRITICAL-1) Pin the `simplify`-output node API; verify in-repo.** Runtime
  probe confirms the mathjs node shape the walk-back consumes:
  `OperatorNode` (`.type`, `.op` ∈ `+ - * / ^`, `.args[]`), `SymbolNode`
  (`.name`), `ConstantNode` (`.value:number`). Verified:
  `simplify(parse('g0*(g1*g2^3/(g3*g0))*g4'))` → `g1*g2^3*g4/g3` (g0 cancels;
  `c^3` SURVIVES as `OperatorNode('^', [Symbol, Constant(3)])`). The ambient
  `mathts-functions.ambient.d.ts` is extended to declare `simplify` + the node
  shape. A `simplify`-specific smoke probe (mirroring `formula-registry`'s
  `SMOKE_EXPR`/`detect`) gates trust: a peer with `parse` but no/broken
  `simplify` falls back to "return input unchanged".
- **(CRITICAL-2) Probe synthesis is specified.** The numeric-drift guard
  synthesizes values for the NON-constant free leaves from a fixed list of
  distinct, mutually-incommensurate positive reals
  (`[2.3, 3.7, 5.1, 7.9, 11.3, 13.1, …]`, one per leaf, varied across ≥3
  probe sets by small multipliers) — chosen to avoid zero denominators and
  accidental cancellation. Constants resolve from `CONSTANTS`. The guard
  compares `evalExpr(original, probe)` vs `evalExpr(simplified, probe)` on the
  SAME probe at rel tol 1e-9. If `evalExpr` throws on a probe (non-finite —
  e.g. a near-zero denominator), that probe is SKIPPED (probe-selection issue),
  NOT a `SimplificationError`; ≥2 finite probes must agree. (There is no
  pre-existing exported drift helper — the symbolic test's `relClose` is inline;
  this module ships its own.)
- **(HIGH-1) Walk-back is integer-and-scalar strict.** A `^` whose exponent
  `ConstantNode.value` is non-integer, or any `FunctionNode`/`sqrt`/unsupported
  node kind, makes the walk-back ABORT → graceful no-op (return the original
  expr, `simplified:false`). This protects UPT's ℤ⁷ integer-exponent model. A
  test pins that BE-42's `c^3` survives the round-trip AS `c^3`.
- **(HIGH-2) Structural subset guard (independent of the gensym table).**
  `collectSymbols(simplified) ⊆ collectSymbols(original)` — cancellation may
  only REMOVE leaves, never invent one. This is the only guard that catches a
  gensym-misattribution that is coincidentally dim- and numerically-consistent
  on the probes. (Checked in gensym space: the simplified tree's `SymbolNode`
  names must be a subset of the gensym set issued for the original.)
- **(HIGH-3) `simplifyObservable` RECONSTRUCTS the Observable.** It returns a
  fresh object literal (new strict `evaluate` closure over the simplified
  `expr` + recomputed `leaves`), NOT a spread over the stale closure — a spread
  would silently evaluate the old unsimplified expr.
- **(MEDIUM-1/2) Mirror `formula-registry` fully.** Module-level `Promise`
  cache of the loaded+smoke-tested peer; `quietly()` wrapping to suppress the
  WASM-absent stderr noise (Open Q4 reversed — suppress, do NOT accept);
  explicit fallback for MathTS-present-but-`simplify`-missing/broken.

## Eve vet — r3 revisions applied

Eve verdict: YELLOW (no RED for the four authored forms, but EVE-A would
corrupt the first general compound-exponent expr — the feature's point). All
grep-verified. Binding:

- **(EVE-A, HIGH) Fully-parenthesized gensym renderer.** The CLI's
  `exprToString` (`bin/upt.mjs`) does NOT parenthesize a `^` base
  (`(a/b)^2` → `a/b^2`, silent corruption). The round-trip renderer is NEW and
  wraps EVERY non-leaf in parentheses (`((g0)*(g1))^3`), using ASCII
  `+ - * / ^` — redundant parens parse fine and eliminate ALL precedence
  ambiguity. A test exercises a compound base under `^`.
- **(EVE-C, MEDIUM) `<2 finite probes` ⇒ fall back, never vacuous-pass.** If
  fewer than 2 probe sets evaluate finite on BOTH original and simplified,
  the numeric guard cannot verify ⇒ return `{simplified:false}` (the
  unsimplified original). Silent-pass is forbidden. (The dim guard is
  necessary-not-sufficient — EVE-D — so the numeric guard is load-bearing.)
- **(EVE-B, MEDIUM) Subset guard excludes numeric literals.** `collectSymbols`
  (`compose-symbolic.ts`) includes `'2'`/`'3'`; the subset check filters them
  (as `freeLeaves` does) and runs in gensym space — only non-numeric symbol
  names count, so a folded coefficient (`6`) never false-rejects.
- **(EVE-E, LOW) `symbolicCmd` becomes async** for `--simplify`; the zero-arg
  `upt` demo does not call it (it runs `explain`+`priority`), so no demo
  regression. `composeSymbolic` stays sync.
- **(EVE-F, LOW) Idempotence asserted on leaf-set + value + dim**, NOT AST
  structure (`simplify` may reassociate `k_B·T·ln2`).

## Open questions for the Adam+Eve vet
