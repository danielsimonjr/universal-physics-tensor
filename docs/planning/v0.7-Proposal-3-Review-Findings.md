## Eve findings

**Eve-R1 — `compose` factory silently gains a `config` parameter not in the proposals doc.**
Proposals doc §4.2 line 299 sketches `compose(L, B, E): UniversalTensor` with NO config arg (verified by re-reading the doc). The design's Task 2.2 silently expands it to `compose(L, B, E, config: TensorConfig)`. The expansion is *necessary* (`UniversalTensor`'s constructor at `src/core/tensor.ts:38-49` requires `rank`, `scales`, `forces`), but neither the proposals doc nor the design discusses this gap. Adam-V10 ratified the expanded signature without flagging that it diverges from the source. Severity: MEDIUM. Remediation: design must note the proposals-doc divergence explicitly; alternatively drop `compose` from Phase 2 (it is named-attributed to Proposal 2 in the design's own Decision #4 prose) and defer.

**Eve-R2 — Internal consumers of the deprecated interfaces DO exist; Risk #2's "UNVERIFIED" is wrong.**
Grep confirms five in-repo import sites for the soon-to-be-`@deprecated` names: `src/core/tensor.ts:14-22`, `src/index.ts:29-31`, `examples/basic-usage.ts:12`, `tests/tensor.test.ts:3`, plus `tests/bridges/_helpers.ts:27` (which imports `BridgeEquationEntry` — different type, false-positive). Adam-V12 treated the consumer base as unknown; it is known and includes the shipping `examples/basic-usage.ts`. TypeScript surfaces `@deprecated` as a tsserver squiggle and emits `deprecated: true` into `.d.ts`. Downstream users copying `examples/basic-usage.ts` would see the warning. Severity: MEDIUM. Remediation: Phase 0 must enumerate these consumers and either migrate them in-sprint OR defer `@deprecated` markers to a later release.

**Eve-R3 — `confidenceToStatus` adapter is lossy AND can contradict the curated catalog.**
Task 1.3 picks `n>=0.8 → 'established'`, `n>=0.4 → 'speculative'`. Bridges in the catalog have BOTH `confidence: number` (`src/core/types.ts:143`) and `status: BridgeEquationStatus` (`src/bridges/index.ts:42-46`), set independently today. A bridge with catalog-curated `status: 'established'` but `confidence: 0.7` round-trips through `confidenceToStatus` to `'speculative'` — producing a label that directly contradicts a curated field. Severity: HIGH. Remediation: drop the adapter (the design's Risk #1 lists this as an alternative — adopt it). Force each cell-construction call site to pass the string explicitly.

**Eve-R4 — Phase 0 baseline-gate omits three measurements.**
(a) The snapshot file `tests/api/__snapshots__/public-surface.test.ts.snap` exists and pins 70 runtime exports — Phase 0 must record this as a hard baseline, not the conditional hedge in Adam-V11. (b) No `@public` JSDoc plan for new `Cell` types — the convention IS established (`src/index.ts:116`, `src/index.ts:190`, `src/numerical/index.ts:17+` show `@public` tagging discipline). Phase 1 Task 1.2 should tag each new variant. (c) Phase 0 Task 0.1 records only `passed-count`, not file-count or test names; "≥ baseline" allows a silent test deletion. Severity: LOW-MEDIUM. Remediation: amend Phase 0 with a `@public`-convention item and a per-suite ID lock.

**Eve-R5 — Goal #3 contradicts Decision #4: `addCell` "replaces" but `addLaw`/`addBridge`/`addEmergence` stay un-deprecated.**
Goal #3 states `addCell` "replaces the three separate `addLaw` / `addBridge` / `addEmergence` call sites in consumers that want kind-agnostic ingestion." Decision #4 keeps all three typed methods public without `@deprecated`. The result: four entry points, no compile-time guidance toward `addCell`. Future readers face an asymmetric API where the type-only interfaces are deprecated but the methods that consume them are not. Severity: LOW. Remediation: reframe Decision #4 as "`addCell` is the kind-erased convenience; the three typed methods remain the canonical typed entry points," OR add `@deprecated` to the methods too. Pick one consistent direction.

**Eve-R6 — Public-surface NET addition of 5 exports runs against v0.6.1 minimize discipline.**
Phase 2 Task 2.3 adds `Cell`, `LawCell`, `BridgeCell`, `EmergenceCell`, `compose` (5 new exports). v0.6.1 just removed 24 internal symbols from the public surface. Without `@public` discipline (see Eve-R4), `LawCell`/`BridgeCell`/`EmergenceCell` may be over-exposed — consumers can narrow `Cell` via `switch (c.kind)` without naming the variant types directly. Severity: LOW-MEDIUM. Remediation: Phase 2 Task 2.3 — re-export `Cell` (union) only, plus `compose`; keep variant interfaces internal-accessible-only.

**Eve-R7 — Existing test fixtures will NOT trivially become `Cell` instances.**
Goal #5 promises "trivially-updated fixture types." Fixtures at `tests/tensor.test.ts:5,15,50,205,228` and `examples/basic-usage.ts:23,37,51` use `confidence: number` (e.g. `0.95`) — not assignable to `LawCell`. Phase 1's TDD cycles will need fresh fixtures rather than reuse. Severity: LOW. Remediation: clarify in Phase 1 that no existing literal is touched; new tests use new fixtures.

**Eve-R8 — No serialization / equality story for `Cell`.**
`grep` for `toJSON`/`serialize`/`JSON.stringify` in `src/core/tensor.ts` returns no public serialization layer. Proposal 2 needs `Map<TupleKey, Cell>` — implies `Cell` equality/hashing. Proposal 3 establishes neither. Severity: LOW (speculative — depends on Proposal 2 sequencing). Remediation: `todo.md` carry-forward item to revisit `Cell` identity when Proposal 2 is drafted.

**Eve-R9 — Tag-decision posture lacks a stall protocol.**
"Do not treat an alpha as the stable v0.7.0 milestone" is posture, not protocol. Proposal 1 is 2-3 weeks, Proposal 3 is 1 week — no decision rule for "Proposal 1 stalls; ship Proposal 3 alone or wait?" Severity: LOW. Remediation: pin an explicit branch — e.g., "if Proposal 1 incomplete at sprint-end, Proposal 3 ships as `v0.6.2` (additive minor); v0.7.0 awaits the rollup."
