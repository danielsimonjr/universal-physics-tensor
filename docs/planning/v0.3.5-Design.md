## 1. Context

UPT v0.3.1 ([commit `da74737`, tag `v0.3.1`, 2026-05-13](https://github.com/danielsimonjr/universal-physics-tensor/releases/tag/v0.3.1)) closed the v0.3.x metric-layer line: `metric-tensor`, `kronecker-delta`, and `tensor-partial-derivative` AST nodes plus `raise()`/`lower()` helpers with internal alpha-conversion, then three audit-driven patch fixes. The catalog stands at 1,293 passing tests / 1,300 total (7 todo), 92 files. Everything in v0.3.x so far is **symbolic**: the validator inspects AST structure and infers dimensions, but nothing computes a concrete numerical value.

v0.3.5 adds the **numerical-contraction backend**: the machinery that takes a validated UPT AST plus concrete numerical inputs and produces actual numbers. This is the load-bearing validation of the v0.3.0 design — if there is a hidden schema issue in how `metric-tensor` or `tensor-partial-derivative` lowers to numerical operations, v0.3.5 surfaces it before v0.4.0 (Christoffel symbols + covariant derivative) builds on top.

Per the TensorJS roadmap (§12 of v0.2.0-Design.md): v0.3.5 introduces the numerical backend; v0.4.0 adds the connection layer; v0.5.0+ adds the curvature layer + the Faraday-cascade BREAKING refactor + threejs visualization.

## 2. Scope

### In scope

1. **`src/numerical/` module**: new top-level module exposing `evaluateNumerical(node, inputs): Promise<NumericalResult>`, `evaluateNumericalRaw(...)`, `evaluateMetricInverse(g, gInverse)`, and the lowering dispatcher. Parallel to `src/dimensional/` (analyzer) and `src/bridges/` (equations).
2. **Hybrid numerical backend**: TF.js (`@tensorflow/tfjs-node`) as the numerical-compute engine for tensor operations; mathjs (already a UPT dependency) for scalar/symbolic operations. UPT dispatches at lowering time.
3. **Three-way numerical partial derivative**: `tensor-symbol` gains an optional `numericalForm?: 'symbolic' | 'tfjs-fn' | 'grid'` field. `∂_μ T` is computed via `mathjs.derivative()` (symbolic closed-form), `tf.grad()`/`tf.valueAndGrad()` (autograd), or centered finite-difference (grid), dispatched by that field.
4. **`Violation.severity` field**: optional `severity?: 'error' | 'warning'` on the `Violation` interface, defaulting to `'error'`. Zero v0.3.0 migration cost.
5. **`InverseMetricInconsistencyWarning`**: deferred from v0.3.0 (Design §13 Q2). Fires at both `validate()` (symbolic structural check) and `evaluateNumerical()` (numerical `‖g⁻¹g − I‖` check). Deduplicated via hash.
6. **BE-37 numerical eikonal evaluator**: lower `BE37_EIKONAL_LHS` with concrete weak-field Schwarzschild components, numerically integrate the Shapiro delay Δt along a null ray, cross-check against the existing closed-form `evaluateShapiroDelay()` to ±10⁻⁹ relative error. End-to-end smoke test.
7. **API-stability pass**: extend `tests/bridges/public-api-stability.test.ts` to snapshot the v0.3.0 metric surface + the new `src/numerical/` surface; `@public` / `@internal` JSDoc tags on every export.

### Explicitly out of scope (deferred to later versions)

- **Browser float32 fallback / precision-mode toggle**: v0.3.5 pins float64 (tfjs-node). v0.5.0+ threejs-visualization work introduces the browser-portable float32 mode and the `setPrecision()` config knob.
- **Christoffel symbols, covariant derivative**: v0.4.0 ("connection layer").
- **Riemann / Ricci / Bianchi curvature, Einstein field-equation solvers**: v0.5.0+.
- **Contraction-path optimization** (NP-hard einsum ordering): v0.3.5 ships a naive left-to-right contraction order. Path optimization is a v0.4.0+ performance concern.
- **GPU / WebGL backend**: v0.3.5 targets tfjs-node (CPU + WASM). GPU backend is a v0.5.0+ performance concern, gated behind the precision-mode work.
- **Grid-scale PDE solving** (BSSN formalism): v0.5.0+. v0.3.5's `'grid'` `numericalForm` ships the `GridField` data structure and finite-difference `∂_μ`, but not time-evolution solvers.

## 3. Approach: hybrid backend, operand-aware dispatch, async-all-the-way

The pattern adopted from v0.3.0 holds: minimal, well-bounded units; spec the contract; test in layers. The genuinely new architectural surface:

- **Two compute engines, one dispatcher.** mathjs already lives in UPT for the dimensional algebra layer. TF.js is the new piece — it owns einsum, matrix multiplication, transposition, reshape, and autograd. The `src/numerical/` lowering dispatcher decides, per sub-expression, which engine evaluates it.
- **Dispatch is operation-based plus operand-contagion.** (Refined during pass-2 adversarial review — see §13.) An operation lowers to TF.js if **(a)** it is einsum / matrix-multiply / transpose / reshape / rank-altering, **OR (b)** any of its operands is already TF.js-backed. Otherwise it stays in mathjs. The lowering pass tags every intermediate result with its backend. Rank-0 mathjs-backed operands are not contagious (so `transpose(scalar)` stays in mathjs as an identity).
- **Async-all-the-way.** TF.js's `.data()` / `.array()` return Promises; the synchronous `.dataSync()` only works on the CPU backend. `evaluateNumerical()` is `async`; mathjs scalar work runs synchronously inside the async function, then awaits TF.js results.

## 4. AST extension

### Existing node types (v0.3.1, unchanged shapes)

The numerical backend reads validated v0.3.1 ASTs. No node *shapes* change in v0.3.5 except one additive optional field:

```typescript
// src/dimensional/tensor.ts — TensorSymbolNode gains one optional field
| { kind: 'tensor-symbol';
    name: string;
    indices: ReadonlyArray<TensorIndex>;
    dim: Dimension;
    role?: Role;
    numericalForm?: 'symbolic' | 'tfjs-fn' | 'grid';   // NEW in v0.3.5; defaults 'symbolic'
  }
```

`numericalForm` defaults to `'symbolic'` when omitted — so every v0.3.0/v0.3.1 AST is a valid v0.3.5 AST with no change. The field tells the numerical pderiv dispatcher which differentiation strategy to use for that tensor-symbol when it appears as the `of` operand of a `tensor-partial-derivative`.

### `Violation` interface extension (`src/dimensional/validator.ts`)

```typescript
export interface Violation {
  location: string;
  expected: Dimension;
  actual: Dimension;
  note: string;
  severity?: 'error' | 'warning';   // NEW in v0.3.5; absent ⇒ 'error'
}
```

`ValidationResult.ok` becomes `violations.every(v => (v.severity ?? 'error') !== 'error') ... ` — precisely: `ok = !violations.some(v => (v.severity ?? 'error') === 'error') && dim !== null`. Warnings do not fail validation.

## 5. `src/numerical/` module architecture

### File structure

```
src/numerical/
  index.ts                  — public surface: evaluateNumerical, evaluateNumericalRaw,
                              evaluateMetricInverse, types. Subpath export.
  dispatcher.ts             — operation-based + operand-contagion lowering dispatch;
                              backend-tagging of intermediate results.
  mathjs-backend.ts         — scalar/symbolic lowering: ExprNode scalar ops → mathjs.
  tfjs-backend.ts           — tensor lowering: einsum, matMul, transpose, reshape;
                              metric-tensor / kronecker-delta / tensor-symbol → tf.Tensor.
  pderiv.ts                 — three-way numerical partial derivative dispatch
                              (symbolic / tfjs-fn / grid).
  grid-field.ts             — GridField data structure + finite-difference stencils.
  null-ray-integrator.ts    — RK4 affine-parameterized null-geodesic integrator
                              (used by the BE-37 evaluator).
  tfjs-loader.ts            — runtime-detection dynamic import of @tensorflow/tfjs-node;
                              throws a clear install-instruction error if absent.
  errors.ts                 — NumericalBackendError (UPTError subclass) + wrappers
                              that re-tag mathjs / TF.js errors.
```

### Public surface (`src/numerical/index.ts`)

```typescript
/** Plain-JS numerical result. `value` is a number for rank-0, nested arrays for rank ≥1. */
export interface NumericalResult {
  readonly value: number | NestedArray;
  readonly dim: Dimension;
  readonly freeIndices: ReadonlyMap<string, { upper: number; lower: number }>;
  readonly warnings: ReadonlyArray<Violation>;   // severity === 'warning' violations surfaced numerically
}

/** Live-tensor result for chaining workloads (geodesic integration, BSSN evolution). */
export interface NumericalRawResult {
  readonly value: unknown;          // tf.Tensor — typed as `unknown` so symbolic-only
                                    //   bundles don't pull TF.js types (see §14.5)
  readonly dim: Dimension;
  readonly freeIndices: ReadonlyMap<string, { upper: number; lower: number }>;
  readonly warnings: ReadonlyArray<Violation>;
  dispose(): void;                  // caller owns the lifecycle for raw results
}

/** Evaluate a validated AST to plain JS. Tensor intermediates are tf.tidy()-wrapped;
 *  the result tensor is extracted to JS and disposed. Zero leak risk for callers. */
export function evaluateNumerical(
  node: ExprNode,
  inputs: NumericalInputs,
): Promise<NumericalResult>;

/** Evaluate to a live tf.Tensor for chaining. Caller MUST call result.dispose(). */
export function evaluateNumericalRaw(
  node: ExprNode,
  inputs: NumericalInputs,
): Promise<NumericalRawResult>;

/** Numerically check g⁻¹g ≈ I. Returns the residual norm + a warning-severity
 *  Violation if it exceeds tolerance. */
export function evaluateMetricInverse(
  g: MetricTensorNode,
  gInverse: MetricTensorNode,
  inputs: NumericalInputs,
  tolerance?: number,               // default 1e-10 in float64
): Promise<{ residualNorm: number; warning?: Violation }>;
```

### `NumericalInputs` shape

```typescript
export interface NumericalInputs {
  /** Concrete component values for each tensor-symbol / metric-tensor by name.
   *  Shape must match the node's rank + index dimensionality. */
  readonly tensors: ReadonlyMap<string, NestedArray | number>;
  /** For 'tfjs-fn' numericalForm tensor-symbols: a SYNCHRONOUS function
   *  (coords: tf.Tensor) => tf.Tensor. tf.grad() requires sync. (§13 — Adam's catch.) */
  readonly fields?: ReadonlyMap<string, (coords: unknown) => unknown>;
  /** For 'grid' numericalForm tensor-symbols. */
  readonly grids?: ReadonlyMap<string, GridField>;
  /** Coordinate values for partial-derivative evaluation. */
  readonly coords?: ReadonlyMap<string, number>;
}
```

### `GridField` (`src/numerical/grid-field.ts`)

Pass-2 (Eve) flagged the `'grid'` `numericalForm` as underspecified. Locked shape:

```typescript
export interface GridField {
  /** Per-axis sample count, e.g. [64, 64, 64] for a 3D spatial grid. */
  readonly shape: ReadonlyArray<number>;
  /** Per-axis physical spacing Δx for the finite-difference stencil. */
  readonly spacing: ReadonlyArray<number>;
  /** The sampled field values, lowered to a tf.Tensor of `shape`. Typed `unknown`
   *  to keep TF.js out of symbolic-only bundles (§14.5). */
  readonly data: unknown;
  /** Boundary policy for stencils at the grid edge. v0.3.5 ships `'clamp'` and
   *  `'periodic'`; `'ghost'` (ghost-cell padding for BSSN-style PDE solvers) is
   *  deferred to v0.5.0 when the grid-scale evolution work lands. */
  readonly boundary: 'clamp' | 'periodic';
}
```

## 6. Numerical partial-derivative dispatch (`src/numerical/pderiv.ts`)

When the dispatcher hits a `tensor-partial-derivative` node, it reads the `of` operand's `numericalForm` (defaulting `'symbolic'`):

| `numericalForm` | Strategy | Mechanism | Notes |
|---|---|---|---|
| `'symbolic'` | Symbolic differentiation | `mathjs.derivative()` on the closed-form expression | Exact, no truncation error. The v0.3.0/v0.3.1 default — every existing AST. |
| `'tfjs-fn'` | Reverse-mode autograd | `tf.grad()` / `tf.valueAndGrad()` | Machine-precision. The user-supplied field function MUST be synchronous `(coords: tf.Tensor) => tf.Tensor` — tf.grad() does not accept async (§13). |
| `'grid'` | Centered finite-difference | O(h²) stencil over the `GridField`, step from `GridField.spacing`, edges per `GridField.boundary` | The h is the grid spacing; not separately tunable. |

The dispatcher itself stays small: it reads `numericalForm`, routes to one of three functions in `pderiv.ts`, and tags the result's backend (symbolic → mathjs-backed; tfjs-fn / grid → TF.js-backed) so operand-contagion (§3) works downstream.

## 7. `InverseMetricInconsistencyWarning` (`src/numerical/` + `src/dimensional/validator.ts`)

Fires at **two** points (Decision 10):

- **Symbolic, at `validate()`**: when both a both-lower `metric-tensor` and a both-upper `metric-tensor` are reachable in the AST, the validator checks that their `tensor-product` has the structural shape of `δ^μ_λ` (rank-2, mixed variance, free indices match). A structural failure pushes a `severity: 'warning'` `Violation`. (This passes vacuously for most well-formed metrics — it catches obvious user errors like a wrong-rank inverse.)
- **Numerical, at `evaluateNumerical()` / `evaluateMetricInverse()`**: lower both metrics to `tf.Tensor`, compute `‖matMul(gInverse, g) − eye(N)‖_∞`, and if it exceeds tolerance (default `1e-10` in float64) push a `severity: 'warning'` `Violation`.

**Deduplication** (Eve's pass-1 concern): warnings are keyed on a hash of `(g.name, gInverse.name, callsite)` and emitted at most once per `validate()` / `evaluateNumerical()` call, so a contraction inside a loop does not spam.

## 8. BE-37 numerical eikonal evaluator (`src/numerical/null-ray-integrator.ts` + `src/bridges/equations/be-37-shapiro-delay.ts`)

The end-to-end smoke test. Steps:

1. Lower `BE37_EIKONAL_LHS` (`g^μν (∂_μ S)(∂_ν S)`) with concrete **weak-field Schwarzschild** `g^μν` components supplied via `NumericalInputs`.
2. Integrate the Shapiro delay Δt along a null ray using the **RK4 affine-parameterized null-geodesic integrator** (`null-ray-integrator.ts`). Fixed-step RK4; step count chosen so the cross-check below holds. (Pass-2 — both reasoners flagged the integrator as underspecified; the algorithm is locked here.)
3. Cross-check the integrated Δt against the existing closed-form `evaluateShapiroDelay()` (the v0.3.0 scalar form, retained for exactly this purpose).

**Acceptance criterion:** integrated Δt agrees with closed-form `evaluateShapiroDelay()` to **±10⁻⁹ relative error** — comfortable in float64, well inside the ~10⁻⁵ Cassini experimental precision the bridge is grounded in.

The null-ray integrator is a genuine piece of implementation work — it gets its own sequencing phase (§10 phase 8), not folded into a contraction task.

## 13. Risks and open questions

### Risks both reasoners flagged (pass-1 and pass-2)

- **Backend contagion (pass-2, Adam, CRITICAL — resolved).** Operation-based dispatch alone is insufficient: `pderiv(tfjs-tensor) + scalar` would route `+` to mathjs, which cannot add a `tf.Tensor`. **Resolved** by refining Decision 4 to operation-based **plus operand-contagion** (§3): any operation with a TF.js-backed operand goes to TF.js; the lowering pass tags every intermediate's backend. This is the load-bearing correctness primitive of the whole module — phase 3 must implement and test it thoroughly before phases 4-5 build on it.
- **Return-tensor lifecycle (pass-2, Eve, CRITICAL — resolved).** `tf.tidy()` disposes intermediates but not the returned result. **Resolved** by Decision 16: `evaluateNumerical()` extracts to plain JS and disposes the tensor (zero leak risk); `evaluateNumericalRaw()` returns a live tensor + `.dispose()` for chaining workloads, caller-owned.
- **Precision boundary (pass-1, Eve).** mathjs `Number` and TF.js `float64` are both IEEE 754 double — no precision cliff at the boundary for v0.3.5. The cliff reappears at v0.5.0 when the browser float32 mode lands; documented as out-of-scope here.
- **Null-ray integrator scope (pass-2, both).** The BE-37 acceptance criterion requires a real null-geodesic integrator — not just einsum. Locked as RK4 affine-parameterized (§8), with its own sequencing phase (#8). If the ±10⁻⁹ criterion proves hard to hit at reasonable step counts, the fallback is to relax to ±10⁻⁷ (still inside Cassini precision) — but only with an explicit note in the CHANGELOG.
- **ArrayBuffer churn at the mathjs↔TF.js boundary (pass-1, Eve).** Each cross-boundary conversion allocates. Noted as a known performance characteristic; v0.3.5 does not optimize it. If profiling during phase 10 (BE-37 integration, which loops the integrator) shows it dominates, an internal conversion cache is a fast follow — but not v0.3.5 scope.

### Open questions for written-spec review

1. **`evaluateMetricInverse` tolerance default.** §5 sets `1e-10` in float64. Is that the right default, or should it scale with the metric's condition number? Implementer should confirm during phase 9; a fixed `1e-10` is the v0.3.5 baseline.
2. **`tfjs-fn` field function signature.** §6 locks it as synchronous `(coords: tf.Tensor) => tf.Tensor`. If a future use case needs async field functions, that is a v0.4.0+ extension — `tf.grad()` fundamentally requires sync, so an async variant would need a different mechanism (pre-sampling to a grid).
3. **`GridField.boundary` policies (resolved).** v0.3.5 ships `'clamp'` and `'periodic'` only. The `'ghost'` policy (ghost-cell padding for BSSN-style PDE solvers — needs a ghost-cell width + fill rule) is deferred to v0.5.0 grid-scale evolution work. Locked in §5.
4. **Naive contraction order.** v0.3.5 ships left-to-right einsum contraction (no path optimization). For the small tensors in v0.3.5's scope (4×4 Schwarzschild metrics) this is fine; flagged so v0.4.0 knows path optimization is unstarted.

## 14. Forward-compatibility sanity checks

Building on v0.3.0-Design.md §14:

### 14.1 `numericalForm` field is additive
`tensor-symbol` gains `numericalForm?` as an optional field defaulting to `'symbolic'`. Every v0.3.0/v0.3.1 AST is a valid v0.3.5 AST unchanged. JSON round-trip: the field is a plain string — survives serialization trivially. Add to `tests/dimensional/metric-ast-serialization.test.ts`.

### 14.2 `Violation.severity` field is additive
Optional field defaulting to `'error'`. All v0.3.0/v0.3.1 violation-construction sites are untouched; `ValidationResult.ok` semantics preserved for error-only violation sets. SemVer MINOR.

### 14.3 v0.4.0 covariant-derivative numerical composition
The `tf.grad()` autograd path (§6) is the direct enabler for v0.4.0's covariant derivative `∇_μ V^ν = ∂_μ V^ν + Γ^ν_μλ V^λ`: the Christoffel term is itself a function of metric derivatives, and `tf.grad()` composes through it. The operand-contagion dispatch ensures the Christoffel contraction (`g^λρ ∂_μ g_ρν`) routes to TF.js correctly. v0.4.0's preview `it.todo` tests (in `covariant-derivative-preview.test.ts`) get numerical bodies in v0.4.0.

### 14.4 v0.5.0 Faraday-cascade compatibility
The Faraday mixed-component-dim BREAKING refactor (Part-VIII §VIII.10) touches `metric-tensor.dim` / `tensor-symbol.dim` / `kronecker-delta.dim`. The numerical backend reads `dim` for the result's `NumericalResult.dim` field but does not branch on it for compute — so the v0.5.0 `dim`-shape refactor is contained to the symbolic layer; the numerical module's lowering logic is unaffected. Confirmed: v0.3.5's numerical backend does not couple to the v0.5.0 BREAKING surface.

### 14.5 TF.js type-import isolation
`src/numerical/` uses `import type` for TF.js types and dynamic `import()` for the runtime. A minimal `ITensorLike` interface is shipped in `src/numerical/tfjs-loader.ts` so symbolic-only consumers' bundles do not pull `@tensorflow/tfjs` types. The public `NumericalRawResult.value` is typed `unknown` for the same reason — symbolic-only TypeScript consumers never see a TF.js type. (Pass-2, Eve.)

### 14.6 Browser float32 forward-compat
v0.3.5 pins float64 (tfjs-node). The v0.5.0 browser-portable float32 mode will add a `setPrecision('float32' | 'float64')` config knob. v0.3.5's lowering code reads the dtype from a single module-level constant — so the v0.5.0 config knob is a localized change, not a cross-cutting refactor. No v0.3.5 design decision precludes it.
