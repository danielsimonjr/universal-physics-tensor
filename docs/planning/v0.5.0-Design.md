## 1. Goal

Land the **GR foundations** that v0.4.0 deferred and the bridge-validation precision that v0.4.6 documented but did not enforce. Concretely: (a) ship a symplectic geodesic integrator (Ruth 4th-order) + bisection perihelion finder so the two `it.skip` cross-validation tests from v0.4.0 (BE-52 Mercury Δφ, BE-37 full Shapiro via geodesic) can be **activated** rather than deferred again; (b) ship the curvature layer (`RiemannTensorNode` AST + `ricci()` / `einstein()` / `bianchiResidual()` helpers) so v0.6.0+ Friedmann-flavored cosmology bridges have the infrastructure they need; (c) close the structural-parity gaps surfaced by the v0.5.0 pre-flight bridge-coverage audit (BE-51 + BE-52 sibling structural tests, plus ~5 catalog-only bridges getting tighter physics anchors).

Pure-additive — no breaking changes. Pattern-mirrors v0.4.0 (CovariantDerivativeNode + christoffel helper) one level up.

## 2. Architecture summary

### Four locked architectural decisions

| # | Decision | Chosen | Rationale |
|---|---|---|---|
| 1 | **Scope** | **Maximal v0.5.0**: bridge validation + symplectic + curvature, all three blocks in the same release. | The three blocks share testing infrastructure (Schwarzschild fixture, geodesic integrator) and share the `it.skip` debt-clearance theme — splitting them produces three half-releases with overlapping test surfaces. |
| 2 | **Symplectic algorithm** | **Ruth 4th-order** (Yoshida composition of Verlet, 4 stages per step). | Mercury Δφ_GR ≈ 5.02·10⁻⁷ rad/orbit needs better than 4th-order RK4's energy drift over multi-orbit integration. Ruth-4 preserves the symplectic 2-form exactly (modulo roundoff) → secular energy/angular-momentum drift is bounded, not linear-in-t. Standard textbook choice (Yoshida 1990); coefficients are pinned (§5.3). |
| 3 | **Curvature API** | **Mixed pattern**: `RiemannTensorNode` is a first-class `ExprNode` kind (operator); `ricci(R)`, `einstein(R, g)`, `bianchiResidual(R)` are **helpers** that build composite trees from existing v0.4.0 primitives (CovariantDerivativeNode + raise/lower + tensor-product + contract). | Mirrors v0.4.0's locked precedent (`CovariantDerivativeNode` = node; `christoffel()` = helper). Riemann is the **operator** users write; Ricci/Einstein are *contractions* of Riemann — formulaic, not primitive. Bianchi is a *residual identity*, not an operator. |
| 4 | **Sequencing** | **Bottom-up**: Phase 1 Foundations → Phase 2 Activations → Phase 3 Validation → Phase 4 Release. | Phase 2 activations literally cannot fire without Phase 1 (symplectic + bisection) shipped; Phase 3 bridge-validation needs the activated infrastructure to anchor against. Top-down would invert the dependency graph and force late refactors. |

### Four-phase structure (~25–30 tasks total)

- **Phase 1 — Foundations** (12–15 tasks): Ruth-4 integrator (1a) + bisection perihelion finder (1b) + `RiemannTensorNode` AST/validator/lowering (1c) + `ricci()` (1d) + `einstein()` (1e) + `bianchiResidual()` (1f). Each sub-task is its own implementer+reviewer cycle.
- **Phase 2 — Activations** (3–5 tasks): BE-52 Mercury perihelion `it.skip` → activated (2a); BE-37 full Shapiro `it.skip` → activated (2b); `evaluateBE37CovariantEikonalNumerical` actually returns a non-zero `shapiroDelaySec` (2c).
- **Phase 3 — Bridge validation sweep** (7–8 tasks per bridge-coverage-audit §"Recommended next steps"): BE-51 + BE-52 structural sibling tests (3a-3b); ~5 catalog-only bridges get tighter physics anchors (3c–3g per audit lines 127–135); catalog-level integrity test (3h).
- **Phase 4 — Release** (3 tasks): version bump + CHANGELOG (4a); full suite + `tsc` gate (4b); tag → push → npm publish with `--ignore-scripts` per Windows lesson (4c).

### Phase 1 — Foundations (~12–15 tasks)

#### Task 1a — Ruth 4th-order symplectic integrator

**Files**:
- Create: `src/numerical/ruth4-integrator.ts` (mirrors `geodesic-integrator.ts` shape; ~150–200 LoC).
- Test: `tests/numerical/ruth4-integrator.test.ts` (new).
- Modify: `src/numerical/index.ts` (export `integrateGeodesicRuth4`).

**Key signatures**:
```typescript
export interface Ruth4Options {
  /** Step count (uniform stepping; Ruth-4 has 4 stages per step). */
  readonly steps: number;
  /** Final proper time (or affine parameter for null geodesics). */
  readonly tauMax: number;
  /** Christoffel function: (x: number[]) => Γ^λ_μν as a 4×4×4 nested array. */
  readonly christoffelFn: (x: readonly number[]) => readonly number[][][];
  /** Domain restriction (e.g., r ≥ 3·r_s for Schwarzschild). */
  readonly domainMinRadius?: number;
}
export function integrateGeodesicRuth4(
  initialState: GeodesicState,
  options: Ruth4Options,
): ReadonlyArray<GeodesicSnapshot>;
```

`GeodesicState` and `GeodesicSnapshot` are **reused unchanged** from v0.4.0's `geodesic-integrator.ts` — same 8-dim state vector `[x^μ, dx^μ/dτ]`, same snapshot shape `{ τ, x, dxdτ }`.

**Algorithm** (Yoshida 1990 composition of Störmer-Verlet):
```
Coefficients (verified §5.3):
  w₁ = 1 / (2 − 2^(1/3))
  w₀ = 1 − 2·w₁
  c₁ = c₄ = w₁/2
  c₂ = c₃ = (w₀ + w₁)/2
  d₁ = d₃ = w₁
  d₂ = w₀
  d₄ = 0           (final position update absorbed into next step)

For each step of size h:
  for i in [1,2,3,4]:
    x += cᵢ · h · v                       (drift)
    v += dᵢ · h · acceleration(x)         (kick, dᵢ = 0 skips)
```
Acceleration `a^μ = −Γ^μ_νρ v^ν v^ρ` (geodesic equation). The drift-kick split exploits the natural Hamiltonian form `H = ½ g_μν p^μ p^ν` (kinetic only; "potential" zero — geometry is *in* `Γ`).

**Test approach**:
1. Schwarzschild radial-infall cycloid fixture (already in `tests/fixtures/schwarzschild.ts`, used by v0.4.0 RK4 to 2.1e-16) — Ruth-4 must match cycloid to **≤1e-13 relative** at 5000 steps (one order looser than RK4 because Ruth-4 is symplectic *4th order*, not necessarily *more accurate* per step; the symplecticity matters for long integrations, not single-step accuracy).
2. Energy-conservation test: bound Mercury-like orbit, 100 orbits, energy drift `|E(t) − E(0)| / |E(0)| ≤ 1e-10` over the full run (linear drift bound, contrast with RK4's monotonic energy bleed that breaks at ~10 orbits).
3. Symplectic-form preservation (cheap probe): two initial states displaced by `δ` in `x` and `δ` in `p`; the volume `δx · δp` of the parallelogram in phase space must be preserved to ≤1e-12 after one orbit. (Cheap sanity check; not a full symplectic-test suite.)

**Dependencies**: none — Ruth-4 is self-contained. Shares `GeodesicState`/`GeodesicSnapshot` types with v0.4.0.

**Honest framing**: Ruth-4 is **4 stages per step** (so 4× more `christoffelFn` evaluations than RK4 per step). It is **not a perf improvement**. Its win is **bounded energy drift over long integrations**, which RK4 lacks. For Mercury Δφ over 1+ orbit, Ruth-4 lets us resolve Δφ_GR ≈ 5·10⁻⁷ rad in a window where RK4 contributes ~5·10⁻² rad of spurious drift (v0.4.0 lesson, per `project_upt.md` line 34).

#### Task 1b — Bisection perihelion finder

**Files**:
- Create: `src/numerical/perihelion-finder.ts` (~80–120 LoC).
- Test: `tests/numerical/perihelion-finder.test.ts` (new).
- Modify: `src/numerical/index.ts` (export `findPerihelion`).

**Key signatures**:
```typescript
export interface PerihelionOptions {
  /** Trajectory snapshots from integrateGeodesicRuth4 (must include velocity). */
  readonly snapshots: ReadonlyArray<GeodesicSnapshot>;
  /** Tolerance for bisection (proper-time precision target). */
  readonly tauTolerance: number;
  /** Re-integration callback to refine inside [tau_a, tau_b] (uses Ruth-4 with smaller step). */
  readonly refine: (tauA: number, tauB: number) => ReadonlyArray<GeodesicSnapshot>;
}
export interface PerihelionResult {
  /** Proper time of perihelion. */
  readonly tau: number;
  /** Position 4-vector at perihelion. */
  readonly x: readonly number[];
  /** Azimuthal angle φ at perihelion (extracted from x[3] in Schwarzschild coords). */
  readonly phi: number;
}
export function findPerihelion(opts: PerihelionOptions): PerihelionResult;
```

**Algorithm**:
1. Walk snapshots; find consecutive pair `(s_i, s_{i+1})` where `dr/dτ` changes sign from `−` to `+` (perihelion, not aphelion).
2. Bisect `[τ_i, τ_{i+1}]`: re-integrate from `s_i` to midpoint via the `refine` callback; check sign of `dr/dτ`; recurse on the half containing the sign change.
3. Terminate when `|τ_b − τ_a| < tauTolerance` (default suggestion: `1e-12 · T_orbit`).
4. Return final state's `τ, x, phi`.

**Test approach**:
1. Synthetic test: analytic cycloid (which has perihelion at `η = π`), inject `r(τ)` from the closed form, bisect → must find perihelion `τ` to ≤1e-12 relative.
2. Round-trip Ruth-4: Mercury-scale ellipse integrated for one orbit → bisection finds perihelion → `φ_perihelion(orbit 2) − φ_perihelion(orbit 1)` must match `6πGM/(a(1−e²)c²)` to ±1e-4 (this is the test that 2a will use).

**Dependencies**: 1a (uses Ruth-4 for the `refine` callback in step 2).

**Honest framing**: precision floor is bounded by Ruth-4's per-step error. The 1e-12 × T_orbit target assumes Ruth-4 delivers ~1e-13 single-step relative accuracy at the step count we will choose. If the bisection precision target proves unachievable in double precision (potential issue: `dr/dτ ≈ 0` over a wide span near perihelion makes the bracketing slow), the test relaxes to 1e-10 × T_orbit and we document the floor — this does NOT block 2a (Δφ tolerance is ±1e-4, far above the bisection floor).

#### Task 1c — `RiemannTensorNode` (AST + validator + lowering)

**Files**:
- Modify: `src/dimensional/connection-validators.ts` — add `RiemannTensorNode` interface + `case 'riemann-tensor'` to `infer()`.
- Modify: `src/numerical/lowering.ts` — add `case 'riemann-tensor'` lowering.
- Create: `src/numerical/curvature-lowering-helpers.ts` (parallels `connection-lowering-helpers.ts`).
- Test: `tests/dimensional/riemann-tensor.test.ts` + `tests/numerical/riemann-tensor-lowering.test.ts`.

**Key shapes**:
```typescript
// src/dimensional/connection-validators.ts
export interface RiemannTensorNode {
  readonly kind: 'riemann-tensor';
  readonly upperIndex: UpperIndex;            // ρ
  readonly lowerIndices: readonly [
    CovariantIndex,                            // σ
    CovariantIndex,                            // μ
    CovariantIndex,                            // ν
  ];
  readonly gLower: MetricTensorNode;
  readonly gInverse: MetricTensorNode;
  readonly xCoord: TensorSymbolNode;
}
```

**Index convention (locked, §5.1)**: 1 upper + 3 lower → `R^ρ_σμν` per Carroll Ch. 3. Definition:
```
R^ρ_σμν = ∂_μ Γ^ρ_νσ − ∂_ν Γ^ρ_μσ + Γ^ρ_μλ Γ^λ_νσ − Γ^ρ_νλ Γ^λ_μσ
```

**Validator output**: `freeIndices = {ρ: upper, σ: lower, μ: lower, ν: lower}`; `dim = DIMENSIONLESS` (curvature in geometric units; SI-units note in §5.4); `gLower`/`gInverse`/`xCoord` validated *without* propagating their free indices upward (same rule as `covariant-derivative` per v0.4.0 §7 H1 fix).

**Lowering**: `riemann-tensor` → emits a composite expression tree built from `christoffel()` outputs and `pderiv` of Christoffel, then computes numerically. The lowering pass is **NOT** a recursive AST rewrite at validation time (which would explode tree size — see §7 Risk Register); instead, lowering walks the `riemann-tensor` node directly, evaluating `Γ^ρ_νσ(x)` and `∂_μ Γ^ρ_νσ(x)` numerically at the supplied coordinate point using `derivativeStrategy`-honoring paths. Result: a 4×4×4×4 `EngineTensor`.

**Test approach**:
1. Validator: free-indices = `{ρ: upper, σ: lower, μ: lower, ν: lower}`; gLower/gInverse indices consumed internally.
2. Numerical: Schwarzschild fixture → `R^ρ_σμν` components match Carroll Ch. 5 exercise values (e.g., `R^t_rtr = −r_s/(r²(r − r_s))`, `R^θ_φθφ = r_s/r · sin²θ`) to ≤1e-9 relative.
3. Antisymmetry: `R^ρ_σμν = −R^ρ_σνμ` to machine precision (structural check on lowered tensor).

**Dependencies**: none (uses v0.4.0 Christoffel infrastructure unchanged).

**Honest framing**: this is a 4-index tensor with 256 entries (4⁴). Lowering performance is bounded by 256 × (Christoffel-eval + Γ-derivative-eval) operations per point. Adequate for fixture-based testing; **not yet** optimized for grid-field curvature (which is what v0.6.0+ Friedmann/Raychaudhuri evaluation would need).

#### Task 1d — `ricci()` helper

**Files**:
- Modify: `src/dimensional/connection.ts` (add `ricci()` next to `christoffel()`) — OR create `src/dimensional/curvature.ts` for the three curvature helpers grouped together. **Decision**: new file `src/dimensional/curvature.ts` (separation of layers — connection vs curvature).
- Test: `tests/dimensional/ricci.test.ts`.

**Key signature**:
```typescript
export function ricci(
  R: RiemannTensorNode,
  contractUpper: string,    // label to contract (e.g., 'rho')
  contractLowerMu: string,  // label in R's lowerIndices to match (e.g., 'mu')
): ExprNode;
```

Builds the trace `R_σν = R^ρ_σρν` via the existing v0.2.0 `contract()` machinery on the upper `ρ` against the *first* of the lower indices `(σ, μ, ν)`. Symbolic, returns an `ExprNode`; numerical lowering happens via the existing pipeline.

**Test approach**:
1. Output free-indices: `{σ: lower, ν: lower}`, dim `DIMENSIONLESS` (or `L^-2` in SI per §5.4 note).
2. Schwarzschild vacuum: `R_σν = 0` to ≤1e-12 (Ricci-flat is the *defining* property of vacuum solutions — this is **the** key curvature test).
3. de Sitter (constant-curvature) fixture: `R_σν = (Λ/3)·g_σν` for the de Sitter solution → trace `g^σν R_σν = R = 4Λ` (this re-uses BE-13's machinery, see §3 Phase 3).

**Dependencies**: 1c (RiemannTensorNode).

**Honest framing**: helper, not a node. The output AST is *bigger* than the input (it expands Riemann into a contracted tree). v0.6.0+ may add an `isRicciFlatVacuum` validator-level optimization that short-circuits the lowering for known vacuum metrics; v0.5.0 lowers everything generically.

#### Task 1e — `einstein()` helper

**Files**:
- Modify: `src/dimensional/curvature.ts` (add `einstein()` next to `ricci()`).
- Test: `tests/dimensional/einstein.test.ts`.

**Key signature**:
```typescript
export function einstein(
  R: RiemannTensorNode,
  g: MetricTensorNode,
  gInverse: MetricTensorNode,
): ExprNode;
```

Builds `G_μν = R_μν − ½ g_μν R` where `R = g^σν R_σν` (Ricci scalar). Uses `ricci()` internally + a fresh metric-trace contraction + scalar-multiply + tensor-subtract (all existing v0.2.0 ops). Output free-indices: `{μ: lower, ν: lower}`.

**Test approach**:
1. Schwarzschild vacuum: `G_μν = 0` to ≤1e-11 (since both `R_μν = 0` AND `R = 0`; same numerical fixture as 1d).
2. de Sitter: `G_μν + Λ g_μν = 0` to ≤1e-11 (matches BE-13's `G_μν = κ T_μν` with `T_μν = −(Λ/κ) g_μν` for cosmological-constant matter). This connects v0.5.0's curvature layer to v0.6.0+'s Einstein-field-equation work without committing to it.
3. Trace: `g^μν G_μν = −R` to machine precision (standard identity).

**Dependencies**: 1c (RiemannTensorNode), 1d (ricci).

**Honest framing**: `einstein()` returns `G_μν`. **Not** `G_μν − κ T_μν = 0` (no matter sources). Vacuum-Einstein-field-equation testing (G_μν = 0 for Schwarzschild) IS in scope; matter-coupled `G_μν = κ T_μν` is **v0.6.0+ work** (see §4 Honest Framing).

#### Task 1f — `bianchiResidual()` helper

**Files**:
- Modify: `src/dimensional/curvature.ts` (add `bianchiResidual()`).
- Test: `tests/dimensional/bianchi-residual.test.ts`.

**Key signature**:
```typescript
export function bianchiResidual(
  R: RiemannTensorNode,
): {
  /** Symbolic residual tree — an ExprNode whose value is zero when the identity holds. */
  residual: ExprNode;
  /** Numerical max |residual_λμνρσ| across all free-index assignments. */
  evaluateMax: (engine: TensorEngine, inputs: NumericalInputs) => Promise<number>;
};
```

Returns the **cyclic-symmetry second Bianchi identity** form:
```
∇_λ R_μνρσ + ∇_μ R_νλρσ + ∇_ν R_λμρσ = 0   (identically, in any geometry)
```
(See §5.2 for choice rationale.)

`residual` is the symbolic LHS as an `ExprNode`; `evaluateMax` numerically lowers and returns `max_{λμνρσ} |residual_λμνρσ|`.

**Test approach**:
1. Schwarzschild: `evaluateMax(...)` ≤ 1e-9 (identity holds; bounded by Christoffel-derivative numerical error). Honest framing: this is a sanity test that our curvature lowering is *self-consistent*, not a new physics claim.
2. de Sitter: same — residual ≤ 1e-9.
3. Synthetic broken-Christoffel injection: deliberately corrupt one Christoffel component → residual jumps to O(1). Confirms the test is not vacuously passing.

**Dependencies**: 1c (RiemannTensorNode), v0.4.0 CovariantDerivativeNode (for `∇_λ R`).

**Honest framing**: this is a **consistency check**, not new physics. Bianchi is a mathematical identity that *any* connection satisfies in 4d; we test it to confirm our implementations of Riemann + covariant-derivative are mutually consistent.

## 4. Honest framing

What v0.5.0 IS:
- The GR foundations release: symplectic integrator, bisection perihelion finder, curvature layer (Riemann + Ricci + Einstein + Bianchi).
- Activation of two v0.4.0 `it.skip` debts (BE-52 Mercury, BE-37 full Shapiro).
- Tightening of bridge-validation precision per the pre-flight audit.

What v0.5.0 is **NOT**:
- **Not a performance release.** Ruth-4 is 4× the work per step compared to RK4 (4 stages). The win is *bounded energy drift over long integrations*, not speed. Mercury perihelion at 50k Ruth-4 steps is slower than 50k RK4 steps; we pay that cost knowingly for the symplectic-form preservation.
- **Not a tensor-algebra refactor.** The existing v0.4.0 lowering pipeline is reused unchanged. RiemannTensorNode lowering walks the node directly (calling Christoffel + Γ-derivative at points) rather than AST-rewriting Riemann into thousands of pderiv nodes. Tree size stays bounded.
- **Not yet Einstein-field-equation work.** `einstein()` returns `G_μν`. Vacuum testing (`G_μν = 0` for Schwarzschild) IS in scope. **Matter-coupled** `G_μν = κ T_μν` requires a stress-energy AST kind (`stress-energy-tensor`?), matter Lagrangian primitives, and is **v0.6.0+ work**.
- **Not yet Friedmann/Raychaudhuri/cosmology bridges.** Those depend on `einstein()` + matter sources + cosmological metrics. v0.5.0 ships the LHS (`G_μν`); v0.6.0+ ships the RHS (`κ T_μν`) and writes the bridges.
- **Not yet threejs visualization.** The Ruth-4 trajectory output shape is the same as v0.4.0's RK4 output, so future viz consumes both without API churn.
- **Not yet higher-order AD.** Riemann involves `∂Γ`; we evaluate `∂Γ` via `pderiv` finite-difference, NOT via forward-over-forward AD composition (which v0.4.0's interface supports structurally per §14.4). v0.5.0 chose finite-difference because Christoffel finite-differencing IS already the v0.4.0 'computed' strategy path; we reuse it without introducing nested-AD complexity. AD-on-curvature is a v0.6.0+ optimization.

## 5. Math conventions

### 5.1 Riemann index convention (Carroll Ch. 3)

`R^ρ_σμν` — 1 upper + 3 lower. Definition:
```
R^ρ_σμν = ∂_μ Γ^ρ_νσ − ∂_ν Γ^ρ_μσ + Γ^ρ_μλ Γ^λ_νσ − Γ^ρ_νλ Γ^λ_μσ
```

**Antisymmetries** (validator-asserted):
- `R^ρ_σμν = −R^ρ_σνμ` (last two lower indices)
- After lowering `ρ`: `R_ρσμν = −R_σρμν` (first two indices); `R_ρσμν = R_μνρσ` (pair-swap).

**Contractions** (used by `ricci`/`einstein`):
- Ricci: `R_σν = R^ρ_σρν` (trace on upper ρ ↔ second lower).
- Ricci scalar: `R = g^σν R_σν`.

### 5.2 Bianchi identity form (cyclic vs alternative)

**Chosen form** (cyclic on first three lower indices of `∇R`, all-lower convention):
```
∇_λ R_μνρσ + ∇_μ R_νλρσ + ∇_ν R_λμρσ = 0
```
This is the standard second Bianchi (per Carroll Eq 3.95). Alternative forms (e.g., `∇_λ R^ρ_σμν + ...` with one upper index, or the *first* Bianchi `R^ρ_[σμν] = 0` on the index ordering) are mathematically equivalent but bury the symmetry. Cyclic-all-lower is the textbook "look at me, I'm cyclic" form most readers recognize. For Schwarzschild we expect residual ≤ 1e-9 (bounded by Christoffel-pderiv numerical noise).

### 5.3 Ruth-4 coefficients (Yoshida 1990)

Let `α = 2^(1/3)`. Then:
```
w₁ = 1 / (2 − α)              ≈  1.3512071919596578
w₀ = 1 − 2·w₁                 ≈ −1.7024143839193153
c₁ = c₄ = w₁ / 2              ≈  0.6756035959798289
c₂ = c₃ = (w₀ + w₁) / 2       ≈ −0.1756035959798288
d₁ = d₃ = w₁                  ≈  1.3512071919596578
d₂ = w₀                       ≈ −1.7024143839193153
d₄ = 0
```
Verification target: `Σ cᵢ = 1` (drift coefficients sum to one step) and `Σ dᵢ = 1` (kick coefficients sum to one step). Both verified analytically. Test asserts numerical sum to ≤1e-15.

### 5.4 SI-units sanity (Schwarzschild gotcha v0.4.0 caught)

`g_tt = −(1 − r_s/r) c²` in SI coordinates. Christoffel `Γ^r_tt` carries an extra `c²` factor versus the c=1 textbook form. v0.4.0 tests confirmed this (per `project_upt.md` line 29). v0.5.0 inherits the SI-aware Christoffel; Riemann and Ricci inherit the units automatically (no extra `c²` factor needed at the curvature level — units flow through). Validator does NOT enforce SI vs geometric units; tests use SI consistently.
