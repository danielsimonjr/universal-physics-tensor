# v0.4.0 — Public API Surface

Each new `@public` entry below has a documented rationale per honest-claude discipline.
The surface snapshot test (`tests/api/public-surface.test.ts`) asserts no
accidental additions or removals, using both `Object.keys()` (runtime exports)
and a source-text grep on `dist/index.d.ts` (type-only exports).

`isChristoffelSymmetric` is intentionally absent from this surface — removed per
the E9 adversarial review. The μ↔ν symmetry of Γ^λ_μν holds by construction of
the symmetric metric g_μν = g_νμ, so a runtime predicate adds no information and
invites misuse.

## New `@public` entries in v0.4.0

| Symbol | Kind | Rationale |
|---|---|---|
| `CovariantDerivativeNode` | type | Bridge implementers compose ∇_μ ASTs; the structural type is essential for callers to express and pass covariant-derivative nodes without depending on internal union types |
| `christoffel(gLower, gInverse, λ, μ, ν, xCoord)` | function | Builds the Γ^λ_μν composite AST tree; public because bridge modules and downstream library consumers compose Christoffel trees directly — the function is not just an internal helper |
| `DuplicateCoordinateWarning` | error class | Callers may filter or handle this warning distinctly from other `UPTError` subclasses; e.g. to suppress it when coordinate shadowing is intentional or to surface it in diagnostic tooling |
| `EngineCapabilityError` | error class | Callers wrap AD method invocations in capability-detected paths; catching `EngineCapabilityError` by name gives a clean recovery path without catching unrelated `NumericalBackendError` instances |
| `ForwardGradResult` | type | AD callers destructure `{ value, jacobian }` from `engine.forwardGrad()`; exporting the result type lets callers annotate their own wrappers without depending on tensor-engine internals |
| `ReverseGradResult` | type | AD callers destructure `{ value, gradient }` from `engine.reverseGrad()`; same rationale as `ForwardGradResult` |
| `hasAutogradSupport(engine)` | function | The canonical capability-detection API before invoking optional `forwardGrad`/`reverseGrad` methods; public by design so callers can branch gracefully rather than catching `EngineCapabilityError` after the fact |
| `integrateGeodesic(inputs)` | function | The headline geodesic solver of v0.4.0 — a fixed-step RK4 integrator for the geodesic equation in an arbitrary Lorentzian manifold; primary consumer-facing API for trajectory computation |
| `evaluateGravitationalLensing(inputs)` | function | BE-51 Eddington 1919 bridge (closed-form α = 4GM/bc²); public by design — bridge evaluator functions are the primary consumer API for this library |
| `evaluatePerihelionPrecession(inputs)` | function | BE-52 Einstein 1915 bridge (closed-form Δφ = 6πGM/(a(1−e²)c²)); same rationale as `evaluateGravitationalLensing` |
| `evaluateBE37CovariantEikonalNumerical(inputs)` | function | v0.4.0 structural preview of the BE-37 covariant-eikonal form; exported as `@public` to allow downstream consumers to integrate it ahead of the v0.5.0 Shapiro cross-check — callers are informed of the preview status via documentation |

## Internal symbols (NOT exported from root barrel)

The following symbols live in their respective modules but are intentionally NOT
re-exported from `src/index.ts`:

- `EngineDualTensor`, `EngineTape`, `EngineTapedTensor` — `Float64ReferenceEngine` AD internals; opaque to callers
- `metricDerivSupplied()` — used internally by Task 12 lowering; callers access this path via `evaluateNumerical` with `NumericalInputs.metricDerivatives`
- `isActiveStatus()` — internal predicate on `BridgeEquationEntry`; useful for catalog filtering scripts but not a consumer API
- `isEinsumSpec()` — internal runtime guard at the lowering→engine boundary; not needed by consumers
- `CovariantDerivativeValidationResult` — internal validator carrier type; not part of the consumer AST contract

## Test coverage

The runtime surface is asserted by `tests/api/public-surface.test.ts` via:
1. `Object.keys(root).sort()` — a `toMatchSnapshot()` assertion catches any addition or removal
2. Per-entry `.toContain()` assertions for all 10 new v0.4.0 entries (gives a named failure message)
3. Explicit `expect('isChristoffelSymmetric' in root).toBe(false)` guard
4. Source-text grep on `src/index.ts` for all type-only exports
5. Post-build grep on `dist/index.d.ts` for the three type-only v0.4.0 additions (`CovariantDerivativeNode`, `ForwardGradResult`, `ReverseGradResult`)
