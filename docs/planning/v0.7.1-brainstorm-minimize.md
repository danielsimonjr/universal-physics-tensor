## M-1 — Re-export 7 v0.7 new dimensional primitives from `src/index.ts`

### Target

The v0.7 BE-X re-encoding sprint and BE-Phase-1 helper extraction shipped 7
new dimensional/numerical primitive modules. Each declares its public symbols
with `@public` JSDoc but none are re-exported from `src/index.ts`:

|---|---|
| `src/dimensional/tensor-trace.ts` | `TracableTensorNode`, `TensorTraceNode`, `validateTensorTrace` (3) |
| `src/dimensional/friedmann-equation.ts` | `FriedmannVariant`, `FriedmannEquationNode`, `validateFriedmannEquation` (3) |
| `src/dimensional/rg-flow.ts` | `RGCouplingNode`, `BetaFunctionNode`, `rgCoupling`, `validateRGCoupling`, `validateBetaFunction` (5) |
| `src/dimensional/gauge-field.ts` | `ArrowOfTime`, `GaugeFieldNode`, `TimeSymmetryPredicateNode`, `validateGaugeField`, `validateTimeSymmetryPredicate` (5) |
| `src/dimensional/klein-gordon-equation.ts` | `ScalarFieldNode`, `KleinGordonEquationNode`, `validateKleinGordonEquation` (3) |
| `src/dimensional/field-equation-helpers.ts` | `validateFreeIndexLabelMatch`, `validateComponentDimension`, `validateTensorSymmetry` (3 — though arguably internal-helpers; see Risk) |
| `src/dimensional/validator-registry.ts` | `lookupValidatorEntry`, `dispatchValidator`, `shouldPropagateFreeIndices` (3 — arguably internal; see Risk) |

Total: ~25 symbols across 7 modules.

### Bucket: (b')

Each declaration site carries a `@public` JSDoc tag but the symbols are
absent from `src/index.ts`. Either:
- promote: re-export from `src/index.ts` + add to
  `tests/api/public-surface.test.ts` snapshot (b' treatment), OR
- demote: strip the `@public` tag and replace with `@internal` (a'
  treatment).

### Risk: **MEDIUM**

- `tensor-trace` + `friedmann-equation` + `rg-flow` + `gauge-field` +
  `klein-gordon-equation` are physics-shaped node types symmetric with the
  v0.6.0 `EinsteinFieldEquationNode` + `KretschmannScalarNode` + `RicciTensorNode`
  + `BianchiResidualNode` which ARE in `src/index.ts`. Re-exporting is the
  symmetric choice. **Recommend: promote** the validators (`validateX`) +
  node-shape types per the v0.6.0 pattern.
- `field-equation-helpers` (3 fns) are intentionally helper-shaped — the v0.6.0
  design pattern was to compose them inside per-node validators. Re-export
  decision needs maintainer judgment: their use is internal to other validators,
  but they ARE the demonstrator API for "how do I write a new field-equation
  validator". **Recommend: keep `@public` tag, re-export them so the pattern
  is discoverable** — symmetric with `christoffel` which IS public.
- `validator-registry` (3 fns) are pure dispatch internals from v0.6.1 Track-B.
  They have no external use case. **Recommend: demote** to `@internal`.

### Estimate

- +25 to +30 lines in `src/index.ts` (3 new `export type {...}` + 3 new
  `export {...}` blocks)
- +20 to +25 lines added to `tests/api/public-surface.test.ts`
  (`EXPECTED_RUNTIME_EXPORTS` + `ALL_TYPE_EXPORTS`)
- 1 commit per module (~6 commits) or 1 batched commit
- Snapshot regeneration via `npm test -- -u tests/api/public-surface.test.ts`

## Cross-cutting observations

### 1. Per-bridge encoding-test pattern is the dominant test-only-importer shape

35+ BE-NN modules each export a `*_LHS` constant, an `*_RHS` constant, and
a `validateBE{NN}Dimensions` function. Tests import them; nothing in `src/`
does. This is THE bulk pattern that v0.7.1 should bulk-tag in one or two
commits, NOT per-file. The v0.7 follow-up audit already dropped 20 truly-
unused exports; ~30-45 stay as bucket (a') for `@internal` tag. **Pattern**:
introduce a `tools/audit-be-module-exports.ts` script that classifies each
BE-NN's exports by consumer set in one pass — re-runnable at every
hygiene release. (Out of v0.7.1 scope; tag for v0.7.2 / v0.8.)

### 2. `@public` JSDoc tag at the declaration site is no longer load-bearing

The `@public` tag was supposed to be canonical per v0.6.1 Decision #4
("every symbol re-exported by `src/index.ts` gets a `@public` JSDoc tag
at its declaration site"). But the v0.7 dimensional primitives (M-1)
have it WITHOUT being in `src/index.ts`, and ~30 manifest-re-exported
symbols (M-13) are flagged as "unused" because the generator does not
follow the manifest. The contract has drifted both ways. **Suggestion**:
v0.7.1 should either re-establish the invariant (per-symbol audit) OR
adopt a different signal (e.g., a TS-side `_public.ts` barrel for
explicit re-exports that the generator can directly parse).

### 3. Bucket (b') is real and recurring at every minor release

v0.6.0 shipped 4 BE-X new structural nodes (BE-13/19/39/50) without
re-exporting. v0.5.x shipped GR machinery (Killing, Einstein,
Kretschmann) and re-exported. The default at v0.7 was "ship the
primitive, defer the manifest update" — which is exactly the surface gap
M-1 picks up. **Recommendation**: add a `tests/api/public-surface.test.ts`-
style invariant that "every `@public`-tagged declaration in `src/` MUST
be re-exported by `src/index.ts`" — runs as a pre-commit guard. This
catches bucket (b') drift at PR time, not at the next hygiene release.

### 4. `*ValidationResult` interfaces always over-export at first ship

Every v0.6.0 GR `*ValidationResult` was exported, then dropped in v0.6.1.
Every v0.7 dimensional `*ValidationResult` is exported now (M-8). The
shape is "validator function returns a typed result, dev exports the
result type out of completeness instinct, no consumer ever imports it
because the call site uses inference". **Recommendation**: add a section
to `docs/architecture/ARCHITECTURE.md` (or wherever the per-module export
convention lives) explicitly saying "internal `*ValidationResult` types
should NOT be exported by default; export only when an external consumer
needs the shape (and add it to `src/index.ts` + `tests/api/public-
surface.test.ts` simultaneously)".

### 5. Dep-graph generator gaps are accumulating, not shrinking

v0.6.1 Phase 3 fixed `--include-tests` semantics + `package.json` exports
subpath. v0.7.1 surfaces two more gaps (M-13 manifest-re-export-blind,
M-14 side-effect-import + ambient-d.ts). The tool's "ground truth" is
diverging from the codebase's actual reachability. **Risk**: at some
release the generator will produce so many false-positives that humans
start ignoring it. **Recommendation**: a dedicated `tools/create-dependency-
graph/` cleanup pass (v0.7.2 or v0.8.0) that closes the 3 known gaps in
one shot, restoring 1:1 fidelity. Or audit a switch to `dependency-cruiser`
/ `ts-prune` as a battle-tested external tool.

### 6. v0.7 stale-carry-forward pattern applies to MINIMIZE counts too

Per the v0.7 execution lesson ("PC-1.5 4 orders, AS-3 1 order, BE-module
exports 40% inflated"), the v0.6.1 baseline's "79 unused exports / 24 to
drop" numbers are pre-v0.7. v0.7.1 Phase 0 MUST re-run `npm run docs:deps`
+ per-symbol grep to produce the corrected baseline. **Do not trust the
v0.6.1-baseline.md table at face value** — re-measure at HEAD as the very
first phase.
