# v0.12.0 — Premise-Extension Directions (Design Note)

Four extensions that advance the original premise — *use the tensor concept
(data dimensionality) to MAP physics and DERIVE bridges/connections* — by
closing the gap between the namesake `UniversalTensor` (today an inert sparse
filing cabinet) and the analytical machinery (dimensional layer, composition
graph, inference suite) that actually does the work.

Grounding read (2026-06-15): the four verification primitives already exist
(`classifyIdentifiability` / `forwardClosure`, `retrodict`, `attemptDerivation`
/ Buckingham-π, `proposeLinkCandidates`); the dimensional validator already
tracks tensor `freeIndices` (upper/lower per label). The extensions are mostly
**wiring + one deferred check**, not new theory.

## Surface policy

The three new analysis layers stay **internal** (off `src/index.ts`), mirroring
`bridge-analysis.ts`. The CLI reaches them by importing the built `dist/`
subpath directly (as it already does for `bridge-analysis.js`). Only Direction 3
changes already-public behavior (`validateEquation` gains a check). This keeps
public-surface churn to zero except the one intended behavior change.

## Direction 3 — Equation-level valence (free-index) homogeneity

**Gap (author-flagged).** `validator.ts` already computes `freeIndices` for the
LHS and RHS of an equation separately, but `validateEquation` (line ~717)
explicitly **defers** comparing them ("Equation-level free-index agreement
checks are deferred to Task 7"). The header (line 6-8) says it cannot catch
"Bridge Eq 17's index-rank mismatch." So an equation `G_μν = (scalar)` passes
today as long as the units match.

**Change.** In `validateEquation`, after the dimensional-homogeneity check,
compare `lhsCtx.freeIndices` vs `rhsCtx.freeIndices` with the existing
`freeIndicesEqual`. On mismatch, push an error-severity `Violation` describing
the valence/rank disagreement. Scalar equations (empty maps both sides) are
unaffected — zero regression risk for the typed-stub bridge encodings. Update
the header scope note.

**Tests.** scalar=scalar ok; rank-2 tensor = scalar → valence violation;
tensor=tensor matching indices ok; mismatched variance → violation. Plus a
full-suite run to confirm no real bridge equation regresses.

## Direction 1 — Make the tensor operational: empty-cell bridge predictions

**Gap.** `UniversalTensor` stores LaTeX strings and never computes. Its one
premise-aligned operation, `unpopulatedNeighborhoods()`, is unused.

**Change.** New internal `src/composition/bridge-prediction.ts`:
- `buildRegimeTensor(edges)` — populate a real `UniversalTensor` from
  `CATALOG_GRAPH`: each endpoint quantity's stated `(scale, force)` becomes a
  diagonal regime cell; each regime-spanning edge becomes an off-diagonal
  bridge cell. The namesake now carries the catalog's structure.
- `predictMissingBridges(edges)` — the empty off-diagonal cells between
  *populated* regimes, ranked by a triadic-closure score (shared regime
  neighbors) — the classic link-prediction heuristic. Each prediction is a
  HYPOTHESIS for review, never a claim.

Honest limit: only edges whose endpoints carry stated `(scale, force)` are
placed; the report includes that coverage.

CLI: `upt predict`.

## Direction 2 — Close the discovery loop: vet link candidates

**Gap.** `proposeLinkCandidates` stops at "same dimension + shared name token"
(132 → 36 → ~3) and hands raw coincidences to a human; the verifiers sit unused.

**Change.** New internal `src/composition/discovery.ts`:
- `vetLinkCandidate(edges, candidate, opts)` — hypothesize the identification
  `a ≡ b` and measure, with the existing primitives:
  - `mergesComponents` — does identifying `a≡b` merge two distinct linkage
    clusters? (structural significance; via `linkageMap`)
  - `unlocksFromAnchor` — quantities newly determinable from an anchor input
    set (default `{mass: M_sun}`) WITH vs WITHOUT the identification
    (`forwardClosure`).
  - `numericallyConsistent` — `retrodict` over the graph WITH the hypothesized
    identification stays `allConsistent` (the identification introduces no
    contradiction). The strong filter.
  - `score` + `verdict` (`promising` / `inert` / `contradictory`).
- `rankDiscoveries(edges, opts)` — run the funnel, vet each survivor, rank.

The human adjudicates a handful of *vetted, provenance-traced* candidates, not
dimensional noise. Output remains a review surface (Part-VI §XXVII-B); dimensional
match is weak, so the weight is on the numeric (`numericallyConsistent`) and
structural (`mergesComponents`) signals.

CLI: `upt discover`.

## Direction 4 — Empirical-spine coverage audit (no fabricated data)

**Gap / constraint.** "Strengthen the empirical spine" must NOT fabricate
physics data. The responsible, composable deliverable is tooling that makes the
spine's gaps machine-visible.

**Change.** New internal `src/bridges/confrontation-coverage.ts`:
- `auditCoverage()` — per catalog bridge: `{ hasEvaluator, hasDataConfrontation,
  citationCount, status, dimensionalSignaturePresent }`, plus aggregate gaps
  (how many bridges are pure typed-stubs with no data confrontation, etc.).
  Surfaces exactly where the empirical grounding is thin so the physicist
  review (CONTRIBUTING.md) is targeted. Composes with Direction 2 (prefer
  well-grounded bridges).

CLI: `upt coverage`.
