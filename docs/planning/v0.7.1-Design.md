## Goal

Ship **v0.7.1** as the **post-v0.7 hygiene release**: minimize the
public surface that drifted during the 6-proposal + BE-X-sprint +
catalog-extension sequence; simplify the BE-NN module triple-
duplication and helper-extraction inconsistencies the v0.7 sprint
shipped; optimize the recoverable BR-2-class wins hiding in the
metric-fixture + Painlevé-Gullstrand modules.

**Three interlocking themes** (one per parallel brainstorm axis):

1. **Surface-discipline restoration.** The v0.6.1 invariant
   `@public ↔ re-exported by src/index.ts` drifted both ways during
   v0.7: 7 dimensional primitives are `@public`-tagged but absent
   from `src/index.ts`; ~30 manifest-re-exported symbols flagged
   "unused" by the dep-graph tool because it doesn't follow named
   re-exports. Restore the invariant + ship a pre-commit guard.

2. **BE-NN triple-duplication reduction.** Three independent
   patterns repeat across 42 BE modules: (a) `evaluateXxx()`
   runtime-guard boilerplate (~−400 LOC potential), (b)
   `validateBE##Dimensions()` 10-line wrapper (~−150 LOC), (c)
   `sym()` factory function duplicated 43 times. Extract once,
   bulk-apply.

3. **BR-2-class allocation wins.** The v0.6.0 BR-2 `christoffelFn`
   → `Float64Array(64)` migration achieved 5–6× RK4 speedup but was
   never propagated to the inverse-metric (`schwarzschildGInverseFn`),
   metric-derivative (`schwarzschildDgInverseFn`), or the new
   Painlevé-Gullstrand metric module. Ship the missing migrations +
   pre-allocated Picard buffers (~140k allocs/Mercury-run eliminated).

## Architectural Decisions (locked)

### Decision #1 — Three-axis parallel-batched sprint (no axis-blocking dependencies)

Minimize / Simplify / Optimize axes are **mostly file-disjoint**.
Cross-axis dependencies that DO exist:

| Cross-link | Resolution |
|---|---|
| **M-1 re-export the 7 v0.7 primitives** ↔ Simplify Phase B (validator+lowering tidy uses some of those primitives) | Land M-1 FIRST so Phase B can rely on the post-re-export surface. |
| **S-8 BE-39 rg-flow uses field-equation-helpers** ↔ Adam-MEDIUM (BRIDGE-PHYSICS-AUDIT v2) carries the same finding | Land S-8 in Phase A; the BRIDGE-PHYSICS-AUDIT v2 deferral closes simultaneously. |
| **O-1 Schwarzschild Float64Array migration** ↔ S-10 fixture mechanical-split | O-1 lands FIRST (perf gate sensitive); S-10 lands AFTER (split sees the post-migration shape). |

All other axis-pairs are file-disjoint. Sequencing is **M-1 → Phase A simplify → O-1/O-2 paired → all others in parallel-safe batches**.

### Decision #2 — `@public ↔ src/index.ts` invariant restored + guarded

Per M-1 + the v0.6.1 Decision #4 precedent. Phase 1 Task 1.1 ships a pre-commit guard test:

```typescript
// tests/api/public-tag-vs-index-invariant.test.ts (NEW)
// Asserts that every @public-tagged declaration in src/ is
// re-exported by src/index.ts (or one of the named-subpath
// modules listed in package.json's `exports` field).
```

The guard FAILS the suite if a future PR adds a `@public` tag
without surfacing the symbol, AND if a future PR removes a
re-export from `src/index.ts` without dropping the `@public` tag.
Closes the drift class M-13/M-14 surfaced.

### Decision #3 — BE-NN triple-extraction goes through `_helpers.ts` module-pattern, NOT inline mixins

Per S-1 + S-2 + S-3 + the v0.6.1 helper-extraction precedent. New
file `src/bridges/equations/_be-helpers.ts` (the underscore prefix
matches the existing `tests/bridges/_helpers.ts` convention)
exporting:

- `validateFiniteInputs(input, fieldNames)` — Number.isFinite +
  range-guard boilerplate from S-1
- `validateBEDimensions(rhs, expectedSig)` — the dimensional-round-
  trip wrapper from S-2
- `sym(name, dim)` — the AST symbol-builder factory from S-3 (this
  one's the riskiest extraction because subtle bugs in the factory
  affect every BE module; needs the most careful test coverage)

Each BE-NN module then imports + uses these instead of duplicating
the bodies. Behavior-preserving extraction; tests stay green by
construction.

### Decision #4 — Catalog data-DRY (`bridge()` record builder) DEFERRED

Per S-7. The 1893-LOC `src/bridges/index.ts` is mostly identical
per-entry boilerplate (`category`, `category_name` derivable from
`category`, etc.). A `bridge({id, name, category, ...})` factory
could collapse ~200 LOC across the 44 entries.

But: S-7 was flagged HIGH-risk because it touches every entry +
the test suite has explicit field-presence pins in 5+ test files.
**Deferred to v0.7.2 or v0.8**. The current per-entry-as-literal
form is verbose but verifiable; the factory pattern needs an
Adam+Eve adversarial vet that this sprint doesn't have time for.

### Decision #5 — O-3 Kretschmann symmetry reduction is MEASURE-ONLY this sprint

Per O-3 + the optimize agent's specific recommendation. The
Kretschmann module's JSDoc estimates ~12× speedup from exploiting
Weyl symmetries (R_{αβγδ} has 105 independent components, not 256).
The algorithm change is non-trivial (index canonicalization) and
needs design-vet before code.

Phase 5 ships `bench/kretschmann-symmetry.bench.ts` as the
baseline that future algorithm change measures against. Closes O-3's
"measure-but-not-fix" disposition.

### Decision #6 — Tagged v0.7.1 keeps the package.json version at 0.7.0 → 0.7.1 (NOT 0.8.0)

Per v0.6.1 precedent. The release is hygiene-only — no new
features. v0.8.0 is reserved for the next round of feature work
(per-bridge physics-judgment, BE-26 Yang-Mills follow-on, additional
TensorEquationNode field equations, etc.).

## Risks

1. **Phase 3's `sym()` factory regression.** A subtle bug in the
   factory affects every BE module. *Mitigation*: comprehensive
   unit tests in Task 3.1 covering every edge case the per-BE-NN
   bodies handle; per-batch tsc + suite gate in Task 3.2.

2. **Phase 5's O-1 doesn't deliver 2-5× speedup.** The optimize
   brainstorm's hypothesis could be wrong. *Mitigation*: Task 5.3
   gates explicitly; if the bench delta is < 1.5×, the
   optimization gets reverted + a follow-up investigation note.

3. **Phase 1 Task 1.4 dep-graph tooling change behaves unexpectedly.**
   The v0.6.1 C-9 precedent showed runtime-empirical checks are
   required for tooling changes. *Mitigation*: Task 1.4 has an
   explicit ABORT-and-redesign clause if the empirical check fails.

4. **Phase 2 Task 2.1 mass *Inputs drop has an orphaned consumer.**
   The agent's risk note ("structural typing keeps it referenced")
   needs per-drop verification, not per-batch. *Mitigation*: each
   drop verified by tsc + suite re-run.

5. **Mid-cycle vet uncovers a Phase-3 design issue.** Per v0.5.0
   ricci-slot precedent, even mid-execution vets can find showstoppers.
   *Mitigation*: Phase 3 commits are batched (~10 modules per batch),
   not bulk; a found issue rolls back at most 1 batch.
