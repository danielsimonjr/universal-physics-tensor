> Turns `promising` discovery identifications into **machine-derived candidate

## 1. Motivation

`upt discover --source=canonical` surfaces `promising` identifications `a ≡ b`
between two canonical quantities (currently `erasure-energy ≟ photon-energy` and
`free-energy-difference ≟ photon-energy`). A `promising` verdict means the
identification merges disconnected physics, unlocks a quantity, and stays
numerically consistent — "worth a physicist's minute," not "true."

Today that's the end of the line: the funnel flags the pair and stops. The user
asked whether those identifications can be turned into *proposed bridge
equations* — i.e. whether known physics can author new speculative bridges.

This design says: **the math can be derived mechanically; the physics cannot.**
We build the derivation and quarantine the result behind the repo's
"enumerator proposes, humans dispose" discipline.

## 2. The core mechanism — identification ⇒ implied equation by elimination

An identification `a ≡ b` where `a = target(Eₐ)` and `b = target(E_b)` (two
canonical equations) implies the equality of their right-hand sides:

```
Eₐ.rhs(governingₐ)  =  E_b.rhs(governing_b)
```

Eliminating the now-identified quantity yields a **constraint among the union of
the two governing sets**. This is NOT new physical content (Adam S2): the two
canonical equations already contain it; elimination only re-points which symbol
is isolated. The value of surfacing it is that, *under the hypothesized identity*,
the constraint is an unobvious algebraic consequence a physicist can adjudicate —
exactly the object the discovery funnel flags but does not yet write down.

Worked example (the pilot candidate):

| | equation | governing |
|---|---|---|
| Eₐ | `erasure-energy = k_B · T · ln2`  (`CE-landauer`) | `{k_B, T}` |
| E_b | `photon-energy = h · ν`  (`CE-planck-einstein`) | `{h, ν}` |

Setting `k_B·T·ln2 = h·ν` and solving for the EM observable `ν`:

```
ν = (k_B · ln2 / h) · T              [the proposed bridge equation]
target:    ν              dim [frequency] = [T⁻¹]
governing: {k_B, h, T}    (k_B, h constants; T the free input)
```

The "Landauer photon" — a `T ↔ ν` relation. **Dimensionally exact, physically
unmotivated.** That is precisely the object we want to emit *as a labelled
proposal*.

### 2.1 The derivation engine (REVISED v2 — Adam S1)

**The engine is `scalarAst`, NOT `dimensional.monomial`.** The original draft said
"solve via the Buckingham monomial." That is wrong: dimensional analysis cannot
supply numerical constants ("the constant is NOT supplied — dimensional analysis
cannot", `buckingham.ts:320-323`), so the headline `ln2` in
`ν = (k_B·ln2/h)·T` is unreachable from `dimensional.monomial`. The `ln2` lives
only in `CE-landauer.scalarAst` (`sym('ln2', DIMENSIONLESS)`). So derivation must
run on the **`scalarAst`** forms, which carry the real prefactors.

`composeSymbolic()` substitutes one AST into another's leaf but does not *solve*
(isolate a variable), and a general CAS is out of scope. We do not need one: the
admissible `scalarAst` forms are **single monomials in their leaves** (products /
quotients / powers, no sums), so the equality `Eₐ.scalarAst = E_b.scalarAst` is a
*monomial equation* and isolating one leaf is **monomial division** — exact and
total (subtract leaf-exponent vectors; carry the dimensionless prefactor through,
`ln2` included).

**Two admissibility gates** (a pair must pass BOTH):

1. **Determinacy gate — `dimensional.monomial` non-null.** Excludes free-group
   forms (`monomial: null` — Newton, Bekenstein–Hawking) whose elimination is
   under-determined. The invariant `monomial !== null ⟺ freeDimensionlessGroups
   === 0` (`dimensional-fields.ts`) makes this total and testable.
2. **Constant-prefactor gate — both sources `epistemicStatus:
   'fully-quantitative'`** (Adam M3 / Eve E3). This excludes forms whose
   `scalarAst` prefactor is a *non-constant* dimensionless stub. The motivating
   case: `CE-jarzynski` is `scalar-up-to-constant` and its prefactor is the
   operator-valued ensemble functional `ln_avg_exp_minus_betaW` — dividing by it
   does NOT yield a closed numeric constant, so a "Jarzynski photon" proposal
   would carry that stub as a free input, not a clean `ν(T)`. Gating on
   `fully-quantitative` keeps every emitted proposal a closed-form relation.

**Effect on the pilot:** `CE-landauer` and `CE-planck-einstein` are both
`fully-quantitative` monomials ⇒ admitted. `CE-jarzynski` fails gate 2 ⇒ dropped.
So the pilot emits **one** honest proposal (the Landauer photon), not two
near-duplicates (Adam M1).

## 3. Decisions (from the 2026-06-18 brainstorm)

1. **Artifact — separate candidate registry.** A new `PROPOSED_BRIDGES` review
   surface, structurally distinct from `BRIDGE_EQUATIONS`. The generator NEVER
   writes the curated catalog.
2. **Depth — math only.** Emit the implied equation (LaTeX + validated AST), its
   dimensional signature, the target/governing, and provenance. NO guessed
   metadata (no citations, regimes, context, tractability, status). Honest-claude:
   fields a human must supply are absent, not fabricated.
3. **Promotion gate — adversarial + literature.** A proposal may enter
   `BRIDGE_EQUATIONS` only after (a) an Adam+Eve-equivalent adversarial review and
   (b) a literature-confrontation note (appears / contradicts / neither). The
   generator cannot auto-promote.
4. **Scope — canonical-only `promising`.** The two `--source=canonical`
   candidates are the pilot. Other sources/verdicts are out of this cut.

## 4. Data model

New module `src/composition/proposed-bridges.ts`:

```ts
/** A machine-DERIVED candidate bridge — the MATH ONLY. Never a status claim. */
export interface ProposedBridge {
  /** Stable id `IC-<sorted-a>--<sorted-b>--<solvedFor>` (Adam m6: endpoint-sorted
   *  + solvedFor, so inverse forms/order don't collide). */
  readonly id: string;
  /** Provenance: the identification + the two canonical equations it came from. */
  readonly derivedFrom: {
    readonly identification: { readonly a: string; readonly b: string; readonly dim: string };
    readonly sourceEquationIds: readonly [string, string];   // canonical CE-ids
    readonly solvedFor: string;                              // the isolated variable
  };
  /** The derived relation's output quantity. */
  readonly target: DimensionalVariable;
  /** Free inputs of the derived relation (constants flagged via CONSTANTS). */
  readonly governing: readonly DimensionalVariable[];
  /** Human-readable derived equation. */
  readonly formulaLatex: string;
  /** Dimensionally-VALIDATED AST of the derived RHS (round-trips to signature). */
  readonly scalarAst: ExprNode;
  /** `format()` of the inferred dimension — same convention as the catalog. */
  readonly dimensionalSignature: string;
  /** Mechanical description of HOW it was derived (no physics claim). */
  readonly provenance: string;
  /** ALWAYS the literal 'unadjudicated'. NOT a BridgeEquationStatus. */
  readonly status: 'unadjudicated';
}

export function deriveProposedBridges(
  opts?: DiscoveryOptions,
): readonly ProposedBridge[];
```

Two type-level firewalls:
- `status` is the literal `'unadjudicated'`, which is **not** a member of
  `BridgeEquationStatus` — a `ProposedBridge` cannot be assigned where a catalog
  entry is expected.
- `ProposedBridge` deliberately **omits** every physics-judgment field
  (`references`, `bridges`, `context`, `known_issues`, `tractability_class`) so it
  is structurally impossible to mistake for `BridgeEquationEntry`.

## 5. Algorithm

```
deriveProposedBridges():
  ranked = rankDiscoveries(CANONICAL_GRAPH)                  // reuse the funnel
  for cand in ranked where cand.verdict == 'promising':
    Ea = canonicalByTarget(cand.a); Eb = canonicalByTarget(cand.b)   // NEW accessor, E1
    if Ea or Eb is null or ambiguous(>1): skip               // a/b must be a unique target
    if Ea.monomial is null or Eb.monomial is null: skip       // gate 1 (determinacy)
    if Ea.epistemicStatus != 'fully-quantitative'
       or Eb.epistemicStatus != 'fully-quantitative': skip    // gate 2 (constant prefactor), §2.1
    # both scalarAsts are leaf-monomials ⇒ Ea.scalarAst == Eb.scalarAst is a monomial eqn
    v = chooseSolveTarget(Ea, Eb)                             // §5.1 — ONE observable
    if v is null: skip                                        // degenerate, §5.2
    ast, dim = solveMonomialAst(Ea.scalarAst, Eb.scalarAst, isolate=v)  // exact division
    assert validate(ast) == dim                               // round-trip guard
    emit ProposedBridge{ solvedFor=v, target={v,dim}, scalarAst=ast, ... }
```

`solveMonomialAst` operates on the **`scalarAst` leaves** (Adam S1), so the
emitted artifact's symbols are the AST names (`T`, `nu`, `k_B`, `h`, `ln2`), NOT
the L0 governing names (`temperature`, …). This resolves the `temperature`-vs-`T`
split (Eve E2): the proposal is internally consistent and `evaluate({T, …})`
works; the governing-name mapping (`T → temperature`) is recorded in `provenance`.

`canonicalByTarget(name): CanonicalEquation[]` is a NEW registry accessor (Eve
E1 — it does not exist today). A target shared by >1 CE is treated as ambiguous
and skipped (none in the pilot).

### 5.1 Which variable to solve for — exactly ONE per elimination (Adam M2)

The elimination can isolate any single free leaf, but the forms are equivalent
rearrangements of one relation, so we emit **one** proposal, choosing the
solve-target by:
1. The variable in **exactly one** source's leaves (the genuine cross-equation
   observable — `ν`) over a shared one (`T` appears only in Landauer here, so this
   rule alone is insufficient; combine with rule 2).
2. The **non-constant** leaf (skip `CONSTANTS`: `k_B`, `h`, …) that is the TARGET
   or a governing of the *partner* equation — i.e. the quantity the identification
   newly expresses. For the pilot that is `ν` (Planck–Einstein's observable),
   giving `ν = (k_B ln2 / h)·T`.
3. The relation is invertible; we record `invertibleAs` in provenance rather than
   emitting `T = f(ν)` as a second proposal.

### 5.2 Degeneracy guard

If the two governing sets share a non-constant variable, or the elimination
collapses to `0 = 0` / a pure-constant identity, the proposal is **degenerate**
(tautological) and dropped. Pilot sets are disjoint ⇒ non-degenerate.

## 7. Validation / tests (`tests/composition/proposed-bridges.test.ts`)

- **Round-trip:** every emitted `scalarAst` validates to its
  `dimensionalSignature` (mirror of `dimensional-signature-catalog.test.ts`).
- **Pilot correctness (Eve-style value check):** the
  `erasure-energy ≟ photon-energy` proposal isolates `ν`, has dim `[frequency]`,
  and `evaluate({T:300}) ≈ k_B·300·ln2/h ≈ 4.33e12 Hz` (Eve-recomputed).
- **Gate-2 exclusion (regression for Adam M3 / Eve E3):** the
  `free-energy-difference ≟ photon-energy` candidate yields NO proposal, because
  `CE-jarzynski` is `scalar-up-to-constant`, not `fully-quantitative`. Asserts the
  pilot emits exactly **one** proposal.
- **Scope guard (gate 1):** a candidate whose source equation has `monomial: null`
  (inject a Newton-like fixture) yields no proposal.
- **Firewall guard:** every proposal's `status === 'unadjudicated'`; the array is
  not assignable to `BridgeEquationEntry[]` (compile-time, asserted via a typed
  test helper).
- **Degeneracy guard:** a candidate with overlapping non-constant governing sets
  emits nothing.
- **No-catalog-write:** `BRIDGE_EQUATIONS.length` is unchanged by importing/calling
  the generator (the catalog stays 44).

## 8. Epistemic guardrails (the spine)

| # | Guardrail | Mechanism |
|---|---|---|
| 1 | Separate registry | `PROPOSED_BRIDGES` ≠ `BRIDGE_EQUATIONS`; generator never writes the catalog |
| 2 | Cannot be promoted silently | `status: 'unadjudicated'` literal + structurally distinct type |
| 3 | No fabricated physics | math-only; judgment fields omitted, not guessed |
| 4 | Loud provenance | mandatory CLI banner; per-record `provenance` + `derivedFrom` |
| 5 | Gated promotion | `promoteProposal({citation, status, reviewRef})` REQUIRES the human inputs and throws without them (Adam m5); no auto-promote |
| 6 | §XXVII-B | every surface states "not a status claim / not a new relation" |
| 7 | No graph-feedback loop | `ProposedBridge` is structurally non-coercible to `BridgeEdge` and is NEVER added to `CANONICAL_GRAPH` — a derived coincidence cannot become a discovery input (Adam m4). A typed invariant, not an open question. |

The §7 **no-catalog-write** test asserts `BRIDGE_EQUATIONS` *reference identity*
and a content hash (not merely `.length` — Adam m4: length is not identity).

## 9. Open questions — RESIDUAL after the Adam+Eve pass

Resolved by review (see `v0.24.0-Review-Findings.md` dispositions): solve-target
blow-up (M2 → one proposal), constant-prefactor scope (S1/M3 → `fully-quantitative`
gate), graph-feedback (m4 → guardrail #7), promotion tooling (m5 → spec'd),
ID scheme (m6 → `IC-<sorted-a>--<sorted-b>--<solvedFor>`).

Genuinely still open (carry into the implementation plan):
1. **Monomial-only scope:** acceptable as a v1 boundary; revisit only when a
   non-monomial `fully-quantitative` candidate appears (none in the pilot).
2. **Cross-proposal dedup at larger scope:** the `fully-quantitative` gate removes
   the pilot duplicate, but a future multi-source run may emit structurally
   identical consequences from different identifications. Add a normal-form
   (`normal-form.ts`) dedup pass when scope widens beyond canonical-only.
3. **Multiple-target ambiguity:** current rule skips a quantity that is the target
   of >1 CE. Is "skip" right, or should it emit one consequence per source CE?

## 10. Out of scope (this cut)

- Bridge-graph and `--source=both` candidates (decision 4).
- Auto-promotion of any kind.
- Non-monomial / sum-form eliminations (EFE, Friedmann).
- Authoring any catalog metadata.
