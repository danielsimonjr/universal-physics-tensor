## How to read each row

For each disputed bridge, the doc shows:
1. **Current status** (in `src/bridges/index.ts`)
2. **Audit recommendation** (from `docs/architecture/BRIDGE-PHYSICS-AUDIT.md` §5)
3. **Test-pinned rationale** (the existing JSDoc + test commentary)
4. **The editorial question** for the user

The user's choice per bridge is one of:
- **(A) Accept audit, override test**: flip status, rewrite the test rationale comment, update the `it("status pinned ...")` assertion text.
- **(B) Reject audit, keep current**: optionally add a brief "audit considered but not accepted; rationale unchanged" footnote to the bridge's `notes:` field.
- **(C) Compromise**: e.g., promote to one tier between current and audit recommendation (only useful if the audit said "promote toward 'established'" and current is two tiers away).
