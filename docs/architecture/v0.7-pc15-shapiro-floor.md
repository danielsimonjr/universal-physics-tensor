## 1. Background — three releases of carry-forward

PC-1 (v0.5.1) hypothesized that the BE-37 Shapiro residual
(~1.76e-4 at v0.5.0; 2.51e-4 post-Task-1 constants migration) was
dominated by truncated `c = 2.998e8` vs exact-SI `299792458`.
**The constants migration did not improve the residual.** PC-1
was filed REFUTED in v0.5.1, and PC-1.5 was opened to investigate
the remaining candidate sources:

1. GL4 step count (truncation at default 2048)
2. Null-IC reconstruction noise (12-13th digit metric eval)
3. Affine-parameter coverage mismatch

v0.6.0 Phase 1 cleared the integrator as suspect via bit-exact
Killing-charge conservation but did NOT re-measure the Shapiro
residual end-to-end. The carry-forward number (2.51e-4) stayed
in todo.md across v0.5.1 → v0.6.0 → v0.6.1 → v0.7 release notes
unverified for three releases.

## 2. v0.7 measurement (step-count sweep)

Earth-Mars solar geometry (`M_kg = 1.989e30`, `R_far_m = 2.279e11`,
`R_near_m = 1.496e11`); closed-form reference
`Δt = (2GM/c³) · ln(R_far/R_near) ≈ 4.147921e-6 s`.

| GL4 steps | shapiroDelaySec | relErr |
|---:|---:|---:|
| 2048 | 4.147922e-6 | **2.28e-8** |
| 4096 | 4.147922e-6 | 5.02e-8 |
| 8192 | 4.147922e-6 | 2.28e-8 |

**Signature interpretation:** the relErr is NOT monotone in step
count (2.28e-8 → 5.02e-8 → 2.28e-8). This is the canonical signature
of having hit the floating-point arithmetic floor — adding integrator
steps actually injects slightly more round-off noise on the
intermediate run before catching up. If the residual were
truncation-bound, doubling steps would reduce relErr by ~16× (GL4 is
4th-order). It does not.

The actual numerical result `4.147922e-6` differs from the closed-form
`4.147921e-6` in the **7th significant digit** — exactly where
double-precision FP runs out of resolution for a quantity assembled
from products of ~10¹¹-scale inputs.

## 3. What changed between v0.5.1 and v0.7

The improvement was not from a deliberate Shapiro-residual fix.
v0.6.0's **BR-2 BREAKING refactor** (commit `5c786cc`) migrated
`christoffelFn` from nested `number[4][4][4]` to flat
`Float64Array(64)`. The GL4 step rebuild every nested-array Christoffel
allocation per step + indexed-property access; the flat representation
eliminates both. The integrator's RK4 speedup (5–6× per
`docs/architecture/benchmarks.md` v0.6.0 BR-2 section) came WITH a
numerical-stability side effect: fewer intermediate allocations =
fewer chances for cumulative round-off injection.

**Nobody re-measured the Shapiro residual after BR-2 landed.** The
v0.6.0 CHANGELOG mentions BR-2's RK4 speedup; v0.6.0 PC-1.5 status
note says "integrator cleared as suspect via Killing-charge
conservation" but does not report the end-to-end residual. The
todo.md and v0.7 release notes inherited the stale 2.51e-4 number.

## 4. Closure of PC-1.5 candidate sources

| Suspect | Status |
|---|---|
| GL4 step count truncation | **DISMISSED** — non-monotone in step count; FP floor not integrator floor |
| Null-IC reconstruction noise | **DISMISSED-BY-IMPLICATION** — if it were dominant, doubling steps would compound it monotonically |
| Affine-parameter coverage | **DISMISSED-BY-IMPLICATION** — 7th-digit agreement at closed-form is tighter than any plausible affine-edge mismatch |

The investigation can be re-opened only if a future numerical
refactor regresses the residual past 1e-6 (the smoke-test upper
bound), at which point the candidate axes are still valid investigation
seeds.
