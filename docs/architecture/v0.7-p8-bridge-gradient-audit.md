  the peer is installed. Consumer environments that DO have
  `mathts-autograd` installed (via `npm install --include=optional`)
  exercise the real AD path via MathTSEngine.

  `evaluate*` function count vs 42 bridges is reconciled here:
  multiple evaluators per bridge (e.g., BE-14 has two, BE-39 has
  BetaG + BetaLambda) are expected; P8 picks one canonical

## Bridge-gradient audit

| Bridge | Status | Differentiable params | Output scalar | AD path |
|---|---|---|---|---|
| BE-11 Decoherence | established | `gamma0_per_s, lambda, lambda0` | rate (s⁻¹) | closed-form rational; MathTS-AD-tractable |
| BE-37 Shapiro time delay | established | `M_kg, R_far_m, R_near_m` | seconds | closed-form log + linear; tractable |
| BE-42 Hawking temperature | established | `M_kg` | Kelvin | closed-form 1/M; tractable |
| BE-52 Perihelion precession | established | `M_kg, a_m, e` | radians/orbit | closed-form rational; tractable (after selecting `dphi_rad_per_orbit` field) |

**Coverage:** 4 of 42 catalog bridges (≈ 10%). Per P8 Decision #1
(thin wrapper layer), expansion to additional bridges is purely
additive — write a `BridgeDiffSpec`, add to `DIFFERENTIABLE_BRIDGE_SPECS`
array.

**Known not-yet-supported:** any bridge with non-scalar output
(`PerihelionPrecessionResult` requires field selection); any bridge
with conditional branching that's not smooth (BE-19, BE-20, etc.
returning step-like quantities); any speculative bridge whose
`evaluate*` doesn't yet exist in `src/bridges/equations/`.
