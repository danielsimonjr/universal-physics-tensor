## Task 0.1 — Axis-value census

Cross-checked against `src/core/types.ts` HEAD (lines 10-48):

| Axis | Count | Members |
|---|---:|---|
| `PhysicalScale` | 4 | `quantum`, `mesoscopic`, `classical`, `cosmological` |
| `Force` | 5 | `gravitational`, `electromagnetic`, `weak`, `strong`, `emergent` |
| `Symmetry` | 5 | `poincare`, `gauge`, `conformal`, `susy`, `emergent` |
| `InformationMeasure` | 4 | `vonNeumann`, `shannon`, `kolmogorov`, `quantumDiscord` |

**Total enumerable axis values: 18** (4 + 5 + 5 + 4).

Plus two integer axes per `TensorConfig`:
  - `dimension` (positive integer, undeclared range — historically used as 3 or 4)
  - `topology` (signed integer, undeclared range — used as 0, ±1)

Per Decision #10 + the P2 `unpopulatedNeighborhoods()` precedent,
the integer axes are wildcards in `Axes` registry semantics. The
`Axes` namespace ships ONLY `Axes.scale`, `Axes.force`,
`Axes.symmetry`, `Axes.information` — 4 namespaces, 18 stable
`UniversalIndex` references at module load.

**Design claim cross-check:** Decision #4 said "the proposals doc §2.4
figures (4 scales, 5 forces, 4+placeholder symmetries, 4 information
measures) may be stale." Actual is **5 symmetries (no placeholder)**.
Mild discrepancy from the design's hedge: `emergent` is a legitimate
member, not a placeholder. Phase 1 `Axes.symmetry` ships all 5.

## Eve findings (empirical-claims red-team)

**Verdict: 1 HIGH (compile-blocking — Phase 0 Task 0.4 dropped),
2 MEDIUM, 2 LOW.**

### Eve-H1 (HIGH, RESOLVED) — Phase 0 Task 0.4 type-only header is non-compilable

Design `docs/planning/v0.7-Proposal-1-Design.md:343-346` says: "Write
`src/core/labeled-tensor.ts` as a type-only header (interfaces +
class signature, no bodies). Type-only RED commit: tsc compiles the
header alone."

Eve verified this fails: TS2390 (constructor missing), TS2391
(method bodies missing), TS2564 (uninitialized property). A
non-abstract class with bodyless members does not compile under
strict TS5.9.

**Resolution: DROP Task 0.4 entirely.** The "header-first" pattern
was a process suggestion, not load-bearing. Phase 1 writes
`src/core/universal-index.ts` + `src/core/axes-registry.ts`
directly; Phase 2 writes the full `src/core/labeled-tensor.ts`
implementation in one TDD cycle. The original intent ("see the
shape before the body lands") is preserved by Phase 1's pre-execution
verification gate reading the design's Phase 2 sketch — no new
file required for the pre-vet.

### Eve-M1 (MEDIUM) — Symmetry has 5 members not "4+placeholder"

Already captured in Task 0.1 axis census above. Phase 1's
`Axes.symmetry` ships all 5 entries (`poincare`, `gauge`,
`conformal`, `susy`, `emergent`).

### Eve-M2 (MEDIUM) — Public-API list under-counts; ~10-11 additions, not 7

Design §"Public-API Additions" prose says "~7" (Decision #10 line
264, Risk 6 line 694), but the enumerated list at lines 731-741
has **10 symbols**:
- `UniversalIndex<Axis>` (type)
- `UniversalIndexId` (branded type)
- `AxisName` (union type)
- `Axes` (singleton)
- `makeIndex` (factory)
- `LabeledTensor<L>` (class)
- `AxisMismatchError`, `IdentityConflictError`,
  `LabeledTensorConstructionError`, `RankPreservationError`
  (4 error classes)

Plus `MergedLabels<L, R>` (Decision #5 type, currently unlisted —
may be `@internal` or may need export). Plus `canonicalLabelOrder`
helper (Risk 2 mitigation — internal per design intent).

**Resolution: locked public surface for P1 is 10 symbols** (per the
enumerated list, treating `MergedLabels` as `@internal` and
`canonicalLabelOrder` as `@internal`). Phase 4 snapshot regen will
show src/index.ts: 45 → 55 exports. Risk 6's "public surface
explosion" mitigation (JSDoc paragraph per symbol) still applies.
