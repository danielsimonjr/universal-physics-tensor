## 4. Why `*Inputs` interfaces stay exported (bucket-(a') deferral)

Each `*Inputs` interface pairs with an `evaluate*` function in the
same file. Tests for ~40 of the 42 BE modules (`tests/bridges/be-NN-
encoding.test.ts`) import the `evaluate*` function but NOT the
`*Inputs` type (tests call `evaluate*({ inline literal })`). So
strictly, the `*Inputs` types are bucket (a) per the dep-graph.

Still kept exported because:

1. **Future-promotion path.** When v0.8+ promotes an `evaluate*`
   function to the public surface (e.g., via package subpath export
   like `universal-physics-tensor/bridges/equations/be-NN`), the
   typed `*Inputs` becomes the consumer-facing arg shape. Dropping
   the export now would either require re-exporting later (churn) or
   force consumers to inline the struct shape (lossy).
2. **Test ergonomics.** Future expansion of the per-bridge encoding
   tests may want `import type { *Inputs }` for fixture sharing.
3. **Discriminator-from-name signal.** The `*Inputs` naming
   convention IS the typed-arg contract for `evaluate*`; readers
   reasonably expect the type to be exported alongside the function.

Recommended follow-up (deferred): annotate the 44 `*Inputs`
interfaces with `@internal` JSDoc tag. That gives consumers a clear
"not in the supported v0.7 surface" signal without losing the
ergonomic export. Mechanical pass; ~30 minutes; can ship as a
hygiene patch alongside the next BE-encoding work.
