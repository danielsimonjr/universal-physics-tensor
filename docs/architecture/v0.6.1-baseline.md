### Failure 3 — `tests/bridges/spec-vs-index.test.ts` (1 failed)

```
> every entry with a "Corrected on YYYY-MM-DD" notes block has a matching spec block
  BE-33: index notes claim "Corrected on 2026-05-20" but spec section does not mention that date
```

"Corrected on 2026-05-20" notes block to `src/bridges/index.ts` but
the test asserts that `docs/specification/Part-II.md` also mentions
the date. Part-II's Phase-3 doc-refresh (commit `fe6d51f`) updated
the BE-33 formulation in spirit but didn't carry the exact date string.

**Fix scope**: add a `Corrected on 2026-05-20` mention to the BE-33
block in `docs/specification/Part-II.md` (or relax the test to accept
spec-content-matches-fix without requiring the date string).

### Failure 4 — `tests/bridges/be-33-reformulation.test.ts` (1 failed)

```
> formula_latex contains the canonical Hertz-Millis ξ ~ T^{-ν/z} form
  AssertionError: expected '\xi_{\text{quantum}}(T) \sim \xi_0 \l…' to match /\\nu|nu/
```

The reformulation test still expects the `ν/z` form in `formula_latex`,
but the BE-33 fix replaced it with `−1/z` (the corrected canonical
form). The test was authored for the v0.5.0 Wave-P-A R-A2 reformulation
and is now stale post-2026-05-20.

**Fix scope**: update the test's regex from `/\\nu|nu/` to match the
new `−1/z` formulation. The fix's intent was to make BE-33's formula
**not** depend on ν.

## Phase 3 design correction (must be applied before Phase 3 starts)

Per the v0.6.1-Design.md Decision #3, Phase 3 Task 3.1 was specified
as "add `--include-tests` to `package.json` `scripts.docs:deps` (one-line
fix)". **This is incorrect.**

Empirical verification (re-running the generator with
`--include-tests`): the flag activates a separate test-coverage
analysis path (line 1623 of `create-dependency-graph.ts`) but does
**not** feed test-file imports into the `detectUnused()` reachability
scan (line 1584). Test imports are parsed into `parsedTestFiles` at
line 1637 — AFTER `detectUnused` has already run on `parsedFiles`
alone. The 40 BE-equation false-positives remain even with the flag.

**Corrected Phase 3 Task 3.1:**

Modify `detectUnused(files, testFiles?)` in
`tools/create-dependency-graph/create-dependency-graph.ts` to accept
an optional `testFiles: ParsedFile[]` second argument. When provided,
walk `testFile.internalDependencies` the same way it walks
`file.internalDependencies` and union the imported-file/symbol sets.
Then in `main()`, move the test-file parsing to BEFORE the
`detectUnused` call (when `--include-tests` is set) and pass them in.

**Expected effect**: all 40 BE-equation modules drop out of the
"unused files" list (they're imported by their per-bridge encoding
tests in `tests/bridges/`). The `mathts-engine.ts` subpath case still
requires Task 3.2's `package.json` `exports` parsing.

Estimated change: ~30 LOC across one function + main-function ordering
shuffle. Still small; still in scope. Adam+Eve missed this because
they verified the flag's existence but not its semantics.
